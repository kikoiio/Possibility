## 当前迭代：对话创建世界与世界动态

用户验收标准：创建世界要逐步和作者讨论、询问细节与确认，从一小片开始；运行时清晰、持续地显示世界实际发生的事；删去不必要 UI。地点、人物、规律应符合讨论，行动应改变状态并影响后续选择。

唯一原型在 `prototypes/`。启动 `node prototypes/server.mjs`，访问 `http://127.0.0.1:5175/`。实现是原生 Node.js HTTP、ES modules、Three.js 和 JSON 存档；目标架构中的 React/Hono/SQLite 等不代表当前实现。

## 本轮已实现

- 创建世界改为持久化对话：第一轮先澄清，逐步形成具体起点；目前先支持 1–4 处地点、1–4 位人物，不再限定四人四房间山庄。模型提出的建议由作者在对话和草稿中确认。
- 作者点击生成后，依次请求地点/连接、人物/前史、资源/规律三个小步骤，后一步引用前一步实际生成的条目。缺失、格式错误或规则错误会拒绝；没有自动重试或固定世界补位。
- 地点语义编译为有限室内/户外场景。作者可继续对话修改草稿；对话版本变化后旧草稿失效。只有确认进入才建立第 0 分钟起源，并保持暂停；原世界保留。
- 运行页收敛为三维画面、当前资源、世界动态、播放/暂停/下一步。错误时才显示重试；新世界和存档放在“更多”。移除旧调试面板、速度按钮、示例入口和原始 JSON 输出。
- 同一服务的 `GET /api/events` 通过 SSE 推送状态；动态从真实提交记录和失败尝试投影，包含对白、移动、行动及资源前后变化。稳定 ID 去重，重连恢复；向上阅读时不强拉到底部。正在考虑/生成显示为临时状态。
- 过程支持 `when`、行动支持 `requires`。全部过程按分钟开始状态检查条件；行动先整体检查前提、成本和容量，失败不移动/不扣资源。开关或库存变化能够影响下一分钟过程和下一次角色观察。
- 人物姓名随真实地点与显示位置更新；混合室内/户外场景使用相应取景范围。房间标签回归验证文字、位置、可见性与相机覆盖。
- 画面观感返工（用户反馈“太丑”）：取景改为围绕实际内容包围盒，不再按岛屿半径；加入渐变天空穹顶、主光/补光/暖冷点缀光、跟随内容的阴影视锥、远景雾和内容以下的地表平面。岛体散布草丛与地表丛簇，房间家具按房间名称选择（书房/餐厅/卧室/厅堂），solid 颜色整体加深。
- 运行页把“重置视角”、天气、资源总量和拖动提示合并为画面左下同一行标签，删去单独的字幕层与全宽状态条；无内容时整行隐藏，窄屏下不再互相压住。动态中的“A → B”数值变化改为带涨/落底色的独立小块，不再是整句纯文本。
- 修正取景测试原先依赖的脆弱数值：户外取景现在断言 27–34 的跨度、与内容位置的对称性、人物移动不改取景、近处树木不缩小画面，室内取景保持不变。
- 修复动态读数位置：页面在隐藏面板上做了首次布局，滚动器会被重置到顶部；现在每次布局前重新施加一次当前读数，只在跟随底部或用户主动滚动时改变位置。
