# Geometry Lab 实验方法与结果

Geometry Lab 用共享的 `SceneDocument` 驱动参数化 solid 和 voxel 两种确定性构造后端，观察场景表达、结构校验、局部编辑和浏览器呈现。以下结果按样本与产物版本组织；它们是原型实验，不是任意题材成功率、正式美术验收或目标设备性能基准。

2026-10-26 已整合到[主原型](../../README.md)。场景文档、空间校验、双后端与增量编译位于 `prototypes/geometry/`，测试为 `prototypes/tests/geometry.test.mjs`。旧生成样例和实验脚本不在当前工作树中，其历史记录不能视为可直接复现的证据。旧独立服务、网页、配置和生成请求客户端已退役。下文是 2026-10-24 至 2026-10-25 的历史测量，不是新主原型的视觉验收。

## 方法与控制条件

手写对照场景让两个后端共享世界尺度、材质、光照、交互界面和观察视角；voxel 单元边长为 0.42 米。场景可切换全景、室内、细节和分屏视图，也可对门廊、桥头等部件作局部修改。共同的语义文档隔离了“场景内容”与“网格如何生成”，但它只覆盖实验 schema 中定义的对象类型。

样本包含三类输入：

- **确定性手写配方**：用于对比 solid 与 voxel 的静态几何和视觉表现。
- **参考解驱动的生成管道**：六个陌生临水场景和四个模糊村庄意图；每个有人工准备的可行参考文档。mock 模型返回参考解，用于检查管道本身。
- **模型输出文档**：由会话模型或十个独立上下文产生的 JSON 文件，再由本地程序校验和编译。生成脚本读文件时不发起模型 API 调用；这些样本的生成过程仍受模型、上下文和提示影响。

结构检查与视觉检查分别记录。结构结果包括 schema、空间约束、确定性编译、探针和受影响部件；视觉检查包括不同视角截图及页面错误、布局溢出。静态面数、对象批次数和实例数分开统计，不能互相代替。

### 形体与视角观察

- solid 配方容易表达斜屋顶、弧桥、圆形观景台、圆柱家具和自由轮廓；树冠和墙体仍有基础图元拼装感。
- voxel 配方有统一材质语言和较高细节密度；对应场景中的桥、屋顶和树冠过密、轮廓锯齿明显。这不是 Minecraft 创作能力上限的样例。
- 两个场景都包括可进入室内的地板、墙、书架和桌椅。门板会遮挡部分初始室内镜头；调整相机后可以观察室内构造。
- 观景台场景检查过全景、voxel、分屏、室内与编辑视图。桌面视口为 1440×1000，移动视口为 390×844；记录中未见页面错误或横向溢出。截图是有限视角检查，不等于盲评审美或完整内部结构验证。
- 结构和空间预算、网格探针不能替代完整碰撞体、角色导航或任意构件间的物理接触检查。

### 浏览器性能观察

一次自动观察使用无头 Chrome、ANGLE SwiftShader 软件 WebGL 和 2048 阴影图。分屏截图操作期间，界面的移动平均读数约为 89 ms/帧。该值来自软件渲染环境，记录没有 CPU/GPU 分解、采样次数或目标硬件数据；不能解释为 GPU 帧率或真实设备性能。目标设备的 CPU/GPU 帧时间、内存、显存与多视口开销需要独立测量。

## 场景语义与确定性验收

实验将场景对象保存在 `SceneDocument` 中，后端把文档编译为 solid 或 voxel 网格。对象具有稳定 ID；部件配方 hash 用于判断是否需要重建。语义修改产生预期脏部件集合，编译器只替换受影响节点并释放旧 geometry。

观景台场景的浏览器编辑检查覆盖两类修改：

- 交互式门廊／桥编辑重建 `porch` 与 `bridge`；`terrain`、`library`、`interior`、`nature` 的对象引用、geometry、material 与配方 hash 保持稳定。
- 文档中只改变门廊宽度时，两后端的 `rebuiltParts` 都只有 `porch`。未知 `kind` 的提案被拒绝且文档不变；应用陌生场景后仍各有一个 solid 和 voxel world。

陌生场景编译检查改变 ID、位置、旋转、宽度、深度和高度，并查询真实生成网格中的入口与桥面。所记录的测试集分别覆盖基础编译与增量更新 **8/8**、村庄语义扩展 **10/10**、加入角色构造后的回归 **11/11**。这些是对应测试集的通过数，不代表未覆盖场景或外部模型成功率。

## 生成与局部修订样本

### 六个临水场景意图

六个参数各异的临水书屋意图包括双岛长桥、高台、六棵树和 10×7 米大厅等。每个意图有手工参考解，并使用“门廊加宽 1.2 米”作为单一编辑指令。

- mock 返回参考解时，**6/6** 通过文档校验、solid／voxel 双后端编译与探针；六次编辑都只重建 `porch`，没有越界重建。
- 会话模型输出文件的首轮结果为 **6/6** 通过，局部修订也精确重建 `porch`。这些文档、参考解与约束提示由同一实验作者准备；该结果测量强约束提示下管道可被走通的样例上界，不能当成冷启动成功率或独立模型评估。
- mock 的 `mock-broken` 样例给出 0.7 米入口，被结构化校验拒绝。它检验入口约束的拒绝路径，不证明所有无效布局都能被正确诊断。

六个临水场景使用的主要硬约束包括：书院与门廊宽、深为 0.5–30 米，墙高为 2–15 米；门廊覆盖正面入口，门中心与入口对齐，门廊和室内地板高差不超过 0.3 米。入口宽至少 `max(0.9 m, 3 × voxelUnit)`、高至少 1.8 米，同时不超过墙体可容纳尺寸。室内主要走道至少 0.9 米，家具周围在宽、深方向各留至少 1.8 米。书院和门廊连同屋檐须完整落在岛上；岛半径为 1–40 米、不规则度为 0–0.2。桥两端须留出桥宽和 voxel 单元对应的岛岸余量，端点高程误差不超过 0.5 米；树冠需避让建筑、桥线和岛岸。每座岛还需落在水域尺寸约束内。此处列的是场景子集中的程序校验条件，不是现实工程安全标准。

### 四个模糊村庄意图

村庄意图为“安静的小渔村”“高一点的山包”“六七户人家路像树杈”“挤一点但要过得走”，不提供数量和坐标参数。mock 参考解 **4/4** 通过。会话模型首轮 **3/4** 通过双后端编译和门廊修订；失败样例为新增第六户时树冠与建筑相交，校验器返回结构化诊断；把树移动 5.5 米后返修通过，形成该样本 **4/4** 的编译结果。

村庄检查加入了 `house`、`path` 和 `character` 类型及部件级编译：

- 恰有一个 water、library、porch、bridge；island、tree、house、path、character 的数量有上限：house 12、path 8、tree 24、character 12。
- 每栋 house 使用 bounds、front entrance 和 gable roof；建筑之间至少留 0.6 米（含屋檐），书院与门廊允许连接。建筑不能进入桥走廊；建筑四角与屋檐需落在岛面内。
- path 使用 2–64 个平面坐标点，宽度 0.4–4 米；全路径需留在同一岛上，且不得穿过建筑。检查包含路径宽度和体素尺寸对应的边界余量。
- 桥端点需位于岛上并匹配岛高；相邻线段坡度不高于 0.8，路径总长不超过 100 米。树冠需避让建筑、桥走廊与岛岸。
- doorway 净空宽度至少为 `max(0.9 m, 3 × voxelUnit)`，高度至少 1.8 米；室内走道及桥、树、建筑之间也有显式空间约束。

村庄子集仍偏临水建筑群，保持单一书院、门廊、桥和水域结构。石板路没有连通性校验，模糊 prompt 中的树杈形路由没有被强制成结构约束；村庄浏览器截图也未纳入该组验收。

### 十个独立上下文的冷启动输出

十个上下文覆盖六个参数化书屋意图和四个模糊村庄意图，输出分别经过结构校验、空间校验、双后端编译与返修检查。它们来自同一模型家族，不是跨厂商比较。

| 环节 | 结果 | 观察到的错误／限制 |
| --- | --- | --- |
| 不返工首轮生成 | **4/10** 通过 | 三例为 schema 沟通缺口：模型按合理外推给书院左／右／后墙加窗，但 schema 只支持 front；三例为空间计算错误，如树或建筑越岛、房屋布局未做全局检查。 |
| 诊断返修 | 六个首轮失败样本中，四例一轮修复、两例两轮修复；最终 **10/10** 通过双后端编译 | 两轮修复反映错误级联：修好字段后空间检查又暴露问题；移动树解决越岛后也可能撞建筑。 |

## 体素斜面屋顶与角色活动

### 体素屋顶

voxel 后端加入 ramp cell：顶面可沿一个轴从低端连续升至高端，斜面高度可以跨越一个格子以上。样例屋顶以沿 x 轴的单坡剖面和屋脊编译。斜面减少了屋顶逐格堆叠的阶梯轮廓；浏览器对照中体素屋顶与 solid 屋顶形状接近。村庄体素渲染批次从 **77** 降到 **71**。该机制只用于屋顶单坡，树木和岸线仍有阶梯轮廓；尚无一般表面网格化结果。

### 角色

村庄样例包含两名角色：一名沿石板路线往返，另一名静立。角色以独立 `character:<id>` 部件编译；solid 使用由腿、身体、头和斗笠组成的矮胖村民，voxel 使用四层小人。前端按路线以 **1.1–1.2 米/秒** 插值移动并朝行进方向转向；无头浏览器观测到两秒位移 **2.2 米**。

该测量验证前端路线动画的速度换算，不是模拟器中的位置事实、路径规划或避障结果。实验没有寻路、碰撞导航或角色与建筑的交互。

## 对照的可复核性与边界

比较不同生成路线时，应固定场景意图、语义 schema、模型家族与版本、提示材料、token／调用预算、修订次数、随机性参数、空间校验和观察视角；保存首轮输出、全部诊断、返修文档和失败样本。报告首过率、返修后成功率、平均返修次数、局部修改越界率，以及独立盲评的外观、内部可用性、角色通行与目标设备成本。

当前样本不足以支持一般化结论：

- 场景集中在临水建筑和村庄子集，缺少商店、农田、复杂地形、社会活动与任意空间题材。
- 会话模型及十个上下文样本来自同一模型家族；每组只有 4–10 个意图，编辑指令只有一种。
- 人工参考解、约束提示与部分生成样本同源；管道通过率不能替代模型冷启动能力或独立地面真值。
- 静态网格统计与 SwiftShader 观察不代表目标 GPU；空间探针不等于完整碰撞、导航或物理接触。
- 模糊路网、复杂交互、长时间模拟、生成失败后的预算耗尽行为和模型 API 真实延迟不在这些样本内。
