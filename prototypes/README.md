# Wispiva 主原型

这是 Wispiva 当前唯一的运行原型，包含创世、模拟、模型调用和三维展示；它不是多个互相独立的体验。产品目标见[项目意图](../docs/intent.md)，现有能力与缺口见[当前架构](../docs/architecture.md)，工作进度见[计划](../docs/PLAN.md)。独立实验位于 `experiment/minecraft-societies` 分支，不接入此运行入口或依赖。

在仓库根目录安装依赖并启动：

```bash
npm ci --prefix prototypes
node prototypes/server.mjs
```

访问 `http://127.0.0.1:5175/`。实际模型配置沿用根目录 `.env.example` 对应的 URL、model、key；启动和观看不调用模型。Agent 不直接打开、展示或修改实际 `.env` / `config.json`。

## 逐步创建

先和模型讨论想从哪里开始、人物的处境，以及希望观察什么变化。第一轮必须先澄清；对话和当前设定持续保存，刷新后可以继续。每次只确定一小片可理解的起点，通常 1–4 处地点、1–4 位人物；更大范围留待继续讨论。

当前设定足够具体后，用户点击“生成这一小片”。模型依次用三次小请求落实地点与连接、人物与前史、资源与运行规则；后一步沿用前一步的真实条目，失败立即停止且不自动重试。程序从地点的室内/户外语义和相对布局编译场景，执行世界、信息结构、空间与实际几何编译检查。缺失或不合法的输出明确拒绝，不使用固定世界补位。

画面和可执行规律一起供用户检查。可继续对话指出要改的地方，更新设定后旧草稿不能直接确认，须重新生成预览。只有“确认并进入世界”才建立第 0 分钟的世界，初始暂停。生成失败不会覆盖正在保存的世界。草稿修订保留此前讨论，模型会收到上一份草稿以保留未要求改变的内容。确认前还会做角色观察隐私审计；它能拦截部分公开文字泄漏，但不能证明同义改写或后续推理绝对安全。

## 看清正在发生什么

运行页只保留三维画面、当前状态和持续更新的世界动态。播放使人物依次自主决定，暂停停止新回合；暂停中可用“下一步”观察一次人物选择。失败时提供明确原因和显式重试；不自动重试。

`GET /api/events` 使用 SSE 推送当前状态。动态从已提交的 revision、真实资源结算和已保存的失败尝试投影，使用稳定身份去重；重连先同步当前状态。人物正在考虑、生成中或等待只作为临时状态，模型的原始 JSON、未验证描述和推理文本不进入已发生的动态。

动态显示移动、对白、检查、行动带来的数值前后变化，以及环境过程的实际结果。没有变化的时间段不编造事件。用户向上阅读时不强制拉回底部，可点击新动态回到底部。页面关闭后，仍在运行的服务可以继续推进；进程退出后冻结，重启不补算离线时间。

数值变化写成“风能电池 9 → 11 格”时，箭头两侧的数值单独成块并用涨/落底色区分，其余文字仍是普通一句话；不是这一形式的动态保持整句显示，不做猜测性改写。

画面取景围绕世界里实际存在的内容（房屋、房间、树木、路径、人物、尚未建成的地点和岛屿近缘），不再按岛屿半径或固定距离取景，所以一小片世界也会占满画面。天空是渐变色穹顶，有主光、补光和两点暖/冷点缀光，阴影跟随内容包围盒；雨天会同时调暗天空、雾和光。地表在内容以下铺一层大面积平面，只用于避免镜头越过小岛边缘时看到虚空，世界的地形本身仍由岛屿承担。

天气与资源总量以画面左下角的一行小标签呈现，“重置视角”和“拖动环视”提示同在这一行；画面上不再有单独的字幕层，因此窄屏下标签不会相互压住。只在还有话要说时才出现这一行，没有天气或资源时整行隐藏。

## 当前能模拟什么

- 地点连接与信息边界：沿相邻地点移动；只有同处的人能听见发言；本人检查后才知道线索内容；私人目标、前史和记忆按人隔离。
- 角色级秘密状态：资源和行动可用 `visibility: { actors, clues }` 限制观察，行动可用 `performers` 限制执行；隐藏资源仍参与客观过程，检查线索后才会向对应角色揭示。`/api/state` 和当前场景是作者级全知视图，角色模型只接收 `observeResident()` 投影。
- 数值状态与资源：数量在 0 和容量之间。每分钟按生成的变化率结算，保留实际增减、溢出和未满足消耗。
- 条件过程：`process.when` 可按一个或多个资源阈值启停，所有条件使用该分钟开始时的状态，不依赖数组顺序。
- 行动前提：`action.requires`、成本和容量必须满足，才提交行动；失败不扣资源或移动。行动改变开关、库存等状态后，可影响下一分钟的过程和人物下一次观察。
- 角色自主选择：模型使用本人可见观察、前史及最近经历决定下一步；程序裁定实际结果。每个回合包括一次尝试与随后一分钟的环境变化。

《红发会》信息边界回归夹具位于 `fixtures/red-headed-league.mjs`，定向验证位于 `tests/red-headed-league.test.mjs`；它用于探索秘密地下行动和反事实条件，不固定小说结局。

这些是有限的离散规则，尚非任意物理、通用生物或完整小说因果模拟。当前尚无完整反思、长期相关性记忆检索、多线分岔或连续寻路。场景支持有限室内/户外布局，不能把单层剖面当成复杂高塔或任意几何已经实现。

## 代码和保存

`tests/` 保存自动和离线行为检查，`fixtures/` 保存回归样例，`scripts/` 保存手动或云端观察脚本，`notes/` 保存原型专属历史记录和实验报告。`model/` 中的检查脚本与模型模块相邻。

| 位置 | 职责 |
| --- | --- |
| `creation-dialogue.mjs`、`world-creation.mjs` | 对话、当前设定、草稿版本、确认和存档切换 |
| `world-genesis.mjs`、`genesis-records.mjs` | 生成提示、小条目解析与语义场景组装 |
| `world-definition.mjs`、`core.mjs`、`actor.mjs` | 世界规则、事实历史、角色观察与经历 |
| `activity.mjs`、`server.mjs` | 已发生动态投影、同一 HTTP/SSE 服务 |
| `geometry/`、`ui/` | 既有 solid/voxel 编译、三维场景及简洁交互；`ui/world-scene.js` 负责取景、光照、天空、地表与画面标签 |
| `model/` | 唯一配置加载器、Responses 流、脱敏审计及受限格式整理 |

`.data/prototype/state.json` 保存当前世界、历史、经历和起源；`creation.json` 保存对话、草稿和世界索引；`worlds/` 保留切换前快照。新建世界前保存旧世界。完整历史仍驻留内存并整体写入文件，长期容量和断电耐久性未验证。

模型请求不设置应用总超时、输出 token 上限、本地 key 额度或自动重试。取消、失败和调用审计保留。格式整理只处理可确定的外围标记、冗余分隔符与字符串内原有控制字符，不补造字段或缺失内容。

## 验证与观察

```bash
node prototypes/verify.mjs
```

这是串行、轻量的 CPU/内存检查，使用合成模型和内存 UI，不读取真实私有配置、不调用真实模型、不启动浏览器。

`scripts/try-conversation.mjs` 用公开输入和 `.tmp/prototype/conversation-live/` 隔离存档，逐条执行明确指定的真实模型步骤，无自动重试。它是观察脚本，不是第二套体验入口，也不会操作作者的当前世界。

`scripts/observe-browser.mjs` 是云端浏览器验收，使用同一页面和 HTTP/SSE 运行时、明确标记的合成模型；通过 `.github/workflows/prototype-preview.yml` 执行，输出桌面/手机截图与检查报告。使用云端前需用户许可，不上传实际配置、世界存档或模型审计。代码检查、真实模型证据与浏览器验收分别记录在 `docs/PLAN.md`。
