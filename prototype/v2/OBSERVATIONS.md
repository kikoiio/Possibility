# 第二轮原型观察结果

日期：2026-10-24。实验代码仍为一次性原型。

## 已观察到的结果

- 八个轻量场景通过：24× 的单位换算与事件偏移、暂停期间晚到回复、固定编辑基准与批量修改、长期记忆与跨线隔离、通用事实与共同场景投影、provider 回退、持久化恢复与密钥不返回网页、调用间隔之后继续备用模型。
- GitHub Actions 的浏览器演练通过：桌面与手机、Canvas2D、真正的 WebGL 3D、并排模式、旋转缩放、编辑器与多元宇宙、暂停。没有页面运行错误，390px 手机页面无横向溢出。
- [真实 Groq 观察流程](https://github.com/kikoiio/Wispiva/actions/runs/40083293453)成功，共六次真实生成请求。三模型比较各一次，再执行批量编辑、编辑后世界线续演、带长期事实的推演。原世界保持不变。
- 这次编辑实际修改了沈青梧、老周、白薇三个角色的目标。新线之后产生四个新事件，独立于原线。

## 失败记录与修正

前两轮真实调用也保留在 Actions 历史中，不能只看最后一次成功：

- 模型会使用数组追加、创建新的嵌套事实容器；最初过窄的操作协议拒绝了这些结果。现在通用 set 支持创建缺失对象父节点及数组末尾追加，并检查已存在字段的类型与引用。
- 模型曾多加 `/world` 路径前缀；prompt 现在明确根路径，并提供完整输出示例。结果仍经过程序校验，不通过时不会推进剧情。
- 模型返回过无法匹配 JSON Schema 的输出，说明服务端结构化输出不能代替应用校验。
- 验证脚本曾把等待免费调用间隔算进请求超时；等待与实际请求的超时现已分开。

## 尚未解决的产品问题

真实样本证明了协议和操作闭环，同时暴露出叙述与事实可能不一致：

1. 在第1天 10:00–11:00 的时段内，模型写出了“今晚18:00集合”，随后又叙述“会议准时开始”和“傍晚”的行动。程序事件时间合法，但文字中的时间仍会漂移。
2. 叙述写老周前往镇报社，对应事实却把他的 location 写成茶馆。两个渲染器虽然忠实展示了同一份事实，画面仍可能与文字不一致。
3. 长期承诺确实保存在世界中并送入真实 prompt；这不等于已经证明长时间人物一致性、角色知识隔离或稳定的因果归因。

因此，当前观察只支持“这一套世界版本、时间提交、编辑和呈现方式可以运行”。不能据此确认剧情可靠，也没有证据认定用户觉得好玩。

## 对后续设计的影响

- 保留固定版本编辑、不可变历史与同一份事实驱动双渲染的方向。
- 比较更明确的绝对时间窗口表达，以及“先形成事实提案，再生成相符叙述”的方式；两者都由 LLM 决定剧情，不引入固定角色行为规则。
- 正式存储分层、长期记忆摘要策略和渲染资产体系继续保持开放，不能把本原型的模块当成已经通过验证的正式架构。
- 原型当前只把 place/character 映射成基础画面，不会为任意新增设定自动生成美术资产；完整快照和全量记忆上下文也尚未做长期容量验证。
