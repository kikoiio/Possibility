# Wispiva 第二轮原型

一次性原型，用于决定世界时间、LLM 事实变化、固定版本上的「如果…」、长期记忆和双渲染应如何组合。这里的文件是实验材料，不是正式产品架构。

## 启动

需要 Node 24，无需安装依赖。在仓库根目录执行：

```bash
npm run prototype
```

打开 http://127.0.0.1:8137。默认是明确标记的演示模式，首次启动的世界暂停；点击「开始」运行。演示事件来自模板，只能验证操作，不能证明 LLM 剧情好玩。

在「推演设置」填 Groq key 并选择真实 LLM，或者启动前提供 `GROQ_API_KEY` 环境变量。密钥仅由本机服务读取，不返回网页、不存 localStorage。网页填写的配置存入 `.data/settings.json`，权限 0600；环境变量中的 key 不复制进配置文件。不要提交或分享 `.data/`。

关闭网页后 Node 服务继续推进所有未暂停的世界线。Ctrl+C 退出服务；重启保留世界、历史、草稿、计划、调用记录和用户暂停状态，离线期间冻结，不自动补算。`PORT` 可更换端口，`WISPIVA_DATA_DIR` 可指定独立数据目录。本原型只监听本机，不提供公网访问或多用户鉴权。

## 体验路径

1. 先保持 24×：1 真实小时对应 24 世界小时。想快速观察可把倍速临时调到 1440×，不是改变 24× 的定义。
2. 切换 2D、真正的 WebGL 3D、并排对照。3D 可拖动旋转、滚轮缩放；两边接收同一份场景数据。
3. 打开「如果…」，修改多个角色或设定；也可以让 LLM 提议修改。修改先保留为草稿，只有「确认」才产生新世界线。
4. 编辑器固定在打开时的世界版本。原线在你编辑时继续运行，新线不会继承这段期间的新事件；未发生的推演计划也不继承。新线继承草稿打开时的速度与暂停状态。
5. 打开「多元宇宙」同时查看各线画面、时间和独立暂停按钮，再对照两份日志。共同历史按事件 ID 判断，用户修改单独记录，不以相似文字猜测亲缘。
6. 在事件日志中搜索离开期间的故事，查看长期记忆及其知情者；可导出世界与日志，导出不含密钥和内部调用正文。

## 时间与事实

LLM 针对固定的世界版本生成一段未来计划；事件偏移始终相对于该段起点。事件到时才写入世界事实和日志。暂停期间晚到的回复可以保存为计划，但不会改变世界事实。没有生成好的未来、发生失败或超出用户额度时，时间明确等待，不能假装故事已经发生。

世界版本不可变，每次事件和用户编辑都形成带父版本的新快照。SQLite 的单条事务提交完整实验状态，避免历史和当前态各保存一半。为保持原型简单，当前保存完整快照；尚未做容量与长期吞吐验证。

事实文档允许自定义字段、实体和关系。LLM 用通用 set/remove 变化描述改变事实，程序只验证数据结构和引用，不预设角色行为规则。叙述与事实是否语义一致仍需观察真实输出，JSON 校验不能证明这一点。

长期记忆保存在世界文档中，具有来源事件与知情者，并随版本继承。每次推演发送完整世界（含自定义字段和长期记忆）与最近 12 条历史。超过上下文字符预算时明确停止，不静默删除记忆。本轮没有验证无限时长运行，也没有自动摘要、全量知识检索或严格的多智能体信息隔离；提示词要求尊重角色知识，仍需检查是否泄密。

## Groq 候选与免费额度

2026-10-24 核对官方文档后，初始首选 `openai/gpt-oss-120b`，中文对照候选 `qwen/qwen3.8-27b`（Preview），快速备用 `openai/gpt-oss-20b`。三者列于 [Groq 免费额度表](https://console.groq.com/docs/rate-limits)，支持 [严格结构化输出](https://console.groq.com/docs/structured-outputs)。这表示可在免费计划额度内调用，不代表付费账户调用这些模型永不计费；具体额度以账号页面为准。

初始选择结合模型能力与结构化输出支持，不能据此宣布某个模型最擅长本产品的中文叙事；`live-groq.mjs` 记录三者实际输出后再比较。只在这些配置的模型间回退；404/429/503 会尝试备用，且尊重用户调用间隔与次数。不会切换到其他服务商或自动升级计划。

默认每段 60 世界分钟、每小时 40 次、每日 200 次、最短间隔 60 秒；都可以修改。多条运行中的世界线共享调用预算，并轮流获得推演机会。服务商的组织级限制仍可能使请求等待。

## 观察与证据

```bash
npm run prototype:observe
```

轻量场景脚本观察 24×、事件时间、暂停晚到、编辑期间分叉、长期记忆、跨线隔离、通用事实、新模型回退和重启恢复，结果写入 `artifacts/observations.json`。其中 provider 使用模拟传输，不能算真实 LLM 验证。

GitHub Actions 工作流 `Prototype observations` 使用免费 Ubuntu runner 执行上述场景，以及桌面/手机、2D/3D/并排、编辑器、多元宇宙和暂停的浏览器演练，上传截图与观察报告。GUI 不在本机启动。

启用工作流的 `live_groq` 输入后，读取仓库 secret `GROQ_LLM_API_KEY`（也兼容 `GROQ_API_KEY`），最多发起六次真实生成请求：比较三个候选，再观察多项编辑、新世界线继续运行、长期事实进入真实 prompt。结果写入 `artifacts/groq-observations.json`，保留虚构事件正文以便判断叙事质量，绝不上传密钥。

GitHub secret 只能在云端读取，不会被下载给本机原型。要在本机实时游玩真实模型，需要在本机设置 key；CI 的真实调用报告可独立查看。
