# s01｜基线与兼容闭环 Plan

## 架构概览

s01 不新增生产运行时架构。它复用现有 API、测试数据库和 D1 迁移链，补齐一条可重放的本地验收路径，并把证据集中记录在当前状态盘点中。验收分为四层：固定夹具验证基线可重复；API 路由验证旧数据读取和精确时间线边界；隔离数据库验证迁移保留数据且可重复；基线报告记录命令、结果、环境和未验证项。

测试数据固定时间、用户、世界、居民、对话、记忆、承诺和时间线 ID。路由旅程使用确定性响应或不触发模型的请求。测试不依赖真实模型、外部服务或 Cloudflare 部署环境。需要运行 Wrangler D1 迁移时，必须把状态目录和数据库绑定指向临时隔离路径，并在执行前核对其位置；不能复用默认持久化目录。

## 核心数据结构

### 基线记录

每条基线记录至少包含：

| 字段 | 含义 |
|---|---|
| 检查项 | 对应的 AC 编号和行为范围 |
| 环境 | 代码提交、工作区是否有改动、数据库类型及隔离位置 |
| 命令 | 完整可复制的执行命令 |
| 结果 | 通过、未通过或未验证，以及退出码/观察结果 |
| 证据 | 测试名称、关键输出或迁移前后快照位置 |
| 缺口 | 失败原因、无法验证原因及后续归属 |

### 小世界夹具

固定用户 `owner` / `other`、世界 `home-world` / `other-world`、主线 `home-main` / `other-main`、原创居民及访客，模拟时间固定。夹具提供测试数据库与请求环境；单测可重复创建并比较世界、时间线和地点标识。

### 旧数据样本

旧数据样本只包含验证兼容读取所需的既有行：世界与居民关联、居民状态、对话与消息、事件、记忆、承诺及没有完整 Fork 快照的子线。样本应能检查迁移前后对应表的行内容，并验证读取结果把缺失的历史证据标为不完整或 `legacy/unknown`。

## 模块设计

### 基线清单

**职责：** 记录仓库当前 API 测试、API 类型检查、Web 构建和基线旅程的实际状态；把实施前基线与当前结果分开，记录已知缺口。

**对外产物：** `docs/current-state-audit.md` 中的 P0 基线表和证据记录。

**依赖：** 仓库脚本及基线夹具。

### 固定夹具与确定性旅程

**职责：** 创建可重复的小世界；提供稳定 ID、固定时间和测试用户；让 API 路由测试无需真实模型或外网。

**主要文件：** `api/src/test/db.ts`、`api/src/test/world-fixture.ts`、`api/src/test/world-journey.test.ts`。

**依赖：** 现有测试环境和 API 应用入口。

### 旧数据与路由兼容检查

**职责：** 通过现有读取入口验证旧世界、对话、记忆、承诺和不完整 Fork；检查显式有效、缺失、异世界及无权时间线 ID；检查跨用户访问与公开只读边界。负向用例同时检查数据库无副作用。

**主要文件：** `api/src/test/legacy-compat.test.ts`，以及被测的世界、场景、聊天、公开和 Fork/Compare 路由测试。新增断言优先落在现有测试文件，避免为相同路由重复搭测试框架。

**依赖：** 固定夹具。

### 隔离迁移检查

**职责：** 分别检查迁移 SQL 对旧数据的保留行为，以及完整 Wrangler 本地迁移流程的重复执行。SQL 级测试使用内存 SQLite；Wrangler 级验证使用独立临时持久化目录。运行前核对实际解析出的数据库绑定和目录，运行后记录迁移状态、关键表快照和清理结果。

**主要文件：** `api/src/test/legacy-migration.test.ts`；必要时新增 `scripts/verify-s01-migrations.*` 和对应包脚本，为临时目录创建、数据库绑定检查、两次迁移及结果记录提供单一入口。

**依赖：** `api/drizzle/` 中的迁移和仓库 Wrangler 配置。

### 证据与阶段判断

**职责：** 将 AC1–AC6 标为通过、未通过或未验证。未通过项记录复现步骤；未验证项说明缺少的环境/证据及归属。阶段出口只依赖本规格的 AC，不引用 P1–P4 的完成情况。

**主要文件：** `docs/current-state-audit.md`。

**依赖：** 上述四类检查结果。

## 模块交互

```text
固定时间与小世界夹具
        ├── 基线旅程 ───────────────→ 稳定 ID 与可重复结果
        └── API 兼容测试 ───────────→ 旧数据读取 / 时间线边界 / 归属边界

旧数据样本 ──→ SQLite 迁移测试 ────→ 迁移前后行快照相同
迁移文件 ────→ 隔离 Wrangler D1 ───→ 两次迁移结果稳定

以上证据 ────→ current-state-audit.md → AC1–AC6 阶段判断
```

失败的越权请求、无效时间线请求和公开写请求还需比较请求前后的相关行数/内容，确认拒绝没有产生副作用。迁移失败时只销毁该次临时目录，不清理或覆盖仓库已有持久化目录。

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 基线数据 | 固定原创夹具和稳定标识 | 可重复比较，避免演示数据和随机内容造成误报 |
| 模型调用 | 使用确定性响应或完全绕过模型 | 本阶段验证数据与边界，不评判生成质量 |
| 兼容验证 | API 路由测试 + 迁移行快照 | 同时覆盖用户可见读取行为和底层数据保留 |
| 迁移验证 | SQLite 单测 + 独立 Wrangler 本地 D1 | SQLite 适合检查 SQL 和旧行保留；Wrangler 检查真实迁移入口。两者都使用隔离数据 |
| 无效 ID 行为 | 显式拒绝；只允许合同规定的缺省主线 | 避免无效输入被静默写入错误时间线 |
| 证据记录 | 只记录实际执行结果；未知状态标为未验证 | 不以实现存在或旧报告中的历史结果替代当前证据 |
| 远端并发压力 | 不纳入 s01 | 本阶段仅本地验收；后续如需要须单独定义环境与验收门槛 |

## 需求追踪

| Spec 项 | 设计归属 | 主要验证位置 |
|---|---|---|
| F1 / AC1 | 基线清单、固定夹具与确定性旅程 | `world-fixture.ts`、`world-journey.test.ts`、`current-state-audit.md` |
| F2 / AC2 | 旧数据样本与兼容读取检查 | `legacy-compat.test.ts`、`legacy-migration.test.ts` |
| F3 / AC3 | 时间线定位与无副作用拒绝检查 | `legacy-compat.test.ts` 及相关路由回归 |
| F4 / AC4 | 用户归属、世界/时间线范围、公开只读检查 | `legacy-compat.test.ts`、公开路由回归 |
| F5 / AC5 | 隔离 SQL 与 Wrangler D1 迁移检查 | `legacy-migration.test.ts`、可选隔离验证脚本 |
| AC6 | 验收证据与阶段判断 | `current-state-audit.md` |

**s01 出口：** AC1–AC5 全部通过，且 AC6 报告完整。AC1–AC5 任一失败或未验证，阶段保持未关闭；P1–P4 的行为不属于 s01 阶段出口。
