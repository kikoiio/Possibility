# s01｜基线与兼容闭环 Spec

## 背景

Possibility 已有世界、人物、对话、记忆、承诺、时间线和 Fork 等能力。当前代码和数据库处于演进中：旧数据形态并不完全一致，部分历史记录没有足够证据还原为结构化世界事实。近期实现也涉及较多文件，必须先有一份可重复、可核对的基线，避免后续状态模型改造掩盖兼容性或访问边界回归。

仓库已有的实现质量记录显示，部分基线、旧数据读取和隔离测试已完成；同时仍有未提交改动，且一些跨阶段验收尚未完成。本规格定义的是一个可单独关闭的基线阶段，不把后续能力的完成情况作为本阶段前置条件。所有当前状态结论须以本地代码、测试和隔离数据的实际证据为准。

## 目标

- G1：记录当前可重复的构建、测试和核心读写基线，并区分已验证行为与已知缺口。
- G2：保证代表性旧数据仍可读；缺少历史证据的内容保持 `legacy/unknown`，不被补造成确定事实。
- G3：保证显式指定的时间线被精确定位，非法或越权 ID 不会静默回落到主线。
- G4：保证私人写入有明确归属边界，公开演示保持只读。
- G5：在隔离数据上验证迁移流程可重复且保留旧数据；不触碰默认本地库或远端数据。

## 功能需求

- F1｜可重复基线：提供固定的小世界夹具和确定性响应，使基线场景可以重复创建和检查。基线记录必须标明命令、环境、结果及已知缺口；不把未实现的愿景能力标成通过。
- F2｜旧数据可读：代表性旧世界、人物、对话、记忆、承诺和 Fork 可以通过现有读取入口访问。缺少结构化来源、快照或历史事实的内容须显式保留不完整状态，不得从叙述文本推断并写成确定事实。
- F3｜时间线精确定位：调用方显式传入时间线 ID 时，读取和写入必须定位到该时间线。ID 不存在、属于其他世界或无权访问时，必须明确拒绝；只有调用方未传时间线 ID 且接口定义允许默认值时，才可使用主线。
- F4｜归属与只读边界：私人读取和写入按用户、世界及时间线归属校验。其他用户或不匹配的世界/时间线不能通过 ID 访问数据。公开演示入口保持只读。
- F5｜隔离迁移验证：新增或既有迁移的基线验证只能在可丢弃的隔离数据库副本中执行。迁移重复执行后状态稳定，代表性旧数据在迁移前后保留；本阶段不在默认本地库或远端数据库上执行迁移。

## 非功能需求

- N1：本阶段只做本地开发和验收，不包含部署、生产数据迁移或公开发布。
- N2：基线夹具使用原创数据与确定性模型替身；通过条件不依赖真实模型输出、付费服务或用户输入。
- N3：所有迁移验证可重复，并记录所用隔离数据库及迁移前后检查结果。
- N4：本阶段不要求 Cloudflare 多 Worker 压力测试。若以后阶段需要该证据，应在对应规格中定义可执行环境、通过标准和失败处置。
- N5：文档中的“通过”必须附可复核证据；代码存在、测试数量增加或构建成功均不能单独证明行为正确。

## 不做的事

- 不建立新的世界事实/命令/投影模型，也不把现有全部写入路径迁入新状态入口。
- 不扩展开放式居民行动、知识传播机制或真实模型质量验证。
- 不实现新的 Fork 语义、分叉状态复制、跨宇宙对照或历史任意时刻 Fork。
- 不重做世界首页、身份模式、创世流程或整体产品体验。
- 不要求跨阶段的成功/拒绝/取消/恢复/并发/多级 Fork 全矩阵；每个后续阶段在自己的规格中定义对应回归。
- 不删除旧数据表、旧 API、人物页、章节或既有入口。

## 验收标准

- AC1：从干净的隔离环境运行基线夹具两次，均得到稳定的世界、人物、时间线和关系标识；基线记录列出实际验证命令、结果和缺口。
- AC2：用代表性旧数据验证世界、人物、对话、记忆、承诺和旧 Fork 的读取；缺少证据的历史明确显示为不完整或 `legacy/unknown`，迁移及读取过程不凭空生成事实。
- AC3：分别验证省略时间线 ID、显式有效 ID、显式不存在 ID、异世界 ID 和无权访问 ID。有效请求定位正确；非法或越权请求明确失败，且不读写主线作为回退。
- AC4：分别验证跨用户、错配世界/时间线及公开演示写入。私人越权请求被拒绝且没有副作用；公开演示写请求被拒绝，已有公开读取行为仍可用。
- AC5：在隔离数据库上应用迁移并再次运行迁移；第二次运行不产生额外状态变化，代表性旧数据的关键行数和内容符合预期。本阶段没有对默认本地库或远端数据库运行迁移。
- AC6：基线报告把每项验收标为通过、未通过或未验证，并为未通过/未验证项记录具体证据和后续归属；P1–P4 的功能完整性不作为本阶段关闭条件。
