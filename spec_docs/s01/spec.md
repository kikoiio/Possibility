# s01｜P3 Fork 与 Compare 验收闭环 Spec

## 背景

S01 P2 已通过在场体验闭环验收。P3 聚焦 Fork 与 Compare：现有实现已具备版本化 Fork、不可变源快照、多级祖先边界和对照视图，但当前报告仍指出四项未闭合的验收缺口：隔离 D1 上的多 Worker 并发证据；记忆、承诺与知识在多级 Fork 中的组合隔离矩阵；从消息提交到接收者实际获知/未获知的完整旅程；以及 Compare 界面中历史边界和证据说明的人工走查。

## 目标

- G1：证明多个独立 Worker 共享隔离本地 D1 时，Fork/相关并发写入在竞争、冲突和失败下保持原子性与时间线边界。
- G2：通过根线、子线和孙线的组合旅程，证明记忆、承诺与知识只按 Fork 检查点及时间线边界继承，分叉后互不污染。
- G3：明确“消息是否送达”的可观察含义，验证消息只进入授权接收者的正确时间线知识；后续获知与否按已记录证据呈现，不将提交成功等同于居民已阅读或必然采取行动。
- G4：通过登录态 Compare UI 走查，确认用户能辨认分叉条件、共同历史、分支差异、证据来源/版本与不完整旧历史，且界面不把观察到的差异表述为确定因果。
- G5：四项缺口均有可复核的自动化或人工证据；未通过项保留为未通过，全部通过后才关闭 S01 P3。

## 功能需求

- F1｜并发 Fork 一致性：多个独立 Worker 同时基于同一世界/源时间线执行 Fork 或与 Fork 竞争的版本化写入时，每个成功子线必须完整对应一个有效源快照；过期源版本、重复请求、容量冲突或事务失败不得产生重复/半成品时间线。冲突应可识别，其他成功请求的数据不能被覆盖。
- F2｜多级历史隔离：在根线、子线、孙线的旅程中，按 Fork 检查点验证记忆、承诺和知识的继承边界。分叉前可继承内容在新线保持冻结；祖先在线后续新增的内容不渗入已创建后代；子线在孙线分叉前形成的内容可按规则进入孙线；任何分叉后的写入不得反向污染祖先或旁支。
- F3｜消息送达与获知：在指定时间线提交给合格接收者的消息，应形成可追溯的接收者知识证据，保留来源与确定性/传闻属性，并只对该接收者及其所属时间线可见。完整旅程应验证提交结果、接收者后续决策上下文和分支隔离；“已提交/已送达”不得被描述成接收者必然阅读、相信或采取特定行动。
- F4｜Compare 证据呈现：对照视图应让用户区分共同历史、分叉条件、分支状态/事实/事件差异及其来源、版本和时间；当旧时间线缺少可证明的不可变历史时，必须明确显示历史不完整，不得补造共同过去。
- F5｜Compare 的因果边界：界面文案只陈述已观察到的状态与证据差异，不把差异宣称为确定因果、预测或实验结论；用户应能从对照返回所选时间线并确认当前上下文没有串线。
- F6｜权限与失败边界：跨用户、错配世界/时间线及不可用源时间线的 Fork/Compare 请求必须遵守现有访问规则；拒绝、冲突和失败均不得改变源线版本、事实、投影或活动子线集合。

## 非功能需求

- N1｜并发验收环境：使用至少两个独立 Worker 进程，共享一个一次性隔离的本地 D1；并发场景可重复运行，并在每轮后核对数据库状态与时间线不变量。
- N2｜确定性：自动化旅程使用固定时钟、固定模型替身和受控并发屏障；验收结果不依赖真实模型文风、外网或付费服务。
- N3｜隔离与清理：验收不得连接项目默认库、远端/生产 D1 或部署服务；临时数据库和进程仅在专用临时目录创建，结束后确认进程与数据清理。
- N4｜证据可复核：并发结果记录请求、成功/冲突状态及最终版本/时间线数量；隔离矩阵记录来源时间线、检查点和可见性结果；消息旅程记录来源事实到接收者上下文的链路；UI 走查记录实际页面观察。
- N5｜只读验收边界：Fork/Compare 历史及投影检查只验证，不自动修复或改写既有历史；旧数据无法证明完整性时保留不完整状态。
- N6｜兼容与访问边界：本阶段维持现有用户归属、世界/时间线权限、活动时间线限制和旧 Fork 读取兼容；不以放宽权限或伪造历史来通过验收。

## 不做的事

- 不扩展 Fork 的产品能力，例如任意多变量实验、时间回溯编辑或跨世界合并。
- 不重做全局世界引擎、居民生活模拟、记忆系统或 Compare 架构；只修复本轮验收实际暴露的问题。
- 不使用真实/远端 Cloudflare D1、生产数据、部署环境或真实模型作为本阶段验收条件。
- 不把消息提交成功定义为居民已经阅读、相信或必须回应，也不要求固定的后续剧情结果。
- 不重建或猜测旧时间线缺失的历史；不把“历史不完整”自动修复成完整。
- 不将 Compare 的观察差异宣称为确定因果关系、预测或科学实验结果。
- 不纳入 P4 的世界优先 UI 改版，也不重做已通过的 P1/P2 范围。

## 验收标准

- AC1｜多 Worker Fork 并发：两个独立 Worker 使用同一隔离本地 D1，对同一源时间线执行并发 Fork，并覆盖源版本变化、同 ID/同内容重试、同 ID/不同内容冲突及活动时间线容量冲突。同 ID/同内容重试返回既有结果且不创建重复子线；每个成功子线的快照与祖先边界对应一个有效源版本；冲突请求没有子线、命令、事实或版本副作用；所有轮次结束后时间线数量、revision 与账本不变量一致。（F1、F6；N1–N4）
- AC2｜多级隔离矩阵：在 Root→Child→Grandchild 的受控旅程中，逐项验证记忆、承诺、知识在分叉前继承、祖先分叉后新增内容不渗入旧后代、当前父线在下一次 Fork 前新增内容可按检查点继承，以及子线/旁支写入不反向污染。通过只读审计并记录各项可见/不可见结果。（F2；N2、N4–N6）
- AC3｜消息送达旅程：在子线向合格居民提交一条带来源的消息，验证该消息成为接收者后续决策上下文中具有正确来源和 certainty 的知识；其他居民、根线及旁支不能看到不属于它们的消息。UI/结果提示准确区分“提交/进入接收者知识”与“居民已阅读或采取行动”，无需居民产生特定反应。（F3；N2、N4、N6）
- AC4｜Compare 登录态走查：在本地合成账号中比较有共同历史的两条时间线，检查分叉条件、共同过去、分支差异、证据来源/版本/时间及返回所选时间线的行为；同时检查缺少完整 checkpoint 的旧 Fork 显示历史不完整。页面文案没有把观察到的差异表述为确定因果、预测或实验结论。（F4–F5；N4–N6）
- AC5｜权限和失败无副作用：跨用户、错配世界/时间线、失效源版本、归档/不可用来源及事务故障的拒绝路径，均不改变源/目标 revision、命令、事实、投影或活动子线集合；Compare 读取只返回授权时间线的数据。（F1、F6；N2、N5–N6）
- AC6｜P3 出口报告：逐项记录 AC1–AC5 的实际命令、环境、结果与证据，并明确遗留兼容范围；只有 AC1–AC5 全部通过时才标记 S01 P3 出口通过，任何失败或无法证明项都保留为未通过/未知。（N3–N5）
