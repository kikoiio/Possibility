# s01｜P1 世界状态一致性与连续推进 Spec

## 背景

`spec_docs/s01` 原先描述 P0 基线与兼容验收。仓库盘点将 P0 标为通过；实施质量报告显示，P1 的版本化命令、世界时钟和主要投影审计已落地，但 P1 出口尚未通过。剩余缺口包括完整投影重建的一致性证明、居民连续多拍推进，以及并发、取消、恢复等验收矩阵。

本规格重做 `spec_docs/s01` 为 P1 规格。`docs/current-state-audit.md` 中的 P0 历史记录保留。当前工作区中已有的未提交改动属于既有工作，不作为本规格的实施成果。

## 目标

- G1：证明结构化世界投影可从不可变起点与事实账本重建，并与当前投影一致；发现差异时能定位来源，且不修改现有世界数据。
- G2：用固定居民完成跨越至少一整天模拟时间的连续推进，验证节拍、日程切换、状态变化和版本化事实之间保持一致。
- G3：在隔离环境验证相关命令的成功、拒绝、取消、恢复、重复请求和跨 Worker 并发行为，确认失败不会留下部分写入。
- G4：保留旧数据的证据边界；无法从历史证据重建的内容继续标为不完整或未知，不补造事实。

## 功能需求

- F1｜投影重建与比对：对具有结构化起点的时间线，从不可变主线基线或 Fork checkpoint 出发，按版本重放事实，在隔离副本中重建时钟、居民状态、日程、事件、承诺、记忆、对话与发言等投影，并与现有投影比对。报告须指出缺失、错误或无来源的记录及其时间线、来源命令和版本；检查过程不修改现有世界数据。
- F2｜Fork 历史边界：重建子线时，使用该线 checkpoint 和分叉后的事实；共同历史必须截止于分叉点。父线分叉后新增的事实、记忆、对话或事件不得进入子线或孙线。缺少结构化起点的旧线保持 `legacy/unknown`，不推断或补造历史。
- F3｜连续生活推进：使用固定数据与确定性模型替身，推进固定居民跨越至少一整天模拟时间，覆盖多个节拍和日程边界。逐拍核对时钟、居民状态及其事实/事件来源，并确认整段历史可审计。完整一天通过测试控制的加速时钟推进，不要求按墙上时间等待一天；加速只用于验收，不改变线上运行速度。
- F4｜版本与重复请求：验证并发或重试情况下，成功的世界变更只产生一次连续版本及对应投影；同一请求 ID、相同内容返回既有结果，同一 ID、不同内容明确冲突。版本冲突或提交中途失败不得留下部分事实、投影或时钟变化。
- F5｜取消、恢复与迟到提交：验证 tick 和在场变更在取消、超时、断流或待处理请求过期后可查询最终状态；失败请求不得留下半完成投影，已过期 worker 不得迟到提交。使用同一请求 ID 恢复或重试时，不重复生成副作用。
- F6｜跨 Worker 并发与写入边界：在共享隔离本地 D1 的两个或更多 Worker 实例间验证竞争推进，确认租约与 fencing 规则使结果最多提交一次；拒绝请求不改变版本、事实或投影。对本阶段涉及的写入口验证跨用户、错配世界/时间线、暂停、归档、调用额度触顶及公开演示写入边界。
- F7｜多级 Fork 隔离矩阵：在根线、子线和孙线的成功、拒绝、重复及并发场景中，验证状态、承诺、记忆、知识、对话和事件的分叉边界。各线只能看到自身和分叉点之前的证据；拒绝或失败的 Fork 不得产生子线或污染源线。

## 非功能需求

- N1：多 Worker 验收只使用新建、可丢弃的本地 D1 数据目录；执行前确认所有 Worker 指向同一隔离库，结束后记录并清理该目录。不得连接项目默认数据库或远端数据库。
- N2：固定夹具、模拟时间与模型替身使多拍旅程和重放结果可重复；通过与否不依赖真实模型、付费服务或外部网络。
- N3：投影重建仅在隔离副本中进行，不修复、覆盖或删除来源数据库中的记录。故障注入数据只存在于可丢弃夹具中。
- N4：遇到未知命令类型、无结构化基线的旧线或不完整 Fork checkpoint 时，必须明确报告无法证明的范围；不得静默跳过或推断历史。
- N5：每项验收记录命令、环境、隔离库位置、退出结果和关键观察；“测试通过”必须对应具体行为证据。
- N6：本阶段只做本地实现与验收，不部署、不执行生产迁移，也不把真实模型生成质量作为通过条件。

## 不做的事

- 不将缺少不可变结构化起点的 legacy 时间线伪装成可完整重建，也不根据叙述文本补造旧事实。
- 不重做世界模型或全面替换现有命令、事实、版本和投影机制；只补齐本规格定义的重建一致性与验收缺口。
- 不扩展居民行动种类、自然语言行动能力或居民目标；连续推进只验证现有行为路径。
- 不以真实模型输出作为功能正确性的证明，也不验证开放式对话的整体质量。
- 不重做产品首页、创世流程、世界视图或 Fork/Compare 的整体交互；只验收与本阶段状态正确性相关的行为。
- 不连接远端 Cloudflare D1、部署 Worker 或执行生产迁移。
- 不将普通旧聊天、章节生成及其他与 P1 结构化世界状态无关的功能纳入本阶段完整回归矩阵。

## 验收标准

- AC1：从固定夹具独立创建两次相同的结构化世界，两次得到一致的起点、居民、时间线和日程描述；测试不调用真实模型或外网。（F1、F3）
- AC2：对有结构化起点的主线，重放事实后，时钟、居民状态、日程、事件、承诺、记忆、对话、逐句发言及访客留言等受版本管理的投影，与现有记录在内容和增删集合上相符。（F1）
- AC3：在隔离副本中分别注入缺失、篡改和无来源投影；审计指出对应时间线、投影类别及来源命令/版本。运行前后原始验收数据库保持不变。（F1、N3）
- AC4：验证根线、子线与孙线的投影重建。各线包含分叉点前应继承的状态和证据，不包含祖先分叉后新增的状态、记忆、知识、对话或事件；缺少 checkpoint 的旧线明确报告不完整，不补造历史。（F2、F7）
- AC5：在测试控制的加速时钟下，通过多个连续 tick 推进至少一整天模拟时间，跨过多个日程边界；每拍后核对状态与事实，整段旅程最终审计一致。加速不要求墙上时间等待一天，且不改变线上运行速度。（F3）
- AC6：相同请求 ID 和内容的重试只产生一份效果；相同 ID 配不同内容明确冲突。版本冲突及故障注入的提交失败不留下部分事实、状态、投影或时钟变化。（F4）
- AC7：取消、断流、超时及过期请求都能查询最终状态；未提交请求不产生半成品，已过期 worker 的提交被拒。使用相同 ID 恢复或重试不会重复调用或产生第二份副作用。（F5）
- AC8：两个独立 Worker 同时尝试推进共享隔离本地 D1 上的同一时间线；最多一个有效推进结果被提交，修订、时钟、事实和投影之间保持一致，旧租约持有者不能迟到写入。（F6、N1）
- AC9：对本阶段涉及的写入口逐项验证跨用户、错配世界/时间线、暂停、归档、额度触顶和公开演示写入。应拒请求明确失败，且没有版本、事实、投影或 Fork 子线副作用。（F6、F7）
- AC10：对多级 Fork 验证成功、重复请求、冲突、拒绝与并发竞争；失败或重复操作不污染源线，不产生多余子线；成功的子线和孙线通过重建审计。（F7）
- AC11：从结构化世界开始，推进居民跨越一整天，运行投影审计，从检查点创建子线，在子线产生独立变化后再分别审计根线与子线；观察到根线保持原状，子线仅呈现继承历史和自身变化。（F1、F2、F3、F7）
- AC12：报告列出各 AC 的实际环境、命令、结果和证据，并将无法重建的 legacy 范围明确列为不完整。所有本规格 AC 均通过，才可标记 P1 出口通过。（N4、N5）
