# s01｜全局验收收口 Spec

## 背景

S01 的 P2、P3、P4 阶段出口已经通过，但全局验收仍有 AC03、AC05、AC07、AC08、AC09、AC14 六项处于“部分完成”。

现有系统已经具备版本化世界写入、时间线隔离、Fork/Compare、居民交谈、请求恢复、权限与预算门禁，以及本地和 Cloudflare D1 多 Worker 验证。剩余问题集中在：

- 全部投影尚不能由独立历史重建过程完整复算并证明等价。
- 真实模型输出异常及多渠道知识传播尚未形成完整闭环。
- 普通聊天缺少跨设备精确恢复所需的持久请求身份。
- 部分 legacy Universe 缺少可证明的完整 Checkpoint。
- 内部引擎和管理操作的权限、预算、世界状态组合覆盖不完整。
- 旧世界 SSE 帧尚未在传输层直接验证切线后的隔离行为。

本轮将关闭这些缺口。对无法可靠恢复历史证据的 legacy Universe，不补造事实，而是保留数据并明确降级为只读、证据不完整状态。

## 目标

- G1：关闭六项部分完成的全局验收，使 AC01–AC15 全部具有可复核的通过证据。
- G2：让所有受支持的 Universe 都能从不可变基线、命令和事实独立重建投影，并与持久化状态逐域比较。
- G3：对无法证明完整历史的 legacy Universe 进行显式分级和安全降级，不伪造 Checkpoint、事实或因果关系。
- G4：保证居民在多渠道信息传播、连续生活和真实模型参与时，仍遵守知识可见性、来源和可信度边界；异常模型输出不得形成错误世界状态。
- G5：让普通聊天具有持久请求身份，可在刷新、断流、进程切换和跨设备场景中查询状态、精确恢复或安全重试，且不会重复调用或重复写入。
- G6：让所有用户入口、内部引擎入口和管理操作统一遵守身份、世界归属、时间线状态及预算限制，拒绝路径不产生副作用。
- G7：通过本地自动化、登录态浏览器、多 Worker、staging D1、真实模型抽样及传输层竞态注入完成端到端验收。
- G8：保留现有兼容行为和历史数据；完成后同步规格、审计、质量报告及实际测试结果，只有全部全局验收通过才关闭 S01。

## 功能需求

- F1｜独立投影重建：对所有受支持的结构化 Universe，系统必须仅依据不可变基线、命令和事实，独立重建时钟、人物状态、事件、知识、记忆、日程、对话、承诺、请求状态及其他持久投影；重建过程不得读取待验证投影作为事实来源。
- F2｜逐域等价与诊断：系统必须逐域比较重建结果与当前持久化状态。缺失、额外、篡改、无来源、版本错位或跨时间线污染都必须被定位到具体 Universe、时间线、版本、证据来源和投影域；审计本身不得修改数据。
- F3｜Legacy Universe 分级：现有 Universe 必须被判定为“完整可重建”“可由可靠证据升级”或“证据不完整”。只有可证明的历史才能升级；证据不完整的 Universe 保留可读数据，但明确显示限制并禁止继续写入、运行、Fork 或将其结果描述为完整历史。不得从当前投影反向补造事实或 Checkpoint。
- F4｜知识与真实模型边界：私有知识只能进入获授权居民的上下文；转述必须保留来源与可信度，传闻不得自动升级为事实。该边界必须覆盖普通聊天、在场交谈、居民间对话、引擎决策、记忆摘要及多跳传播。真实模型返回截断、无效、矛盾或越权结果时，不得形成完成回复、错误知识或世界状态；系统应给出可恢复的失败结果。
- F5｜真实居民连续生活：使用真实模型推进居民多个连续节拍，覆盖离场、刷新或重新进入后的继续运行。可观察结果必须经版本化记录持久化，并能追溯到模型请求、可见上下文和来源证据；验收不要求模型产生固定叙事，但要求结构、隔离、可信度和提交边界始终成立。
- F6｜普通聊天精确恢复：每次普通聊天发送必须具有持久、稳定且与用户、人物、世界、时间线和载荷绑定的请求身份。刷新、断流、Worker 切换或跨设备重新打开后，用户能够查询请求状态并恢复结果；相同身份和相同载荷不得重复调用模型或重复写入，不同载荷复用同一身份必须冲突。失败或取消不得留下伪完整回复。
- F7｜统一权限、状态与预算门禁：所有用户入口、内部引擎/director 路径、后台恢复任务及管理操作，都必须一致校验身份、所有权、世界归属、时间线归属、运行状态、归档状态和预算。拒绝请求不得调用模型，也不得改变版本、事实、命令、投影、请求状态或预算账本；不同用户和世界的预算必须隔离。
- F8｜迟到结果与传输隔离：切换世界或时间线后，旧快照、旧请求结果、旧订阅回调及已经到达传输层的旧 SSE 帧都不得覆盖当前页面或写入当前选择。原请求若最终完成，只能归属其原世界、时间线和会话。
- F9｜全局出口与证据同步：本地测试、浏览器旅程、多 Worker、staging D1、真实模型抽样及故障注入必须使用隔离环境并记录实际结果。规格、任务、Checklist、审计和质量报告必须一致；只有 AC01–AC15 全部通过且工作区交付状态清楚时，才能将 S01 标记为完成。

## 非功能需求

- N1｜确定性与可重复性：相同基线和历史输入必须产生相同重建结果。除明确标记的真实模型抽样外，自动化验收使用固定时钟、固定标识和可控模型替身。
- N2｜数据真实性：不得为了通过验收而补造历史命令、事实、模型回复、Checkpoint 或因果关系。未知和证据不完整必须作为一等状态保存和展示。
- N3｜兼容与数据保留：现有世界、时间线、人物、对话和历史记录不得被静默删除或改写。迁移必须可重复执行，并能区分无需变更、成功升级和无法可靠升级的数据。
- N4｜原子性与幂等性：请求预留、模型调用记账、命令、事实、投影和最终状态之间不得留下不可解释的部分提交。重放、并发、取消、超时和 Worker 故障必须收敛到唯一、可查询的结果。
- N5｜隐私与最小披露：私有知识、聊天内容、模型凭据、验收 canary、账号标识和远端数据库配置不得进入未授权上下文、公共响应、日志或仓库。失败报告只保留诊断所需的最小信息。
- N6｜有界资源消耗：投影重建、权限矩阵和连续生活验收必须有明确的数据规模、时间上限及模型调用上限。生产请求不得因全域审计而无界扫描历史；离线全量审计与在线增量检查应具有清晰边界。
- N7｜环境隔离：本地验收使用一次性数据库和合成账号；远端验证只能访问显式指定的 staging/acceptance 环境。不得访问生产数据库，不得把临时凭据或测试配置提交到仓库。
- N8｜真实模型调用控制：真实模型验收必须在用户单独授权后运行，预先声明最大调用次数和可能费用。失败、超时及格式错误的调用计入预算，不得自动无限重试，也不得把固定模型结果冒充真实模型结果。
- N9｜可观测恢复：长运行请求必须具有可查询的状态、更新时间和终态。客户端中断、跨设备恢复及后台回收都应产生可复核状态，不依赖单一浏览器内存或标签页存储。
- N10｜证据先行：每项完成结论必须对应实际命令、测试结果、浏览器观察或账本审计。构建通过不能替代用户旅程，固定模型通过不能替代明确要求的真实模型抽样。
- N11｜交付完整性：最终变更应按逻辑单元整理，保留进入本轮前的用户改动，并通过格式、类型检查、全量测试、迁移检查和差异检查。未提交或未验证的内容必须明确列出，不得被隐含为已完成。

## 不做的事

- 不从现有投影反向编造缺失的历史命令、事实、模型回复或 Checkpoint。
- 不让证据不完整的 legacy Universe 继续写入、运行或 Fork；本轮只保留安全读取、明确提示和可证明的升级路径。
- 不重新设计世界页、聊天页或 Compare 的整体信息架构；只增加完成全局验收所需的状态、恢复和限制提示。
- 不改变已经通过的 Fork、Compare、版本化提交和时间线隔离业务语义，除非验收发现它们与本轮硬性要求冲突。
- 不要求真实模型生成固定文风、固定剧情或固定决策；只验证结构有效性、知识边界、连续性和失败安全。
- 不训练或微调模型，不扩展到所有模型供应商；只验收项目当前明确支持并获授权调用的模型配置。
- 不把真实模型的猜测当作事实正确性证明，也不声称模拟能够预测现实。
- 不在生产数据库、生产 Worker 或真实用户数据上执行迁移、故障注入、压力测试或验收。
- 不构建通用管理后台、数据修复平台或新的可观测性产品；只提供关闭 S01 所需的诊断和安全入口。
- 不无限扩大投影域；范围限定为当前产品会持久化和读取的世界、时间线、人物、状态、事件、知识、记忆、日程、对话、承诺、请求及预算数据。
- 不自动执行未经用户授权的付费模型调用、远端部署或生产变更。
- 不删除、覆盖或顺带整理与 S01 无关的工作区改动；现有未提交内容在后续开发前单独盘点归属。

## 验收标准

- AC1｜全域独立重建（关闭全局 AC03）：对新建主线、子线和孙线，仅使用不可变基线、命令与事实重建所有支持的投影；逐域标准化比较结果完全一致。对每个投影域分别注入缺失、额外、篡改、错版本或错时间线数据，审计必须定位具体差异，且审计前后数据库内容不变。（F1、F2）
- AC2｜Legacy 分级与安全降级（关闭全局 AC09）：使用代表性的完整、可升级和证据不完整旧数据集执行迁移与分类。完整数据保持可运行；可升级数据只依据已有可靠证据生成缺失结构；不完整数据保持可读并明确提示限制，所有运行、写入和 Fork 尝试均被拒绝且无副作用。任何分类都不得补造未知历史。（F3）
- AC3｜多渠道知识与可信度矩阵（关闭全局 AC05）：在普通聊天、在场交谈、居民间对话、引擎决策、记忆摘要和多跳转述中验证：只有授权居民获得私有信息；来源链可追溯；传闻不会自动升级为事实；无知识居民不会从系统上下文获得 canary；公共视图不泄露私有内容。（F4）
- AC4｜模型异常输出安全：分别让模型返回有效结果、截断结果、无效结构、矛盾可信度、越权内容、超时和中断。只有有效且完成的结果可以提交；其余请求进入明确可恢复的失败终态，不产生完整回复、知识升级、世界命令、事实或投影变化，也不发生无限重试。（F4）
- AC5｜真实模型连续生活旅程（关闭全局 AC07）：在用户明确授权的调用上限内，让真实居民完成多个连续决策点，并覆盖离开页面、刷新或重新进入后继续推进。每项持久结果都能追溯到请求、当时可见上下文和版本化证据；无效模型输出按 AC4 安全失败。真实模型样本必须全部满足结构和隔离断言，失败样本不得被固定模型结果替代。（F4、F5）
- AC6｜普通聊天跨设备精确恢复（关闭全局 AC08）：客户端 A 发起聊天后，在响应前由客户端 B 查询同一请求。相同请求身份和载荷只能产生一次模型调用及一组最终消息；完成、失败、取消、断流、超时和过期回收均有可查询终态。相同身份配不同载荷必须冲突；失败路径不留下伪完整居民回复。（F6）
- AC7｜权限、状态与预算全矩阵（关闭全局 AC14）：对全部用户入口、内部引擎/director、恢复任务及管理操作，逐项验证匿名、跨用户、错世界、错时间线、暂停、封顶和归档状态。拒绝时模型调用数、预算账本、版本、命令、事实、投影和请求记录均无非预期变化；允许路径的预算只计入正确用户和世界。（F7）
- AC8｜旧结果与 SSE 传输隔离：人为延迟旧世界或旧时间线的快照、请求、订阅回调和已进入传输层的旧 SSE 帧，在到达前切换选择。迟到内容不得改变当前页面、版本或会话；原请求完成后只能在原归属位置查询到。（F8）
- AC9｜兼容、迁移与完整旅程回归：现有 AC01、AC02、AC04、AC06、AC10–AC13、AC15 的通过证据必须继续成立。全新数据库、代表性旧数据库和显式 staging D1 均能完整应用迁移且无待处理项；CREATE→RUN→OBSERVE→ENTER→ACT→CHAT→FORK→COMPARE→RETURN 的登录态旅程通过，匿名入口仍保持只读。（F1–F9）
- AC10｜S01 全局出口：API/Web 全量测试、构建、差异检查、本地多 Worker、staging D1、浏览器旅程、故障注入和获授权的真实模型验收均记录实际结果；规格、任务、Checklist、审计和质量报告状态一致。只有原全局 AC01–AC15 全部为“通过”、没有未解释的验收失败，才可将 S01 标记为完成。（F9）
