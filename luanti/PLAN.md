# Luanti 基准与验证记录（2026-10-28）

本文件记录社会实验的范围与结果；本分支完整产品目标和实施安排见[工作计划](../docs/PLAN.md)。

状态：第一轮实施、第二轮实现、容量对照、记忆实测、预算调优和最终验证均已完成。当前证据显示万级完整规则负载可以保持角色存活和完整工作量，但尚未达到每人 2 秒决策目标；受控真实模型任务中检索优于 FIFO，尚不能外推开放世界长期记忆或社会涌现。

目标：在 Luanti 中量化从实体到感知、记忆和模型决策各层的成本，并用真实模型探索角色互动。单纯实体数量不能代表 LLM agent 容量；报告须包含决策频率、延迟、失败和资源消耗。

## 第二轮执行计划（2026-10-28）

目标：检验共享邻域索引与分帧调度能否提高完整规则负载的可用规模；检验相同存储、输出预算下的检索记忆是否改善特定记忆任务。未量测前不预设提升幅度，也不将规则容量称为模型容量。

- [x] 核对第一轮证据、当前源码与资源约束；先更新本计划。
- [x] 空间索引：按精确球形距离返回公开角色对象，移动后立即更新；替换规则感知、角色观察、接触的重复引擎邻域扫描。测试边界、负坐标、跨格移动、自身排除、稳定排序和与穷举等价性。
- [x] 分帧调度：保留 legacy 开关用于同源码对照；优化侧每帧限时处理一轮的一部分，禁止在一个 callback 追赶多轮。保留每人 12 次动作的完整工作量；同时记录完成耗时、实际动作吞吐、callback 成本与引擎步率，避免仅靠降低决策频率改善指标。
- [x] 云端容量：每个规模的新旧对照在同一 runner/runtime，1000/5000/10000、cognition 开关、每人 12 次决策、2 秒目标间隔、相同 seed/spacing/bounds。各侧至少 5 次交替运行；性能失败仍归档。增加一个优化侧较长运行（每人 60 次决策，不代表长期稳定性）。检查存活、决策总数、世界回读和确定性；若调度改变事件序列，单独说明，不能宣称逐事件等价。1000/5000/10000 均完成；10000 长跑完成 600,000 决策，约 15 分钟，不代表长期稳定性。完整证据见 `scale/evidence/2026-10-28-optimization/`。
- [x] 检索记忆：有界本地事件库，保留来源与时间；确定性词项/实体相关检索，不调用 embedding 服务。FIFO 与检索共享同样的存储容量、返回条数及序列化字符上限；记录实际 token，用量无法确定时保留 unknown。实现与同源 Lua 测试已验证。
- [x] 记忆评估：延迟回忆、来源归属、过期事实、避免已知失败，多个 seed 和交替条件，先确定性数据/评分验证再调用已配置模型。24 次真实配置模型调用全部完成：retrieval 12/12，FIFO 0/12；token 13,480，零错误。结论限定为这组受控任务。
- [x] 调度预算取舍：10,000＋cognition 在独立 runner 内交替 25／50／65 ms 软预算，各 5 次，记录步率、实际间隔、完整吞吐与成本。65 ms 为 5/5 通过且中位完整耗时最低的选择，已改默认；中位实际间隔约 4.97 秒，不能宣称每人 2 秒决策达标。
- [x] 有限并发探针：核心验证通过后，在同一真实模型端点以 1/2/4 个 worker 测小批请求，记录吞吐、尾延迟、失败/限流和总用量。24/24 请求成功；由于每级单批、没有重复交替和 limiter profiling，结论保留为 inconclusive，不推断万人同时调用能力。
- [x] 复核集成差异和证据，永久保留压缩原始日志、配置、源码 SHA、结果摘要及校验清单；同步 docs 索引和审计记录，提交并推送实验分支，不合并 main。最终验证运行 `40753203801` 成功，工作区测试集合为 92 个 Python 测试和 7 个 Lua 5.1 套件，容量、模型和验证产物均已按目录归档。

职责与依赖：主 agent 拥有 init.lua、调度、runner、workflow 和集成；worker A 只修改空间索引及其测试，worker B 只修改记忆模块、评估器及其测试。先约定接口，再并行开发，主 agent 集中安排所有重型操作，三个规模互不共用 runner，独立模型任务可在第四台 runner 并行，模型作业之间单独串行。评估调用依赖记忆模块完成，容量实验依赖引擎集成完成。

资源与停止条件：GitHub Actions 免费资源已获用户授权，需仓库推送、Actions 执行及 artifact 读取权限；不上传秘密或原始模型凭证。重型引擎、全量验证、并发探针都在云端执行；三个规模可用独立 runner 并行，每个 runner 内的重型操作串行，本机仅定向轻量测试。下载使用项目 .tmp，流式处理大日志。真实模型错误有界退出，绝不无限重试；未通过性能门槛如实报告。云端不可用时记录缺口，不用本机重型任务绕过。

预期可发布主张形式：“在所记录 runner 与相同完整工作量下，优化侧的总完成时间、决策吞吐和引擎步率为……；FIFO 与检索在指定任务、相同预算下的成功数为……”。速度提升需结合至少 5 次交替运行的中位数和范围、正确性与成本一起判断。

## 验收与顺序

1. **基线和容量**：在 GitHub Actions 顺序测实体与感知，记录版本、配置、资源、存活、推进率、错误和原始日志；对感知、记忆与模型调度的额外成本分别测量。重复运行并给出范围；结果只适用于实际配置。
2. **观察、行动、记忆**：角色只接收自身能观察的状态；行动经引擎验证并记录结果。每条记忆标明来源与时间，限制容量，确保其他角色的私人信息不可见。测试正常、失败和隔离路径。
3. **快照和重置**：停服后保存世界及角色状态，以相同世界启动独立实验并重置记忆、关系与 persona，保留 body ID；验证副本隔离、初始状态与可重复性。
4. **真实模型闭环**：从 GitHub 配置的端点调用免费模型，限定目标地址、输入和动作；记录请求数量、延迟、token（如提供）、错误及实际生效的模型动作，不记录密钥。先用 3–5 个角色，保留规则策略作对照。
5. **互动与调度实验**：观察采集、建造、交流和合作；用相同初始世界和条件比较记忆开关，报告互动事件和失败案例。用受控延迟及实际吞吐量测排队、过期请求和决策频率，推算而非冒充实测千人模型负载。
6. **汇总**：保存可复现命令、版本和原始证据；明确哪些条件下达到实时、瓶颈和尚未解决的问题。没有实际证据的项目不得标为完成。

## 实现边界与评估约定

- 角色是服务端 Lua 实体，平面位置移动，没有玩家视角、碰撞／寻路、生存机制或真实客户端。`meet` 是距离事件，不是对话或合作；persona 目前只是标签。
- 基线情节记忆每人 32 条，记录来源与时间；当前消息和上次动作结果独立于历史开关。没有长期语义检索、reflection、关系推理和持久计划。初轮摘要把资源计入 marks 的缺陷已修复，故初轮只保留诊断意义。
- 模型只返回受限动作；坐标／目标／库存由执行器校验。队列不阻塞 tick。运行时不读 `.env`；只把合成实验信息发送到用户已配置端点。
- Actions 安装 Luanti 5.10.0，不能外推后续引擎版本。RSS 每秒采样且只含引擎，不含模型 worker 或 provider；区间 stepped 只表示至少推进过一次。合成实体阈值 11.0，与 agent 运行器的 10.0 阈值不同。
- 首轮大阶梯每人 4 次决策，统计触发依赖模拟时间，10,000＋cognition 缺样本；修正后按墙钟统计、结束补样本并记录每轮墙钟耗时，再做每人 12 次决策的三次重复。两轮数值不直接作为性能提升比较。
- 改进观察后的三次配对使用同一停服世界分别复制、每组每次 3 人×8 动作，交替组顺序；共同提示要求采集、交流和建造。这是目标驱动任务探测，不能把被提示的行为当作自发涌现，也不能用三次样本宣称记忆有统计收益。
- 云端 job 绿色代表验证程序执行完成；大阶梯每项的 FAIL 状态照常保存，不会包装成“万级性能通过”。格式重试计入 token 和延迟；传输／provider 错误记录可测时延，缺失 token 标为 unknown，不能推断总用量。失败不自动改走规则策略。

## 已处理的问题

独立审查发现并处理：恢复批次在验证前清空存档；有响应文件时绕过截止时间；失败动作误报 applied；资源计入 marks 摘要；夹具缺少显式来源；队列模拟在截止前提前计过期。云端负向恢复进一步暴露统一失败收尾与旧用例断言不匹配，已统一记录 `done result=fail` 并按错误类型验收。所有问题与重跑记录见 [.audit](../.audit/wispiva-luanti.tsv)。

## 已完成的重复结果

[模型与配对运行 40733909302](https://github.com/kikoiio/Wispiva/actions/runs/40733909302) 完整成功。三次配对、每组 72 个有效动作；[逐次结果与证据](model/evidence/2026-10-28-memory-paired/summary.md)。开启记忆／关闭记忆分别成功采集 10／8 次、放置 5／5 次、消息 14／15 条；token 为 81,401／61,230（含重试）。未证明记忆有可靠任务收益。实际发生对话与资源修改，不构成共同结构或自发社会分工的证据。

同一运行的 1,000 人规则策略，间距 2、边界 64、每人每 2 秒决策一次，共 12 次，每条件重复 3 次。关闭附加观察／情节记忆时，区间最低步频为 10.67–10.73、各次中位数 10.92–10.96，RSS 92–93 MiB，3/3 通过 ≥10 的约定阈值。开启时最低 9.66–9.84、中位数 9.91–10.06、RSS 101 MiB，3/3 未通过。两组角色均存活、每次完成 12,000 决策；[原始压缩日志与汇总](scale/evidence/2026-10-28-repeated-1000/results.json)。这是 26–27 秒（含启动）的有限测量，不是长时稳定性；关闭条件仍有规则感知与接触集合。运行器当时只自动对照前两次；收尾另核对三次的完整事件 SHA-256，各条件三次均相同，见同目录 reproducibility.json。最终运行器已改为比较所有重复。

## 重跑本轮配置

运行器、变量／secret 名称与数据格式见 [模型说明](model/README.md)。当前工作流不依赖合并 main：从包含工作流的提交推送唯一的 `validation/luanti-model-...` 分支，触发配对和 1,000 人重复；`validation/luanti-large-...` 触发万级重复和队列模拟。工作流 concurrency 保证顺序。

```sh
git push origin HEAD:refs/heads/validation/luanti-model-<唯一后缀>
gh run list --workflow wispiva-validation.yml --limit 5
gh run watch <运行ID> --exit-status
```
