**POSSIBILITY**

**产品概念与体验设计**

*A place for what could be.*

  ------------------------------------------------------------
  让一个人的某种可能版本存在于一个小小的平行世界里。\
  用户可以与 TA
  相遇、交谈、观察生活，也可以改变一个条件，探索另一种可能。
  ------------------------------------------------------------

  ------------------------------------------------------------

核心不是 AI Agent，而是
Possibility：一种可以被创造、进入和经历的可能性。

# 1. 产品定义

Possibility
是一个个人平行世界平台。用户可以创建自己、认识的人、想认识的人、失去联系的人、公众人物或虚构人物的"可能版本"，让这些人物在一个持续运行的世界中生活。用户既可以作为观察者，也可以进入世界，与人物进行实时语音或文字交流。

同一个平台还允许用户从某个时间点改变一个条件，创建新的
Timeline，探索"如果当时......"可能如何发展。

## 一句话定义

**Create people. Give them a world. Meet them. Explore what could be.**

## 核心产品原则

- 用户创造的是 Version，不是真人的精确复制品。

- 用户体验的是 Possibility，不是对现实或反事实的确定预测。

- 人物应该持续存在，而不是每次打开都只是一次新的 Chat session。

- 世界应该能够自行运行；用户可以观察、进入、交流和干预，但人物保留自主性。

- AI、Prompt、Skill、Memory Store、Agent Runtime
  等技术概念默认隐藏在产品界面之下。

# 2. 产品的基本模型

  --------------------------------------------------------------------------------
  **Person**              **World**                        **Timeline**
  ----------------------- -------------------------------- -----------------------
  谁在这里                他们在哪里、何时、遵循什么规则   事情如何随时间发展

  自己 / 他人 / 公众人物  现实 / 回忆 / 假设 / 虚构环境    主时间线 / 分叉时间线
  / 虚构人物                                               

  Identity + Behavior +   Places + Context + Events +      Actions +
  Memory + Skills         Rules                            Consequences +
                                                           Relationships
  --------------------------------------------------------------------------------

**Possibility = People × World × Timeline**

## Possibility 的对象层级

- Possibility：一个可运行、可进入的可能世界。

- Version：某个人在这个世界里的模拟版本。

- World：时间、地点、社会背景、规则与可发生事件。

- Timeline：这个世界已经发生的历史。

- Fork：从某个节点改变条件后产生的新时间线。

- Visit：用户以参与者身份进入世界。

- Call：用户直接与某个 Version 实时交流。

# 3. 两个核心体验

## A. Meet --- 与一个想接触的人相遇

用户可能只是想和某个人说话。这不应该要求先创建复杂世界。用户只需要描述"我想见谁"，系统自动建立最小可用的人物版本和背景环境。

- 实时语音优先：体验更接近"打电话给一个人"，而不是语音助手。

- 持续关系：人物记得双方过去的交流、共同经历、关系变化和边界。

- 持续状态：人物在用户没有说话时也处于某个时间、地点、活动和情绪状态。

- 用户可直接 Call，也可以 Visit 对方所在的 World。

## B. Explore --- 探索"如果当时......"

用户给出一个反事实起点，例如"如果我当时没有离开北京"。系统把它转换为一个
Scenario：确定起始时间、改变的变量、参与人物和尽量保持不变的条件，然后创建新的
Timeline。

- 默认采用"改变一个变量，其他条件尽量保持一致"的设计。

- 结果表达为 plausible possibility，而不是预测"真正会发生什么"。

- 允许生成多个不同但合理的 Timeline，避免制造单一确定答案。

- 任何已有世界都可以从关键节点 Fork。

# 4. 首次使用体验

首页不问用户"创建 Agent 还是 Simulation"，而只问一个问题：

**What would you like to make possible?**

  ------------------------------------------------------------------------------------------------------
  **Meet someone\**                  **Explore a what-if\**           **Create a world\**
  我想认识、再次见到或和某个人交流   我想知道如果某个选择不同会怎样   我已经知道想放入哪些人和什么环境
  ---------------------------------- -------------------------------- ----------------------------------

  ------------------------------------------------------------------------------------------------------

## 创建人物：不要要求 skill.md

普通用户入口应该是自然语言和材料上传。skill.md / JSON / Agent package
只作为 Advanced Import。系统从用户材料中自动蒸馏出一个可编辑的 Person
Model。

- Describe：直接告诉系统这个人是谁。

- Upload：聊天记录、文章、邮件、音频、视频、日记、人物资料等。

- Interview：系统针对未知行为模式提出少量具体情境问题。

- Review：生成一张用户看得懂的 Person Card，并明确标注 What we know /
  What we infer / What we don\'t know。

- Advanced：允许导入结构化人物包、skill.md 或开发者格式。

# 5. Person Model

人物不应该被压缩成单一 skill.md。推荐把"一个人"建模为以下几个层次：

  ------------------------------------------------------------------------------------------
  **层**                              **作用**
  ----------------------------------- ------------------------------------------------------
  **Identity**                        生平、身份、价值观、偏好、世界观

  **Behavior**                        面对具体情境时通常如何判断、选择和反应

  **Speech**                          语言习惯、语气、幽默、交流节奏

  **Skills**                          专业能力、爱好、做某类事情的方法

  **Memories**                        人物已知经历、重要事件、关系记忆

  **Relationships**                   与用户及其他人物的熟悉度、信任、亲密、冲突、共同记忆

  **Boundaries**                      哪些事情人物不知道、不能确定或不应声称

  **Runtime State**                   当前地点、活动、目标、情绪、精力、计划
  ------------------------------------------------------------------------------------------

## Person Card

Person Model 是底层表示；Person Card
是用户看到的版本。它应该让用户快速校正人物，而不是编辑 Prompt。

建议展示：核心特质、说话方式、价值观、日常倾向、重要关系、已知记忆、技能，以及最重要的
Unknowns。

# 6. World Builder

环境设定同样不应该要求
environment.md。用户可以只写一句话，系统自动生成世界；需要控制时再逐层展开。

- Quick World：一句话描述，例如"2019 年的北京，我没有离开"。

- Templates：小镇、大学、都市、公寓、历史时期、完全虚构世界等。

- Customize：地点、时间、人口、世界规则、事件密度、现实程度。

- Advanced World Editor：供研究者或高级用户编辑规则、事件和环境文件。

# 7. 世界运行与观察界面

进入一个 Possibility
后，主界面应强调"世界正在运行"。地图不一定是第一版必需品，但必须让用户感受到时间、人物位置、活动和事件持续变化。

- 顶部：World / Timeline / 当前日期时间 / 时间速度 / Pause。

- 中央：World view（地图、地点列表或事件流）。

- 人物卡：当前位置、当前活动、状态、目标。

- Activity：最近发生的行动和互动。

- Call：直接实时语音联系某个人。

- Visit：以用户身份进入世界并与人物互动。

- Why?：解释某个行为主要受哪些记忆、目标、关系和当前状态影响。

- Fork：从任何关键事件创建另一条 Timeline。

# 8. 用户如何介入世界

用户应该能够影响世界，但不应默认直接控制人物。更自然的设计是改变人物能够感知到的条件，然后让人物自己决定。

  ------------------------------------------------------------------------
  **用户动作**                        **例子**
  ----------------------------------- ------------------------------------
  **Talk / Call**                     直接与人物交流

  **Visit**                           以自己或一个角色进入世界

  **Send information**                某人收到一条消息或邀请

  **Change environment**              下雨、公司裁员、搬家等外部变化

  **Trigger event**                   社交、职业、冲突、偶发事件

  **Fork choice**                     把一个已经发生的选择改成另一个选择
  ------------------------------------------------------------------------

# 9. Memory 与 Timeline 必须隔离

同一个人物可以存在于多个 Possibility 或 Timeline
中。必须区分现实资料、主世界经历和各条反事实时间线，否则不同世界的记忆会互相污染。

- Source / Canon Memory：用户提供或可靠来源中明确存在的信息。

- Persistent World Memory：人物在默认世界中实际经历的事件。

- Timeline Memory：只属于某条 Fork 的经历。

- Relationship Memory：人物与用户在特定世界中的共同经历。

默认情况下，人物不应把某条反事实 Timeline
当成现实记忆。可以提供明确的"Let this version
remember"选项，但必须由用户主动选择。

# 10. 信任、身份与边界

因为产品可能涉及现实人物、已故人物和公众人物，可信边界不是附加功能，而应该进入核心产品设计。

- 始终使用 Version / Simulation
  等概念，不把模型呈现为"本人复活"或本人真实思想。

- 明确区分用户提供的事实、模型推断和未知信息。

- 真实人物的声音相似度与人物行为模拟分开处理；高度相似的声音/形象应有独立授权机制。

- 公众人物应清楚标识为模拟版本，并说明主要依据公开资料。

- 反事实结果应标识为一种 plausible timeline，而不是预测或事实。

- 提供删除人物资料、导出资料、来源查看和隐私控制。

# 12. MVP 建议

第一版不要试图先做完整"元宇宙"。先证明三个体验成立：

1.  Create a Person：自然语言 + 文件材料 → Person Card →
    可校正的人物版本。

2.  Call a Person：低延迟实时语音 +
    长期关系记忆，让用户感受到"这个人一直存在"。

3.  Create a What-if：一句话改变一个条件 → 运行一段时间 → 时间线事件流 →
    可与其中人物交流。

## MVP 可以暂缓

- 复杂 3D 世界或完整游戏地图。

- 大量同时运行的 Agent。

- 开放式用户脚本系统。

- 高度复杂的经济/物理模拟。

- 把 skill.md 暴露给普通用户。

# 13. 核心循环

**CREATE → MEET → LIVE → CHANGE → FORK → RETURN**

用户创造一个人或一个世界；与其中的人相遇；世界继续生活；用户改变一个条件；产生新的
Timeline；再回到人物交流或继续观察。这个循环把"AI companion"和"world
simulation"统一为一个产品。

# 15. 最终产品愿景

Possibility
不试图告诉用户"事情本来一定会怎样"。它提供一个空间，让那些现实中无法发生、没有发生、已经错过，或者尚未发生的相遇与人生，以一个明确属于"可能性"的方式暂时存在。

用户可以创造另一个自己，遇见一个想认识的人，让几个人生活在一个小世界里，或者从人生中的某个节点创造另一条时间线。

***Possibility gives the "what if" somewhere to live.***
