# Possibility 产品愿景

> 一个可以创造、进入、交谈、干预和分叉的生成式平行世界。

## 文档目的

这是一份愿景文档。它描述 Possibility 最终想创造什么、用户应该获得怎样的体验，以及我们判断这个愿景是否成立的标准。

它不描述当前版本的能力，不承诺具体发布日期，也不规定技术架构、模型供应商、交互界面或实现顺序。当前实现可以不完整，也可以被替换；只要它仍然朝向这里描述的产品目标。

## 1. 我们想创造什么

Possibility 是一个以世界为中心的生成式开放环境。

用户可以创造一个世界，让它拥有自己的时间、空间、居民、关系、组织、资源、规则、信息和历史。这个世界能够持续变化，其中的人基于自己知道的事情、所在的位置、拥有的关系和正在追求的目标采取行动。

用户既可以站在世界外观察，也可以以一个世界内身份进入其中，与居民实时交流、采取行动、作出承诺并承担后果。用户还可以改变一个条件，从当前状态分叉出新的宇宙，让相同的过去通向不同的未来。

Possibility 的核心不是生成更多内容，而是让一个可能世界能够被创造、经历、改变和比较。

## 2. 为什么是平行宇宙

现实只有一条已经发生的历史，但人的理解天然包含许多可能性：

- 如果一个决定不同，之后会发生什么？
- 如果几个人在另一个环境中相遇，他们会建立怎样的关系？
- 如果一个规则、资源或信息发生变化，世界会如何重新取得平衡？
- 如果我亲自进入其中，我能改变什么，又会被什么改变？

传统互动内容通常把这些可能性预先写成有限的剧情分支。Possibility 希望把分支点从作者预设的选项中释放出来：用户可以在任意有意义的时刻提出一个改变，并让新的宇宙从那里独立发展。

这里没有唯一的“正确时间线”。每个宇宙都是在特定条件下形成的一种可能。Fork 的目的不是预测现实，而是让不同可能性变得可经历、可观察和可比较。

## 3. 世界是第一产品对象

Possibility 不是一组角色聊天窗口。人物、对话、事件和故事都属于世界，并且只有放回世界状态中才具有意义。

一个世界不只是背景描述。它至少包含：

- **时间**：当前时刻、持续时长、先后顺序、等待和变化速度。
- **空间**：地点、距离、连接方式、人物和物品所处的位置。
- **居民**：身份、能力、需要、目标、习惯、边界和当前状态。
- **关系**：熟悉、信任、依赖、冲突、权力、承诺和共同历史。
- **组织**：家庭、社区、机构、公司、群体以及它们的规则和利益。
- **资源**：金钱、物品、机会、时间、精力、信息以及其他稀缺条件。
- **规则**：自然规律、社会规范、制度、世界设定和不可随意改变的约束。
- **信息**：事实如何产生、被谁知道、如何传播，以及误解和秘密如何存在。
- **事件**：行动、偶然和外部变化对世界状态造成的改变。
- **历史**：已经发生、不能被当前宇宙悄悄改写的共同过去。

世界状态先于叙述。事件流、对话、章节、地图或摘要只是观看世界的不同窗口，不等同于世界本身。

## 4. Possibility 的概念模型

### Possibility

一组共享同一世界基础、但拥有不同发展历史的平行宇宙。它容纳共同起点、所有 Fork 以及它们之间的关系。

### World Model

世界的基础定义，包括世界允许什么、存在什么、遵守什么规则，以及初始状态是什么。它是多个平行宇宙共享的语义基础。

### Universe

世界的一次具体存在。一个 Universe 在任何时刻都有自己的当前状态，并且独立于其他宇宙继续发展。

### Timeline

一个 Universe 已经发生的有序历史。它记录状态如何随事件变化，而不仅是一组生成文本。

### Checkpoint

某个可被准确返回、观察或用于 Fork 的世界状态。Checkpoint 保留当时已经成立的事实边界。

### Fork

从一个 Checkpoint 复制完整状态，保留不可变的共同过去，并从指定改变开始形成新的 Universe。Fork 之后，各个宇宙的状态、记忆和历史互不污染。

### Inhabitant

生活在世界中的居民。居民不是等待用户提问的助手，而是受到世界规则约束、拥有局部知识和自主目标的参与者。

### Presence

用户在某个 Universe 中被世界承认的身份。Presence 使用户能够从“世界之外的操作者”变成“世界之中的参与者”。

### Intervention

构造者对世界条件施加的显式改变，例如引入一场暴雨、关闭一家工厂、改变一项制度或投放一条信息。Intervention 改变条件，但不直接规定居民必须作出什么反应。

## 5. 什么叫“足够真实”

Possibility 追求的不是画面上的拟真，而是结构上的可信。一个世界是否真实，取决于用户能否相信它在自己看不见的时候仍然遵守同一套事实和规则。

### 5.1 持续存在

世界在一次对话或一次页面访问结束后仍然保持状态。人物的位置、计划、关系、知识和承诺不会因为用户关闭界面而重置。

持续存在不意味着每一秒都必须产生内容，而是世界从不无理由地失去自己的过去。

### 5.2 时间与空间连续

人物不能同时出现在互不相容的地点，移动需要时间，行动具有先后关系。发生在昨天的事可以影响今天，但未来的信息不能倒流成为过去的记忆。

### 5.3 局部知识

居民只知道自己能够知道的事情。没有目击、获知或推断依据的人，不应因为系统知道某件事就自动知道它。秘密、误解、传闻和信息传播因此才有意义。

### 5.4 因果一致

事件必须留下与其规模相称的后果。受伤、失约、搬家、争吵、获得资源或失去工作不能只存在于一段文本里；它们应改变之后可发生的事情。

### 5.5 居民自主

居民有自己的目标、偏好、边界和处境。他们可以拒绝用户、误解用户、改变主意，也可能优先处理与用户无关的事情。

自主性不意味着随机。行为应当能够从居民的经历、认知、关系、目标和当前条件中得到理解。

### 5.6 资源与约束真实

世界中的行动有条件、有成本、有失败的可能。时间、距离、精力、关系、制度和物质条件都会限制愿望。开放世界不是无限满足愿望，而是允许用户在明确规则内尝试未被预先写好的行动。

### 5.7 后果持久

一次谈话、一次行动或一个承诺会进入共同历史，并改变未来的关系、认知和选择。用户不能在一次交流中影响人物，却在下一次见面时面对一个完全重置的对象。

### 5.8 可观察、可追溯

用户需要知道世界发生了什么，也需要在重要时刻理解为什么。世界应能区分可观察的事实、居民的主观解释、构造者设定和系统推断，而不是用一段事后生成的理由掩盖矛盾。

### 5.9 分叉完整

平行宇宙在 Fork 之前拥有完全相同的过去；在 Fork 之后，各自的事件、记忆和状态独立发展。任何宇宙都不能把另一个宇宙的经历误认为自己的事实。

### 5.10 惊喜来自涌现，而不是随意

好的世界应当同时满足两件事：结果不是用户一眼就能预测的，但回看时又能理解它是怎样发生的。惊喜应来自多个角色、规则和条件的相互作用，而不是为了戏剧性凭空制造转折。

## 6. 用户如何与世界相处

Possibility 允许用户在三种位置之间明确切换。三种位置拥有不同的权力，也承担不同的责任。

### 观察者

观察者不直接改变世界。他可以查看世界时间、地点、居民状态、公开事件和已经显现的后果，也可以选择关注某个人、地点或问题。

观察者看到的不是所有居民的全知视角。必要时，产品应明确哪些内容是世界事实、哪些是特定人物的认知、哪些是为构造者提供的解释。

### 在场者

在场者以 Presence 进入某个 Universe。他存在于具体时间和地点，能够被居民看见、记住和评价，也受到同样的世界规则约束。

在场者可以交谈、行动、建立关系、作出承诺、传递信息和承担后果，但不能直接改写他人的内心或指定他人的决定。

### 构造者

构造者定义世界、居民和规则，控制观察范围，创建 Checkpoint 和 Fork，也可以对环境施加 Intervention。

构造者改变的是条件，而不是强制结果。例如，构造者可以安排两个人在同一场活动中相遇，但他们是否信任彼此，应由各自的处境和行动决定。

这三种身份可以属于同一个用户，但每次操作都应清楚表达用户当前是在观察、参与，还是改造世界。

## 7. 实时交流是世界行为

与居民交流不是附着在世界旁边的 Chat 功能，而是世界内真实发生的行为。

一次可信的交流应当具备以下性质：

- 它发生在某个 Universe 的具体时间和情境中。
- 交流渠道受世界条件约束，例如当面、电话、书信或其他世界内方式。
- 对方可能忙碌、睡眠、无法联系、不愿回应，或者只能获得不完整的信息。
- 回应来自对方当前的知识、关系、情绪、目标和近期经历，而不只是静态人设。
- 交流消耗世界时间，并可能影响之后的计划和他人。
- 谈话内容成为参与者的共同经历，但不会自动成为全世界都知道的事实。
- 同一个居民在不同 Universe 中可以因为经历不同而作出不同回应。

判断交流是否真正属于世界，有一个简单标准：即使不再展示对话文本，这次交流仍然应该在世界状态和未来行为中留下痕迹。

## 8. 开放世界意味着什么

开放不是地图无限大，也不是用户可以无条件做到任何事情。

开放意味着用户不必从一组预先写好的按钮中选择行为。他可以用自然语言表达意图，尝试开发者没有逐条设计过的行动；世界负责在自身规则、当前状态和用户能力范围内理解、回应或拒绝。

因此，合理的结果可以是成功、部分成功、失败、误解、延迟或产生意外后果。世界不为了顺从用户而放弃自己的规则。

世界在不同距离上可以呈现不同程度的细节：远处是概括的生活，用户关注的地点拥有更丰富的状态，用户亲自进入的场景可以被细致经历。无论细节程度如何变化，事实和因果不能互相矛盾。

## 9. Fork 是第一等能力

Fork 不是撤销按钮，也不只是生成另一个故事结局。它是创建平行宇宙的基本动作。

### 9.1 共同过去不可变

新 Universe 必须准确继承分叉点之前的世界状态、人物记忆、关系和历史。共同过去不应为了适配后来的故事而被悄悄重写。

### 9.2 改变必须明确

每次 Fork 都应能够说明从哪里分叉、主动改变了什么、哪些条件计划保持一致。默认鼓励一次只改变一个主要变量，从而让后续差异更容易理解；复杂改变仍然可以存在，但必须被明确记录。

### 9.3 未来彼此独立

Fork 之后，各个 Universe 独立运行。它们可以拥有不同的人物状态、关系、信息和事件，不能共享分叉后的记忆。

### 9.4 平行宇宙可以被再次进入

用户不只是观看一段推演结果，而可以进入任何仍然存在的 Universe，与其中已经被经历改变的居民继续交流和行动。

### 9.5 比较不是因果证明

产品可以展示多个 Universe 的状态和历史如何分化，也可以帮助用户追踪可能的影响链，但不能把一次生成式对照宣称为科学实验、现实预测或确定的因果结论。

## 10. Possibility 的核心循环

```text
CREATE → RUN → OBSERVE → ENTER → ACT → FORK → COMPARE → RETURN
```

### Create

创造世界、居民、规则与初始条件。

### Run

让世界在规则和居民行动中产生变化。

### Observe

查看当前状态、重要事件、关系变化和正在形成的问题。

### Enter

以世界内身份来到某个地点和时刻。

### Act

交流、行动、承诺，或者以构造者身份改变一个条件。

### Fork

从有意义的 Checkpoint 创建另一个 Universe。

### Compare

观察各个 Universe 的状态、历史和关系如何分化。

### Return

回到任意一个 Universe，面对已经形成的后果，继续生活或再次分叉。

这个循环没有预设终局。用户创造的不是一次性内容，而是一组可以反复进入的可能世界。

## 11. 世界应当如何被感知

产品应该帮助用户建立对世界的空间感、时间感和因果感，而不是只展示不断增长的文字流。

用户最终应当能够回答：

- 现在是什么时候？世界以什么速度变化？
- 我在哪里？其他人在哪里？从这里能到哪里？
- 现在正在发生什么？哪些事情只是传闻？
- 谁知道什么？信息是怎样传到这里的？
- 哪些关系、承诺和矛盾仍然没有结束？
- 某次行动改变了哪些状态？
- 为什么这个人作出了这个选择？依据是什么？
- 当前 Universe 从哪里 Fork 出来？它与其他宇宙有什么差异？
- 如果我现在进入，我能做什么，又会受到什么限制？

地图、事件流、人物视角、关系图、时间线、章节和对话都可以成为答案的一部分，但任何单一视图都不等于世界。

## 12. 世界创建的愿景

创建世界应该允许不同程度的表达，而不是要求所有用户从复杂编辑器开始。

用户可以只提供一句话，让一个最小但完整的世界开始存在；也可以逐步补充地点、历史、居民、组织、资源、规则和初始矛盾。系统应当把推断与用户明确给出的设定区分开，并允许用户检查和修正。

世界模板、人物素材和规则可以复用，但每个 Universe 的经历属于自己。创建过程的目标不是填写尽可能多的字段，而是形成足以产生连续行动和真实后果的初始条件。

我们优先追求“小而可信”，而不是“大而空洞”。一个拥有少数地点和居民、但能够保持因果与记忆一致的世界，比一个看似无限却不断自相矛盾的宇宙更接近愿景。

## 13. 产品语言

产品语言应始终强化“世界与可能性”，而不是暴露底层 AI 机制。

推荐使用：

- 世界、宇宙、居民、在场身份
- 当前状态、共同历史、世界时间
- 观察、进入、行动、改变条件
- Checkpoint、Fork、平行宇宙、比较
- 已知、推断、未知、传闻

谨慎使用：

- Agent、Prompt、Context、Token、调用次数
- 绝对真实、本人、复活、预测、注定
- “AI 认为某人一定会……”

模型、记忆系统和运行机制是实现世界的手段，不是用户进入 Possibility 的理由。

## 14. 这不是什么

### 不是角色聊天集合

居民的意义来自共同世界、相互关系和持续历史，而不是各自独立的人设窗口。

### 不是故事生成器

故事可以从世界中产生，但世界状态不能为了写出更戏剧化的段落而随意改变。叙述服务于世界，而不是世界服务于一篇即时生成的故事。

### 不是全能愿望机器

用户可以尝试开放行动，但世界拥有边界，居民拥有自主性。失败、拒绝和代价是可信世界的一部分。

### 不是现实预测器

平行宇宙展示的是在设定和模型条件下形成的 plausible possibility，不是对现实人物、人生选择或社会事件的确定预测。

### 不是对真人意识的复制

基于现实人物创建的居民始终是 Version，是受资料和设定限制的模拟，不是本人、意识上传或真实思想的延续。

### 不是预设任务驱动的传统游戏

Possibility 可以包含目标、挑战和故事，但不要求所有世界围绕固定关卡、胜负或主线任务组织。用户也可以把它当作观察场、创作空间或可能性实验室。

## 15. 信任与伦理边界

越真实的世界越需要明确边界。可信不是让用户忘记这是模拟，而是让模拟诚实地遵守自己的事实，并清楚表达未知与推断。

- 现实人物的 Version 必须明确标识为模拟，不代表本人意见。
- 用户提供的事实、系统推断和未知内容应可区分、可校正、可追溯。
- 第三方的聊天、声音、影像、邮件和私人资料不能因为被用于“创造世界”就失去隐私边界。
- 高相似度声音、形象或身份表现需要独立的授权与保护。
- 产品不能把生成式平行宇宙包装成现实预测、因果证明或精神意义上的真实存在。
- 用户应能删除、导出和管理自己创建的世界及资料。
- 与逝者、未成年人、亲密关系对象和其他敏感身份有关的模拟，需要比普通虚构人物更严格的产品规则。
- 居民的自主性不应用来伪装系统错误；产品必须能够承认信息不足、不确定和无法判断。

## 16. 产品原则

1. **世界优先于人物窗口。** 人物属于世界，对话属于历史。
2. **状态优先于叙述。** 先有发生了什么，再决定如何讲述。
3. **因果优先于戏剧性。** 宁可平静但可信，不要精彩却无来由。
4. **自主优先于顺从。** 居民是参与者，不是用户愿望的执行器。
5. **交流必须有处境。** 每次对话都发生在具体时空、关系和信息范围内。
6. **Fork 是第一等对象。** 平行宇宙不是结果页面，而是可以继续进入和生活的世界。
7. **共同过去不可篡改。** 修正错误必须被看见，不能为了连贯悄悄重写历史。
8. **事实、观点与推断分离。** 世界事实不等于人物认知，也不等于系统解释。
9. **开放不等于无约束。** 能尝试未预设的行为，也必须接受世界规则产生的限制。
10. **小而可信优先于大而空洞。** 世界规模服从一致性和可理解性。
11. **复杂度逐步展开。** 一句话可以开始，深度控制在需要时出现。
12. **技术退到幕后。** 用户面对的是世界，不是模型调用面板。

## 17. 如何判断愿景成立

Possibility 成立，不是因为它能持续生成大量事件，而是因为用户开始把它当作一个地方。

我们期待看到这些迹象：

- 用户会问“那里现在怎么样了”，而不是“又生成了什么内容”。
- 用户能够根据人物与世界规则形成预期，同时仍被合理的涌现结果惊讶。
- 用户的一次交流会在之后的生活中留下可以辨认的影响。
- 用户可以离开一段时间，再回来理解期间发生了什么以及为什么发生。
- 同一个居民在不同 Universe 中因为经历不同而自然地成为不同版本。
- 用户能够指出两个宇宙共享的过去、明确的分叉条件和逐渐扩大的差异。
- 世界在被反复追问、进入和观察时仍能保持时间、空间、知识和关系一致。
- 用户愿意返回某个 Universe，不是为了消费新文本，而是因为那里存在尚未完成的关系、问题、承诺或可能性。

最终，我们希望用户拥有的感受不是“AI 为我写了一段故事”，而是：

> 我创造了一个世界。它按照自己的规则生活。我进入过那里，也改变过它。现在，同一个过去已经通向了不止一个未来。
