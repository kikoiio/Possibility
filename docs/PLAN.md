# Possibility 当前产品收敛计划

本计划吸收两轮 2026-10-08 深度黑盒体验、其第二轮操作证据以及仓库当前实现，作为后续开发和验收的唯一工作入口。

目标是先把一条小而完整的世界体验做可靠：

```text
创建人物 → 创建世界 → 生成有效场景 → 进入并探索 → 交谈/传话
→ 离开并等待 → 回来查看一致回顾 → 保存/恢复 → 创建 Fork → 比较 → 刷新后继续
```

产品愿景、学习型世界模型和工具候选继续保留，但在这条主线稳定前不扩大范围。

## 当前判断

仓库已经有世界引擎、人物自主体、记忆流、访客副本、场景检查、2D/3D 表现、分叉和比较等基础实现。当前阻塞来自真实入口之间的断裂：

1. 世界生成后仍可能包含用户无法修复的场景问题。
2. 2D、3D、室内视图可能展示不同世界、空间或时间线。
3. 事实已经写入，但生活回顾、来源面板和电话回答没有保持一致。
4. 认领、分叉、场景修复和 pane 切换失败后缺少可靠恢复路径。
5. 窄屏、弹窗和内部字段降低了核心操作的可达性和可理解性。

自动化测试、固定 fixture 或独立 2D 样板只能证明局部能力。最终完成标准必须包含当前产品入口的真实 API/UI 路径和可复查证据。

## 当前文档如何进入本计划

- `README.md` 作为实现边界：当前技术栈是 React/Vite + Hono/Worker + D1/Drizzle；已有世界引擎、人物自主体、记忆、电话、注入、Fork、比较、Voxel 和 native2d。阶段 0 以这些真实入口和服务为准，不把愿景能力当成已实现能力。
- 产品愿景材料归并为验收原则：世界优先，区分观察者、在场者和构造者；CREATE → RUN → OBSERVE → ENTER → ACT → FORK → COMPARE → RETURN 这条循环必须体现持续存在、时空连续、局部知识、因果一致、居民自主、后果持久和分叉隔离。
- 两轮 2026-10-08 体验材料及其操作证据归并为当前缺陷和回归基线，形成下面的 BB-01 至 BB-18 矩阵。阶段 0 重新生成当前版本证据，不依赖历史截图或已删除材料。
- 原型材料中的世界画布/管理抽屉、居民状态/对话卡和左右宇宙比较图作为交互方向，分别落到阶段 1C、阶段 2C、阶段 3A/3B；它们是形态参考，不替代真实世界状态和 API 验收。
- `world-model/README.md` 的学习型世界模型暂缓到核心闭环稳定后。未来只能输出带不确定性的候选变化，由世界引擎校验、提交并按权限投影，不能直接写成事实。
- 工具候选材料中的 WFC、Rive、glTF-Transform、meshoptimizer、Recast 等保持为候选清单；当前继续使用现有 React/Pixi/Three.js 和确定性校验，等真实布局、资产体积或导航瓶颈出现后再逐项评估。

## 文档收敛边界

`docs/` 只保留四类入口：本计划、`README.md`、`world-model/` 讨论稿和 `spec_docs/` 规范目录。其余材料删除后，信息按以下位置承接：

- 两轮体验报告及截图/文本证据 → 本计划的问题矩阵、阶段 0 基线和发布前验收清单。
- 产品愿景 → 本计划的核心闭环、跨模块契约、完成定义和“暂缓事项”边界。
- 原型图 → 阶段 1C、阶段 2C、阶段 3A/3B 的交互目标。
- 开源工具箱 → “暂缓事项”中的候选技术，只有出现对应性能或资产瓶颈才重新评估。

删除源材料不会删除待办事项；后续若需要新的证据，应写入阶段 0/发布验收记录或对应的 `spec_docs/` 规范，而不是恢复历史体验文件。

## 阶段 0：冻结基线和证据

产出一份当前版本的验收矩阵，不修改业务代码。

1. 固定当前 `main`、本地数据库、演示世界、访客副本和测试账号；凭证只保存在本地，不写入仓库。
2. 确认运行中的 web bundle、API 和数据库迁移与当前代码一致，排除旧服务或旧缓存造成的假象。
3. 复测 BB-01 至 BB-18；同时复测第一份报告的注册后自动认领、访客时区、室内 3D 和时间线显示。
4. 记录每项的入口、身份、world/timeline/space、模拟时刻、响应状态、最终页面和截图/文本证据。
5. 冻结以下跨模块契约：
   - 世界、时间线、空间、表现和模拟时刻必须由同一当前上下文驱动。
   - 认领和分叉请求保持幂等；失败时保留可恢复状态。
   - 访客 UI 的能力判断先于可写控件渲染，服务端权限仍是最终防线。
   - 事实、居民知识、回顾、来源和电话必须使用同一来源链。
   - 用户文案不能直接输出内部 ID、枚举或版本号。

阶段 0 未完成前，不开始大范围重构，也不把历史成功截图当作当前通过。

## 阶段 1：恢复核心闭环

### 1A：生成和场景可用性

范围：世界生成、场景生成/规范化、兼容检查、修复预览和编辑门禁。

实施顺序：

1. 找出生成文档经过的每一层校验，确保保存前使用与用户“场景检查”相同的最终规则。
2. 对无效入口、缺失空间、道路断裂和室内不可读分别返回可执行建议。
3. 若模型多次失败，提供最小合法场景作为可进入结果，或提供真正能够提交的修复草稿。
4. 修复成功前不得把普通 AI 编辑永久锁死；修复不可行时要给出明确恢复路径。
5. 用新世界而不是只用固定演示世界验证：生成、检查、修复、编辑、刷新和重新进入必须连续完成。

验收：新世界不会在首次进入时出现无法提交的兼容问题；失败结果不会只显示内部术语；场景编辑至少有一条完整成功路径。

### 1B：访客保存和恢复

范围：`web/src/pages/Login.tsx`、`DemoLanding.tsx`、`web/src/api/client.ts`、demo session/claim 服务。

实施顺序：

1. 覆盖 `guest token → claimDemo → auth token → claim → saved world`。
2. 分别验证首次正确登录、注册后自动认领、输错密码后正确重试、网络失败后重试、重复点击和已认领冲突。
3. 只有认领成功才清理 guest token、pending 标记和 request id。
4. 失败时保留原访客副本和“重试保存”入口，不跳到空世界列表。

验收：注册后不需要重新寻找访客副本；输错密码后重新输入正确密码仍能保存同一个副本；不会生成第二份副本。

### 1C：真实世界投影一致

范围：`WorldCanvasPage`、`ComparisonHost`、2D source/projection、Voxel scene loading、timeline/space query。

1. 所有 pane 读取后断言 `worldId`、`timelineId`、space、identity、simNow 和 presentation。
2. 2D 不再使用固定庄园作为未知世界或室内空间的静默 fallback。
3. 不支持某种表现时显示原因和可用替代方式。
4. 切换 timeline、空间、2D/3D 和比较模式时，取消旧请求，避免旧响应覆盖新上下文。

验收：同一世界的外景、室内、2D、3D 和比较视图指向同一空间事实；刷新后上下文仍一致。

## 阶段 2：修复事实、时间和交谈一致性

### 2A：传话和记忆来源链

范围：传话写入、居民知识、生活回顾、来源详情、电话查询和相关事件投影。

1. 为一次传话建立可追溯的事实/知识来源标识。
2. 区分“已听到”“相信”“已证实”和“未知”。
3. 生活回顾和电话必须读取居民实际拥有的知识，不能重新生成一个与来源冲突的结论。
4. 加入跨模块回归：发送传话 → 查看来源 → 离开期间回顾 → 电话询问。

验收：居民可以说“我听过，但还不确定”，不能说“你从未告诉过我”。

### 2B：时间线和状态语义

1. 顶部时钟、pane 时钟、分叉起始时间和生活回顾都使用同一时间线及时区。
2. 相对时间词必须基于事件的模拟时刻计算。
3. 首次到场不显示“上次离开后”；只有存在有效上次访问记录时才显示回顾。
4. active、paused、archived 使用不同标题、说明和按钮名称。

### 2C：人物生成和无人地点

1. 人物创建输入、模型补写、用户确认分别标记为确知、推断和未知。
2. 无人地点交谈返回可理解的确定结果，不留下长期待定状态。
3. 电话、当面和访客交谈继续保持各自的渠道和位置语义。

## 阶段 3：Fork、比较和窄屏体验

### 3A：Fork 工作流

1. 分叉弹窗使用视口内的 Portal、滚动容器和明确的最大高度。
2. 源状态变化后提供“刷新当前状态并重新起草”，保留用户输入。
3. 暂停/运行限制在表单开始时说明。
4. 人物页入口直接打开分叉流程。
5. 显示分支名称、假设和起始时刻，不显示内部 ID。

### 3B：比较视图

1. 关闭右 pane 后保持单视图状态。
2. 左右 pane 各自保存 world、timeline、presentation 和相机状态。
3. 只有同一世界且表现类型兼容时才允许相机联动。
4. 一侧失败、重试或取消不能重置另一侧。

### 3C：窄屏布局

目标视口至少包括 `485×724`、`390×844` 和桌面双栏。

1. 单视口使用全部可用宽度。
2. 比较模式让第二个 pane 有明确的滚动终点或切换入口。
3. 顶部工具条、设置、分叉和人物面板不遮住主要画布和按钮。
4. 关键操作同时支持鼠标、触摸和键盘焦点。

## 阶段 4：统一显示层和发布门槛

1. 建立统一的 timeline、person、location、world 状态格式化函数，并搜索所有下拉项、标题、比较卡片和原生 2D 入口。
2. 移除 `timeline-*`、UUID、`owner/guest`、`single/left/right`、资产名和工程字段的直接展示。
3. 访客时区控件根据能力渲染为只读。
4. 所有错误都必须说明当前状态、是否写入成功、是否可以重试以及下一步是什么。

发布前必须串行完成：

- 新世界生成和修复成功路径；
- 注册认领、错误密码恢复和重复提交；
- 传话到回顾到电话的一致性；
- 2D/3D/室内和同/跨时间线比较；
- Fork 过期刷新、暂停限制和关闭 pane；
- `485×724`、`390×844` 和桌面视口；
- 暂停、归档、恢复和刷新；
- 第一视角实际移动、真实 SSE/model 交互、权限组合和模型失败恢复。

## 验证和资源规则

- 每个问题至少有一个定向 API/单测证据和一个当前入口的 UI/浏览器证据。
- 类型检查或固定 fixture 通过不能替代真实用户路径。
- 生成结果必须记录输入、模型调用次数、校验结果和最终保存状态。
- 只读 GET、失败重试和页面读取不得产生额外世界事实。
- 完整构建、浏览器和 GUI 验证错峰执行；本机执行前检查 `MemAvailable`、`vmstat`、memory PSI 和 `/tmp` 余量。
- 优先使用已授权的云端 CI 执行重型构建和浏览器矩阵；涉及私有代码、账号或数据时先确认权限边界。
- 本机 GUI 一次只启动一个实例，结束后确认临时进程退出。

## 暂缓事项

以下内容保留在文档中，但等阶段 1–4 的核心闭环稳定后再启动：

- 学习型世界模型训练和在线推理；
- WFC、Rive、Recast、glTF 优化、纹理压缩等工具引入；
- 更大地图、更多居民和复杂社会模拟；
- 新的 Fork 类型和更复杂的自动化行动。

世界模型未来必须从一个窄领域开始，先记录结构化状态转移和可解释基线，再离线评估，最后作为受规则约束的候选变化接入世界引擎。模型永远不能直接成为权威事实来源。

## 完成定义

只有当下面这条路径在当前版本中可以重复完成，才进入下一轮产品扩展：

```text
创建人物 → 创建世界 → 得到合法场景 → 进入 → 交谈/传话
→ 离开并等待 → 回来看到一致事实和回顾
→ 保存/恢复 → Fork → 比较 → 刷新后仍保持同一上下文
```

验收结果必须逐项记录为“通过、失败或未验证”，并附当前版本、身份、world/timeline/space、操作路径和证据位置。
