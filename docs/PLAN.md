## 本轮目标与状态

目标仍是一条完整体验：用自然语言创建湖边木屋和修表老人，检查可进入的空间，局部修改窗户及屋顶，保留其余内容；撤销、刷新和重启后可恢复；确认进入后观察至少一次人物行动。木屋只是验收样例，不是固定产品模板。

**反馈、恢复、保存、空间检查和等待测量已实施，真实创建至人物行动已走通；建造质量尚未通过，不能将体验验收整体标为完成。**

## 验证证据

GitHub Actions 在独立验证分支 `prototype/review-creation-experience-20261029` 执行完整离线检查、创建／运行浏览器流程、体素浏览器流程及失败恢复流程，使用合成模型。最新通过运行 `40931477484` 包含 **132 个 Node 测试、282/282 项环境检查、40/40 条模型客户端观察**，并通过所有浏览器流程；体素报告还确认精确部件换色、室内查看、刷新／重启和确认进入保持同一场景快照。该验证不读取私有模型配置或存档。

本机只运行轻量定向回归，以及依赖私有模型配置的真实交互。新增回归先复现了空命令误成功、格式拒绝、坏档被覆盖、取消时保存乐观成功、已取消检查点仍生成草稿、最终校验后无法修复检查点等问题，再验证修复。完整结果不能代替真实模型与画面判断。

加载和资源仅有小场景样本；requestAnimationFrame 回调不是 GPU 帧率，没有大型世界或长期运行性能证明。具体环境、耗时与失败见体验记录，不在多份文档重复维护。

## 尚未通过项与下一顺序

1. **空间与部件复验。** 已实现精确归属、部件换色和有限空间诊断；用真实模型重新检查建造和局部修复是否准确采用这些能力。旧对象没有精确归属时明确拒绝猜测换色，需作者明确重建部件。检查只覆盖单层矩形建筑，不能代替多角度外观判断。
2. **短步骤生成。** 让一次请求只做可检查的有限变化，避免一条长命令链反复因格式失败。继续保留原子提交、版本检查和显式重试；评估真实模型能否稳定创建及准确修改，而非只看合法命令数量。
3. **观感与持续行为。** 主流程已完成确认、人物行动与修理进度变化；下一次应在质量合格的场景中复验，再调整构图、尺度、室内观察与动态反馈。有其他已授权模型时，按相同任务和条件对比。大场景性能另行测量。
