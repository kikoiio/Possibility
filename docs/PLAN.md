## 当前目标：对话建造可持续修改的 3D 世界

用户通过自然对话慢慢构思世界，可以随时要求建造、查看、修改和撤销。画面要有吸引力，建造结果应尽可能不依赖某个模型的专有接口。用户不需要安装 Blender、CUDA 或大型本地模型；首版入口仍是网页。

先以体素世界为建造基础，借鉴 Minecraft 的区块和方块表示、WorldEdit 的批量编辑、Mineflayer 的观察／行动接口，以及 Voyager 的执行反馈与可复用技能。系统自主实现适合 Wispiva 的基础设施，Luanti 社会实验提供证据与经验，不自动成为网页运行时依赖。Three.js 是当前浏览器渲染起点；保留以后扩展其他对象表现形式的可能，不宣称纯方块已经是所有题材的最优解。

首条贯通场景：用户通过多轮对话创建湖边小屋，查看 3D 场景，将窗户调整为朝向湖并抬高屋顶，保留未要求改动的内容；撤销、刷新和重启后可检查或恢复结果。该场景是验收样例，不是把产品固定为木屋模板。

## 分阶段实施

### 1. 定义共享建造契约

- 定义世界坐标与单位、区块和材料注册表，明确权威方块状态与世界 revision。未加载、空方块和未知材料要区分。
- 定义稳定对象及部件 ID、边界、归属与关系，使“木屋的屋顶”可查询和修改；明确直接改块时对象记录如何更新或失效，避免对象描述与方块事实矛盾。
- 定义查询、编辑提议、检查结果、提交和错误形状；批量操作以固定基准执行，过期基准拒绝或重验。更改、对象记录、版本与持久化须一致提交，失败不留下半次修改。
- 保留对话中用户确认、模型建议和未确定事项的区别；场景中已经提交的事实与尚未执行的建议分开。工具描述不绑定某家模型的函数调用格式。
- **完成证据**：契约样例能表达创建对象、局部修改、失败和撤销；测试覆盖越界、未知材料、未加载区域、冲突基准、原子失败和对象一致性。评估并复用已有 `voxel-building.mjs` 时不得把其内存变更记录当作已完成事务。

### 2. 建立体素世界与可恢复编辑

- 实现区块存取、材料、区域查询及有限规模的批量变更；编辑记录保留修改前后信息和基准 revision，支持撤销／恢复与审查。
- 将状态保存到本机，定义新世界、创建草稿和确认后世界的生命周期；刷新或进程重启后从已保存结果恢复，不重新调用模型生成历史。确认、切换或新建世界不能覆盖已有存档。
- 先让确定性工具操作产生真实世界变化，再连接模型；避免直接运行模型生成的任意代码。对操作规模、内存及持久化失败给出明确结果。
- **完成证据**：创建、修改、撤销、重启恢复和失败不改变世界均有定向检查；对跨区块和对象关联进行验证。容量、崩溃耐久性和并发能力只在实测范围内表述。

### 3. 建立实时 3D 与视觉底座

- 使用 Three.js 将区块中可见方块面合并为可渲染网格；区块边界读取相邻数据，局部修改只更新受影响区块与必要邻区。区块和材质复用、异步构建及旧任务结果的版本检查按实际规模实施。
- 画面消费同一份已提交世界状态；预览与正式世界的区别明确，不让渲染器产生第二份权威事实。提供取景、环视、缩放及错误反馈。
- 建立协调的方块色板、纹理、地形、光照和镜头；必要时允许不同造型部件，但先验证所选风格。视觉吸引力由作者实际查看判断，几何合法不等于好看。
- **完成证据**：跨区块修改前后画面与状态一致、刷新恢复、多角度截图，以及作者对成品的评价；在明确设备、场景规模与分辨率下记录加载、帧时间和内存／显存。浏览器和截图属于重型验证，按资源与授权规则安排。

### 4. 接入建造工具和多轮对话

- 从查询、填充／清空、替换开始，逐步增加复制／旋转和门窗、屋顶等可组合操作；高层工具由可检查的基础操作实现，避免只能调用固定成品模板。
- 复用现有模型配置与调用路径，将同一套工具语义适配为模型可用的格式；工具执行由程序验证，返回实际修改、诊断和稳定对象 ID。必要时提供结构化场景观察，支持视觉输入的模型可另用截图。
- 创建页支持边聊天边提出建造／修改，在完成后更新同一个场景；支持继续聊天、局部修改、明确失败和撤销。模型输出或失败不能冒充已提交的世界变化。
- 与现有草稿、确认和世界模拟的边界已经接通：确认时把同一份体素快照写入 `genesis.voxel`，并写入稳定的地点／人物语义绑定；进入世界、刷新、服务重启、归档和重新打开都继续消费该快照，世界页不会切换到另一套自动生成的体素场景。
- **完成证据**：合成模型测试正常、无效工具、取消、中断、过期结果和保存恢复；生命周期测试覆盖“对话建造 → 确认进入 → 重启 → 归档 → 重新打开”。真实模型跨模型比较仍需在配置模型后进行，不能用单次合成调用代替。

### 5. 跨模型与体验验收

- 使用相同场景要求、工具能力、预算、初始状态、修改轮次和记录方式，对多个已配置的模型分别运行；记录每次调用、耗时、失败、修改准确性、保留未修改内容和作者审美评价。提供模型能力限制与差异，不用单次成功证明模型无关。
- 在相同条件下检查对象身份、空间结构和实际画面；涉及语义或美术的判断由用户结合多视角查看，截图不能替代碰撞和可通行检查。比较生成质量与沟通体验，也记录未达到要求的尝试。
- 以证据决定优先改进工具、视觉底座还是模型适配。通过一次小场景验收不代表任意世界、长时间运行或大型地图已经可靠。

## 借鉴边界与后续事项

- Minecraft／WorldEdit 的区域编辑、Mineflayer 的接口、Voyager 的反馈和技能可借鉴；其 Minecraft 接口不能直接作为 Luanti 或 Wispiva 的实现。复用外部代码、素材或插件前分别核对来源、许可证及版本，不复制无许可代码。
- 真实模型长素材体验、信息边界、空间认知、长期记忆、预测失效、分岔和社会实验仍重要，但不与本阶段建造工作混作同一个验收目标；维持已有行为，发现相关缺陷时记录并按影响处理。
- 社会实验的容量、真实模型、重置及互动证据继续由实验工作区独立维护；不覆盖其未提交工作，也不把实验代码整体合入原型。

## 执行与资源约束

- 重型构建、依赖安装、大规模测试、浏览器自动化和 GUI 验收优先使用云端免费资源。使用具体云服务前告知用途、权限并取得许可；既有授权仅按其明确范围使用，不擅自上传私有代码、存档、素材或密钥。云端不覆盖的场景才按本机规则兜底。
- 本机需要重型操作时，检查 MemAvailable、换页速率、memory PSI、cgroup 限额和 `/tmp` 配额；GUI 另遵守最少 4 GiB 可用内存、低 PSI、单实例和 GPU 约束。大缓存与临时文件改道项目根文件系统；验证结束清理本任务的临时进程。
- 开发和定向验证可以并行，但涉及同一契约或文件的变更须协调；重型任务由主 agent 集中安排。资源不足或授权缺失时如实记录未完成的验证。
