## 本轮目标与状态

目标仍是一条完整体验：用自然语言创建湖边木屋和修表老人，检查可进入的空间，局部修改窗户及屋顶，保留其余内容；撤销、刷新和重启后可恢复；确认进入后观察至少一次人物行动。木屋只是验收样例，不是固定产品模板。

**反馈、恢复、保存和等待测量已实施；真实建造质量尚未通过，不能将本计划整体标为完成。**

## 验证证据

GitHub Actions 在独立验证分支 `prototype/review-creation-experience-20261029` 执行完整离线检查、创建／运行浏览器流程、体素浏览器流程及失败恢复流程，使用合成模型。`40924924276` 已通过，覆盖反馈、显式重试、取消、刷新、重启、讨论隔离、移动端溢出及截图；后续代码以更新的通过记录为准。

本机只运行轻量定向回归，以及依赖私有模型配置的真实交互。新增回归先复现了空命令误成功、格式拒绝、坏档被覆盖、取消时保存乐观成功、已取消检查点仍生成草稿、最终校验后无法修复检查点等问题，再验证修复。完整结果不能代替真实模型与画面判断。

加载和资源仅有小场景样本；requestAnimationFrame 回调不是 GPU 帧率，没有大型世界或长期运行性能证明。具体环境、耗时与失败见体验记录，不在多份文档重复维护。

## 尚未通过项与下一顺序

1. **空间与部件。** 给修改部件建立比包围盒更精确的方块归属；在提交前检查建筑净空、门洞与外界连通、窗嵌墙、屋顶覆盖和水面相交。诊断应指导局部修复，保留对象身份和未修改部件，不能猜测作者意图或套用固定成品。
2. **短步骤生成。** 让一次请求只做可检查的有限变化，避免一条长命令链反复因格式失败。继续保留原子提交、版本检查和显式重试；评估真实模型能否稳定创建及准确修改，而非只看合法命令数量。
3. **完整运行与观感。** 在质量合格的场景中完成确认、人物行动和有意义的修理进度；再调整构图、尺度、室内观察与动态反馈。有其他已授权模型时，按相同任务和条件对比。大场景性能另行测量。

## 范围与资源

本轮文档集中于 `docs/`，保留意图、当前架构、计划、一次体验记录和示例素材；不维护重复 research 或其他分支的实验材料。长期记忆、反思、分岔、复杂社会及大型世界仍在本轮之外。

重型构建、全量回归和浏览器自动化优先使用已获本次授权的 GitHub Actions 免费资源，不上传密钥、私有配置、存档或原始审计。本机复用现有浏览器，仅保留隔离体验服务；按 MemAvailable、换页与 memory PSI 控制负载，遵守 `/tmp` 配额与进程归属规则。
