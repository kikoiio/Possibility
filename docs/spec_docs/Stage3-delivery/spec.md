## 背景

`docs/DEVELOPMENT_ARRANGEMENT.md` 将阶段三定义为正式双入口集成、交付验证和用户评估。前两阶段负责稳定创建、编辑、会话与 2D 产品能力；阶段三交付验证依赖这些能力和验收门槛。

该安排原先将 P3 定义为“开放与投票”。本阶段按用户确认调整为 P1 双入口集成、P2 交付验证和内部 QA；公开评估与投票暂列为后续事项。

规格编制时参考的是本机 main worktree 中 2026-10-05 版本的 `docs/DEVELOPMENT_ARRANGEMENT.md`（该文件声明代码基线为 `dbba8b6`）。当前管理 worktree 为 `phase3`，基线提交为 `07dcdb4`。main worktree 的未提交改动不属于本规格基线，也不自动复制到 phase3 子 worktree。

## 目标

- 在同一世界和身份下集成 2D/3D 两种入口，切换时保留时间线、历史和用户状态。
- 对完成前两阶段的核心旅程进行跨空间、身份、设备、网络和恢复场景的交付验证，留下可复查证据。
- 由当前 `phase3` worktree 作为 Orca 协调入口；子 worktree 从 `phase3` 创建，任务完成后汇入 `phase3`。
- 前置门槛未通过前，只完成规格与无依赖准备；通过后按任务 DAG 并行派发集成任务，并集中安排重型验证。

## 功能需求

- F1: 用户可在同一世界的 2D 与 3D 表现间切换；切换保留 `worldId`、`timelineId`、身份和历史，不隐式创建世界或推进时间。分屏可并排呈现当前身份有权访问的任意两组世界/时间线，每侧独立选择 2D 或 3D，允许 2D/2D、3D/3D 和混合表现；每侧使用自己的 world/timeline、时间和访问能力，一侧加载失败不影响另一侧。同一 `worldId` 且表现类型相同时，两条时间线可选相机联动；跨世界或混合表现时相机独立。
- F2: 系统在当前浏览器保存用户的表现偏好；相机状态按世界、时间线和表现分别恢复，不要求账号间同步。
- F3: 某世界不支持目标表现时，系统明确说明原因并提供可操作的替代入口。
- F4: 前置阶段通过后，交付验证覆盖单/多空间、2D/3D、分屏每侧的 2D/2D、3D/3D 与混合表现、同一或不同世界、owner/guest/readonly、桌面/窄屏/触屏、慢网/失败恢复，以及单视口/分屏的性能与资源释放；逐项记录环境、版本、路径、结果和限制。
- F5: 内部 QA 使用相同主题、人物、检查点、模型条件和核心任务对比两种表现；记录任务完成、错误、性能与回访检查结果，不开展面向用户的公开投票。
- F6: 当前 worktree 维护任务 DAG、依赖、文件所有权、验证证据和工作区状态；每个并行任务使用独立子 worktree，从 `phase3` 分支创建，完成后汇入 `phase3`。
- F7: 前两阶段的旅程验收未通过时，只调度不依赖其结果的准备任务；通过后再派发依赖公共契约和完整旅程的集成任务。
- F8: 轻量任务可并行；构建、浏览器和全量回归由协调者结合 MemAvailable、换页趋势、memory PSI 和 cgroup 限额安排并发，避免同时启动多套重型验证。

## 非功能需求

- N1: 切换表现后，世界、时间线、身份、历史和时间状态保持一致；分屏两侧的状态、权限、数据请求和失败相互隔离；加载失败或恢复时不丢失已提交状态，也不重复执行已提交操作。
- N2: 目标表现不可用或加载失败时，界面保留用户当前世界上下文，并给出明确原因和可用后续操作。
- N3: 对冷/热加载、单视口/分屏和视图切换记录耗时、性能与资源释放证据；先测当前基线，再确定量化门槛，不预设未经测量的数字。
- N4: 内部 QA 使用测试账号和测试世界；记录汇总完成率、错误、性能及回访结果，不记录 API 密钥或原始私人对话；不进行公开部署或外部用户投票。
- N5: 每个子任务有明确文件所有权、独立验证和汇合点；同一热点文件由单一负责人集成，迁移、公共类型、共享 fixture 和端口不发生未经协调的并发冲突。
- N6: 重型验证按实时可用内存、换页趋势、memory PSI 和任务自身内存限额排期；保留桌面余量，压力升高时降低并发或错峰，不能因 swap 使用率单项判断资源不足。

## 不做的事

- 本阶段不面向公开用户发布评估，也不收集公开投票；相关方案留待后续决策。
- 前置阶段验收门槛未通过时，不启动依赖性集成实现；当前只做规格和无依赖准备。
- 不把本阶段扩大为前两阶段所有缺陷的全面重写；只处理阻断双入口集成或交付验收的缺陷，其他问题单独排期。
- 不决定长期保留哪一种表现，也不删除 2D 或 3D 路线。
- 不实现完整历史空间回放、每条分支独立几何编辑，或任意 2D/3D 几何无损互转。
- 不新增多人协作、无限分支或大型社会模拟系统。
- 不修改或自动搬运 `main` worktree 当前未提交的改动；子 worktree 按已确认方案从 `phase3` 创建。
- 不进行公开部署或云端运行；若后续验收需要调用云端资源或外部账号权限，另行明确范围与权限后再执行。

## 验收标准

- AC1: 在支持两种表现的世界中切换 2D/3D，切换前后 `worldId`、`timelineId`、身份和历史一致；没有新建世界或意外推进时间。分屏能比较同一世界的两条时间线及当前身份有权访问的不同世界；左右各自选择 2D/3D，2D/2D、3D/3D 和混合组合均可工作。两侧各自显示时间与权限，一侧失败不影响另一侧。同一世界且同一表现类型时可选相机联动，跨世界或混合表现时相机独立。
- AC2: 重载或往返切换后，浏览器保存的表现偏好按约定恢复；相机按世界、时间线和表现分别恢复；目标表现缺失或加载失败时，当前世界上下文保留，并显示明确的替代操作。
- AC3: 有第一、二阶段完整旅程的验收证据后，才派发依赖集成任务；未通过时仅调度独立准备，并记录阻塞项。
- AC4: P2 所列空间、表现、身份、设备、网络、恢复、2D/3D 单视口、分屏的 2D/2D、3D/3D 和混合组合以及资源释放场景均有实际结果记录；同世界和不同世界分屏均覆盖左右身份/权限隔离、独立时间、相机联动边界和单侧失败恢复；每项记录版本、环境、操作路径、结果和限制。
- AC5: 同主题、人物、检查点、模型条件和任务下完成 2D/3D 对照；记录任务完成、错误、性能和回访结果，不涉及公开投票。
- AC6: 每个任务都有唯一负责人、依赖、文件边界、验证方式和结果证据；独立子 worktree 从 `phase3` 创建，完成后汇入 `phase3`，共享文件由协调者安排集成。
- AC7: 重型操作开始前有资源评估记录；并行度符合实时可用内存与压力状态，没有未经协调的多套重型验证同时争抢资源。
- AC8: 最终报告逐项说明通过、未通过或未验证，并附证据；公开用户评估和投票明确标为延期。

AC3 用于确认上游依赖已具备，不代替前两阶段自身的验收。
