# E1：变化发现、证据追溯与离开期间回顾 — 技术设计 Plan

## 架构概览

- **读取服务：** 扩展现有登录世界 `/return` 回顾读取路径，并增加按事件查看证据的只读接口。服务端统一校验世界所有者、当前时间线与模拟时刻，再聚合持久化事件、命令、事实、相关人物/地点和可用检查点；全程不调用模型、不写入世界事实。
- **证据重建：** 复用 `world-state/evidence` 的证据完整性及历史状态重建能力。对齐到具体时间点时，仅返回已有检查点或命令/事实可支持的字段，并附重建状态；不能重建时仍返回原始事件和缺口说明。
- **回顾与已读：** 保留现有 `worldVisits` 用户+时间线水位，用服务端有界事件页生成新变化摘要；已读接口校验水位属于当前时间线且未超过当前模拟时刻。来源明确的状态变更与约定变更按固定条件突出，其他事件照常列出。
- **呈现层：** 在现有回顾面板与事件列表上增加变化详情和证据展开，将记录事实、可能关联、未知分区展示；通过人物/地点可读名称导航。消息正文根据现有所有者权限返回，不出现在公共事件文案中。
- **继续探索：** 对有完整证据的事件时点提供历史查看或 F1 分叉入口，复用现有比较、历史重建和 F1 确认流程；无法验证的时点不提供可操作入口。

## 核心数据结构与接口

- **回顾响应：** 扩展现有 `ReturnBrief`，包含 `timelineId`、`simNow`、已读前后的事件游标、摘要、确定性突出原因、按时序分页的事件，以及现有约定与未读数量。事件仍只来自当前时间线且 `simTime <= simNow`；游标继续按用户+时间线保存。
- **事件证据详情：** 新增 `EventEvidenceDetail`：包含可读事件信息、可选来源命令、通过 `sourceCommandId` 确认关联的事实、人物/地点引用、事件时点、可重建状态及其证据版本/完整域。任何可选字段缺失时返回 `gaps[]`，不伪造关联。
- **知识与关联：** 详情单独携带观察者获准查看的当时知识记录；事件、事实与知识可通过明确来源关系标为“记录事实”。仅能由同时间/人物/地点等弱关系联系的记录属于“可能关联”，必须附来源和标签；没有规则支持的关联不返回。
- **检查点状态：** 使用 `versionAtTime` 与 `reconstructAt` 确认可重建性。结果区分完整、部分、不支持，并列出缺失域和原因；不能确认覆盖所选时点时，服务端不给历史查看或 fork 可用标记。
- **接口：** 在登录受保护的 life routes 扩展 `GET /worlds/:id/return`（有界游标/页大小），新增 `GET /worlds/:id/events/:eventId/evidence?timelineId=...`；已读仍走 `/return/seen`。事件详情和检查点只读。fork 从详情带 `timelineId + simTime + expectedSourceVersion` 调用 F1 现有入口。
- **持久化：** 复用 `events`、`worldCommands`、`worldFacts`、`universeRevisions`、分叉快照和 `worldVisits`；不新增表。对旧事件未保存的地点、命令或状态关联保持可空，并明确列出缺口。

## 模块设计

- **`api/src/life/routes.ts`：** 负责认证、世界所有者校验、当前时间线作用域、游标/页大小校验和 HTTP 响应；不直接拼接复杂证据规则。
- **新增 `api/src/life/evidence.ts`：** 提供回顾摘要查询与单事件证据聚合。按 event ID 和 timeline ID 精确定位；通过 `sourceCommandId` 找命令/事实，解析事件参与者与地点可读名称，生成缺口及固定高亮理由。弱关系只作为带来源的可能关联，不进入确定事实字段。
- **`api/src/world-state/reconstruct.ts`：** 复用 `versionAtTime`、`checkMoment`、`reconstructAt` 判断事件时点是否可重建；仅将已经验证的重建投影用于状态详情，不修改重建行为，也不因此写世界状态。
- **`api/src/life/compare.ts`：** 继续负责已有时间线差异比较；E1 只从有效检查点导航到既有比较/分叉 UI，不另造比较或因果算法。
- **Web API 层：** 在 `web/src/api/types.ts` 增加回顾分页、事件证据和重建状态类型，在 `web/src/api/client.ts` 增加证据详情读取方法并扩展回顾方法。
- **Web UI：** 扩展 `web/src/components/world/LifePanel.tsx` 显示摘要、重点事件和空状态；新增事件证据详情子组件展示记录、关联、未知及来源缺口；复用 `WorldCanvasPage` 的当前 timeline 上下文和 F1 分叉确认入口。
- **安全/兼容：** 所有新增 API 沿用 life routes 的 auth middleware 和 world owner scope。现有回顾中的约定操作和未读数原样保留；详情端点不输出无权限的私人正文。

## 模块交互

1. **打开回顾：** Web 请求当前世界/时间线的 `/return`；API 先验证所有者，再读取当前 `simNow`、该用户和时间线的双水位（事件 rowid 与已读事实版本）。回顾只纳入 `simTime <= simNow` 且高于对应水位的记录，合并可明确关联的事件、命令和事实，生成有界摘要与重点项，并返回 `nextCursor`/`hasMore`。
2. **重点规则：** 版本化事实中有命令来源的状态改变及约定状态改变可确定性突出，并显示具体命令/事实；其余新事件仍在事件列表浏览。弱关系仅标为可能关联，不作为突出事实依据。
3. **展开证据：** 点击事件后按 eventId+timelineId 请求详情；API 验证该事件属于此世界和时间线，找到显式来源命令/事实，再调用 `versionAtTime`/`reconstructAt` 检查事件时点。响应将记录事实、可能关联、未知、观察者可见知识、状态快照及 `gaps[]` 分区返回。
4. **查看/分叉：** 若完整检查点确认覆盖该时点，UI 可进入历史状态或带时间点/来源条件打开 F1；携带检查点版本作为乐观并发条件。否则保留详情和证据缺口提示，不显示可操作入口。
5. **标记已读：** 用户标记当前实际展示的页面后，`/return/seen` 校验事件游标和事实版本均属于该时间线且不晚于当下可见水位，再用单次条件更新推进 `worldVisits`。并发新增只会留到下次回顾；不同用户或分支的水位互不影响。
6. **失败与空结果：** 回顾或证据读取失败显示重试；缺少记录展示原始事件及缺口。所有流程均只读，不调用模型、不写事实/记忆。既有约定按钮与未读消息逻辑继续使用现有接口。

### 技术决策

- 已读水位为 `worldVisits.eventCursor + worldVisits.revisionVersion`，用户与时间线键保持现有隔离；提交水位时服务端验证其不超过响应中实际展示的、同一时间线的当前可见记录。
- 回顾按命令/事实版本和历史事件分成可合并的有界流；强关联仅由直接来源 ID 确认。不同流按模拟时间排序显示；分页令牌携带两条流的游标。
- “重要变化”用固定类别与直接来源条件判定，不调用模型；其他已持久化事件仍可浏览。证据不足时返回明确缺口。
- 不新增表；仅给 `world_visits` 加水位列。事件、回顾详情、历史状态均为读取操作，F1 确认仍负责实际分叉写入。
- 旧数据库通过单向默认 0 迁移兼容；旧记录继续可见，其缺失来源不补造。
