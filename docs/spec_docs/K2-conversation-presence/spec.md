# K2：交谈渠道与空间事实一致 Spec

> 状态：整份 Spec 已获用户批准。
> 日期：2026-10-04。
> 工作线：B——世界可信性与分叉。

## 背景

第二轮体验报告第 20 项记录了一个空间事实错误：用户从人物生活页选择“打电话”并发起交谈后，居民回复“进来吧”，人物活动和记忆都把用户写成在书店门口来访。用户说明自己仍在别处、是通过电话联系后，记忆改成电话联系，但人物活动仍保留现场会面。问题在于交谈渠道没有贯穿交谈上下文和后续状态记录，远程联系被误写成共同在场。

## 目标

- 让电话等远程交谈始终作为远程交流处理，不自动改变用户的地点或生成到场、同地会面等事实。
- 让交谈回复、活动、事件和参与者记忆反映实际渠道与已知位置。
- 只有存在有效在场及地点证据时，才记录现场会面。
- 用户纠正渠道或位置时，相关交谈状态保持一致，避免记忆与人物活动互相矛盾。

**依据：** 第二轮体验报告第 20 项、产品愿景“可信交流”与“在场者”定义，以及发展安排中的 K2 预期结果。后续需求明确支持的渠道、位置证据、既有错误状态的修正范围和验收边界。

## 功能需求

- **F1 渠道明确：** 每次交谈请求都携带明确渠道与必要上下文。首版至少支持电话和当面交谈；没有明确渠道的既有调用须按其实际入口确定语义，不得由模型猜测。
- **F2 电话不产生到场：** 电话交谈不得把用户加入居民所在地点的在场者、访客或同地会面上下文；不得因电话本身改写用户地点、居民位置或生成“在门口相遇”等共同经历。居民可邀请用户来访，但邀请只作为对话内容，不代表用户已到场。
- **F3 当面交谈需证据：** 只有在请求中的在场身份、交谈地点和模拟时刻通过服务端校验，且交谈者符合该地点的会面条件时，才能记录当面会面及共同在场经历。校验失败时拒绝该交谈请求或提供明确的可恢复结果，不得降级成虚构的现场交谈。
- **F4 记录反映渠道：** 对话上下文、持久化事件、双方活动文本及参与者记忆应使用一致的交谈渠道、实际位置和模拟时刻。电话事件可记录双方通过电话交谈，但不把消息正文泄漏给无权者；电话对话成为参与者经历，不自动成为其他居民的知识。
- **F5 用户纠正：** 用户在对话中明确纠正“我仍在别处”或“这是电话联系”时，后续回复与新生成的活动/记忆须遵循已确认渠道和位置。不能可靠修复现有活动或记忆时，应保留原记录并用后续可追溯记录更正，不静默伪造历史已被改写。
- **F6 调用覆盖：** 所有能发起居民交谈的入口均须传递同一渠道语义；人物生活页电话入口不得绕过校验。访客或其他会话模式如未提供可验证的在场证据，不得被记录为现场会面。
- **F7 兼容：** 既有对话记录继续可读；不带渠道的旧记录标为渠道未知，不从对话文字追溯猜测其为电话或当面。K1 居民知识隔离规则继续生效。

## 非功能需求

- **N1 服务端可信：** 渠道、交谈者、在场身份、地点和模拟时刻由受信请求上下文确定并由服务端校验；模型输出不能单独创建或改变这些空间事实。
- **N2 一致性：** 一次交谈的渠道与空间上下文在模型输入、持久化事件、活动及记忆写入中保持一致。只有实际提交成功才向用户显示为已发生；部分写入或失败不得留下“已经现场会面”的残余状态。
- **N3 位置与时间边界：** 在场证据必须属于当前用户、世界、时间线和有效模拟时刻；过期或跨时间线的位置不能支持当前当面交谈。电话交谈不要求用户与居民同地，也不隐含任何位置移动。
- **N4 可追溯：** 可持久化的交谈记录应保存足以区分渠道、参与者、模拟时刻及必要位置的信息。渠道或位置未知时明确标未知；不从自然语言事后推断缺失字段。
- **N5 知识与隐私：** 电话交谈内容只进入获准参与者的知识/记忆；其他居民须通过实际可见证据获知。渠道信息可以用于解释事件，但不能绕过 K1 的时间线知识边界或暴露私人内容。
- **N6 失败恢复：** 渠道不受支持、在场校验失败、模型或持久化出错时，返回可理解且可重试/纠正的结果；不能静默切换渠道、伪报成功或要求用户靠猜测修正空间状态。
- **N7 兼容与性能：** 不改变旧事件与记忆原文；旧渠道缺失按未知处理。新增校验复用现有世界状态读取，避免额外模型调用来判断用户是否到场。

## 不做的事

- 不接入真实电话、语音通话、短信或外部通信服务；“电话”是世界内交谈渠道标签与语境。
- 不实现完整通信可达性模拟，包括电话设备、号码、信号、费用、接通率、拒接策略和网络故障；首版只阻止系统把远程渠道误写成同地在场。
- 不扩展为书信、公告、群聊等新渠道；这些渠道后续另行定义证据、时延、接收者和知识传播规则。
- 不实现用户跨地点即时移动或完整位置模拟；电话不会移动用户，当面交谈沿用现有在场与地点校验能力。
- 不批量重写历史事件、既有对话或压缩记忆来修复旧数据。当前交谈中发现错误时，可更正当前活动并追加可追溯更正记录；历史原文保留。
- 不保证电话对象必然接听，也不重做居民日程、情绪或关系模型；这些因素可影响回应，但不改变渠道与空间事实规则。
- 不改变 K1 的知识隔离和 E1 的变化回顾契约；不为表达活动文本而新增完整动画或场景渲染行为。

## 验收标准

1. 从人物生活页发起电话交谈时，居民回复上下文标明电话渠道；用户仍保持原地点，不被加入居民地点的在场者或访客列表。
2. 电话交谈可以包含来访邀请，但系统不会因此记录用户已接受邀请、已移动或已与居民同地会面；事件、活动及参与者记忆一致记录为电话联系，且不泄漏给无权者。
3. 用户在电话对话中明确说明自己仍在别处时，后续回复和当前人物活动反映电话渠道；记忆记录正确描述远程交谈。若需更正已写记录，历史原文仍保留，并可查到明确的更正记录。
4. 当面交谈只有在当前世界、时间线和模拟时刻下存在有效用户在场身份及合格交谈地点时才成功记录；缺少证据、证据过期或地点不符时，不产生现场会面事件、活动或记忆，并向用户说明如何恢复。
5. 其他交谈入口传递与入口语义一致的渠道；缺少渠道的旧调用/记录按未知处理，不猜测为电话或当面，不因此生成位置事实。
6. 模型输出不能覆盖服务端渠道与位置；即使模型文案声称用户在现场，电话记录仍不得产生同地事实。
7. 对话模型、校验或持久化失败时，界面不显示交谈成功；重试/纠正后不会留下重复或互相矛盾的现场会面状态。
8. 交谈内容只进入获准参与者知识；未参与居民不会仅因共享事件、系统摘要或跨时间线继承而获得电话内容，继续遵循 K1 证据规则。
9. 旧记录和压缩记忆不会被批量改写；正在发生的错误活动可经用户纠正而同步到当前状态，且更正过程可追溯。
