# 虚拟邻居（Virtual Neighbor）Spec

## 背景

- 我有一个静态博客（有域名、无服务器），想给博客加一个"活着的"虚拟小世界。
- 现有代码库是本地多人格语音助手原型，本次整体推倒重构，旧代码仅作素材参考。
- 产品参照：星露谷物语 / 斯坦福小镇（Generative Agents）的"活着的小世界"，
  叠加《新参者》（东野圭吾）式的人情推理口味——谜底落点皆是人心。
- 更深一层的动机：一个人可以被"蒸馏"成一份人格档案——
  让现实里难以交互的人（远方的、故去的、虚构的）以角色身份活在网站上。

## 主线决策（来自需求问答）

1. 新租 VPS 运行后端；博客保持静态站，信息流页面嵌入其中。
2. 本期纯文本信息流呈现，不做可视化；世界状态结构化，预留未来像素地图的数据基础。
3. 本期访客纯围观，页面无任何输入口。
4. 世界按定时心跳运转，夜间时段角色休眠；LLM 成本可预算、可配置。
5. 角色由「人格档案」（结构化 markdown，类 skill.md）定义。
6. 路线图确认：访客搭话、访客创建角色都要做，但均不在本期；
   架构为世界状态查询、会话、角色注册预留扩展点。

## 世界设定

- 舞台：临海商店街小镇（《玉子市场》《元气囝仔》式日常氛围）。
- 地点：满月喫茶、拾光旧书店、海边堤坝、神社台阶、街心公园、两家住家。
- 背景人物（只被提及、不建模）：駄菓子屋奶奶、邮局大叔、流浪猫等。
- 世界自带谜团供给：日常小谜团每周出现；一个季度级大谜团贯穿
  （即星野辞职前那桩未破的旧案）。

## 首发阵容

- 星野 · 42 ·「满月喫茶」老板
  前刑警，因一桩未破案件辞职来到海边。温和有礼，职业习惯改不掉：
  记得全街每个人的习惯，一眼看出谁今天不对劲。
- 七濑 · 24 · 喫茶店打工店员
  直觉跳脱派，结论跑得比证据快十倍，偶尔蒙对到吓人。
- 关系：星野演绎、七濑直觉，常殊途同归。

## 目标

- G1: 访客打开博客的信息流页面，能看到一个活着的中文小镇：
      两位居民经营日常、相遇闲聊、解谜、写日记，内容持续更新。
- G2: 世界全自动运转，无需人工干预，LLM 成本可预算、可调节。
- G3: 居民言行符合各自人格且前后一致，能记住并引用自己过去的经历；
      谜团跨时间推进，线索与揭示前后呼应。
- G4: 新增一名居民只需新增一份人格档案，不需要改动系统代码。
- G5: 架构为后续阶段（访客搭话、访客创建角色、像素地图可视化）
      预留扩展点，届时不需要推翻世界模型。

## 功能需求

- F1 世界心跳引擎
  系统按可配置的时间间隔（心跳）自动推进世界，无需人工触发。
  每个心跳中，每位居民根据自己的状态、记忆、日程和所处环境决定行动：
  留在原地做事、移动到别的地点、或与在场的其他居民互动。
  夜间休眠时段（可配置）世界暂停，居民"睡觉"。

- F2 人格档案系统
  每位居民由一份独立的人格档案完整定义：身份背景、性格、说话方式、
  喜好、作息、住所与常去地点、与其他居民及背景人物的关系。
  新增居民只需新增一份档案并通过校验，无需改动系统其他部分；
  档案不合法时拒绝载入并指出问题。首发包含星野与七濑两份档案。

- F3 角色记忆
  每位居民拥有持久的个人记忆，经历与看法随时间累积；
  后续行动中能回忆起相关的过往（包括几天前的事）并言行一致；
  支持"反思"：定期把零散经历沉淀为抽象认识（对某人的印象、
  某个习惯、对某桩谜团的猜想）。系统重启后记忆不丢失。

- F4 结构化世界状态
  系统维护权威的结构化世界状态：地点清单、每位居民当前位置与
  进行中的活动、当前时间段、居民间关系倾向、进行中的谜团及其状态。
  信息流由它生成；未来的可视化地图直接读取它，无需改造。

- F5 居民日程与生活感
  每位居民有符合人格的作息规律（星野清晨烘豆备料、七濑午后看店），
  在作息框架内随机变化，避免每日重复。
  天气、季节、节日、背景人物的只言片语等作为世界事件，
  影响居民的话题和行为。

- F6 谜团供给机制
  系统周期性在街上生成"日常之谜"（背景人物的反常举动、
  无法解释的小现象），并跟踪每个谜团的状态（出现/调查中/已揭晓）。
  另有一个季度级大谜团（星野的旧案）以缓慢节奏分阶段推进。
  谜团的揭晓必须落在"人心与温暖"上，不涉及犯罪与伤害细节。

- F7 信息流条目生成
  系统将世界事件转化为公开文本条目，类型至少包括：
  动态（某人做了什么）、对话（居民间的交谈片段）、
  独白（某位居民的内心独白，定期产出；星野的推理笔记即属此类）。
  每条目关联角色、时间、地点、类型；独白体现记忆与反思成果，
  口吻严格符合人格档案。

- F8 只读 API
  对外只读接口：时间线（分页、倒序）、居民列表与公开人格信息、
  单居民条目。本期不提供任何写接口；为未来的访客会话预留扩展位。

- F9 信息流前端页面
  可嵌入任意静态博客的页面：时间倒序展示条目，
  显示角色名、时间、类型标签；支持按居民筛选；
  支持居民主页（人格介绍 + 该居民的条目）；
  桌面与手机浏览器均可正常阅读。
  嵌入方式为 iframe 或一段脚本，不依赖具体博客框架。

- F10 成本与运转控制
  心跳频率、休眠时段、各环节模型档位均可配置，改配置即生效。
  记录每次 LLM 调用用量，可按天统计与估算成本。
  提供演示模式：更高心跳频率运行，用于调试与验收，不产生公开内容。

- F11 内容护栏与条目下线
  条目发布前自动检查敏感主题与不当内容（含犯罪细节描写），
  命中则拦截不发布；管理员可将已发布条目标记下线，
  下线后从 API 与页面消失；拦截与下线均留有记录。

## 非功能需求

- N1 成本可观测与可调节
  本期不设硬性成本上限。系统必须提供按天的 LLM 用量与估算成本
  统计（见 F10），且心跳频率、休眠时段、各环节模型档位可配置，
  使运营成本可随时下调。运行一段时间后由主人决定是否设红线。

- N2 轻量托管
  全部后端组件运行于单一免费云托管额度内，无需自有服务器；
  使用轻量级托管存储起步，不依赖自建数据库服务。

- N3 可演进性
  世界状态结构化且完整（含地点、位置、谜团状态）；
  API 预留扩展位。未来的访客会话、访客创建角色、像素地图可视化，
  不需要推翻世界模型或破坏现有 API 契约。

- N4 运行可靠性
  7×24 无人值守运行；进程异常退出后可自动恢复；
  世界状态与记忆定期持久化，重启后从中断处继续，不丢故事进度。

- N5 前端嵌入兼容
  信息流页面可嵌入任意静态博客，不依赖具体博客框架；
  桌面与手机浏览器均可正常阅读；目标访客的网络环境下可正常访问。

- N6 中文内容
  一切对外生成内容以简体中文为主。

- N7 时间真实感
  世界时间与真实时间同步（同一时区）；居民作息对应真实一天
  （清晨开店备料、傍晚海边散步、深夜休眠）。

- N8 隐私与安全
  后端仅暴露只读接口；LLM 凭据只存于服务端，不下发前端；
  访客无任何输入口，无注入面；
  管理操作（条目下线、配置修改）需要管理员凭据。

## 不做的事（本期）

- 访客与角色的任何互动：搭话、评论、点赞、私信。
  （访客搭话已确认在路线图，属二期。）
- 访客创建角色：产品化的角色创建入口（上传人格档案、LLM 辅助蒸馏）。
  本期新增/修改居民由主人直接编辑档案文件完成，不做管理界面。
- 可视化地图与美术资产：像素地图、立绘、动画。
  本期只保证世界状态结构化，未来可直接支撑可视化。
- 语音能力整条线：STT / TTS / 唤醒词 / 声音克隆，不迁移旧项目实现。
- 现实世界工具接入：角色不调用真实搜索、B 站、日历、音乐等外部接口。
  世界自洽虚构：背景人物、信件、传闻等均由生成而来。
- 用户账号体系：访客无注册/登录；管理操作仅认服务端管理员凭据。
- 实时推送：信息流以轮询方式更新即可，不做 WebSocket 推送。
- 犯罪题材内容：谜团落点限定在人心与温暖，
  不做凶案、犯罪细节描写（与 F6/F11 呼应）。
- 多世界/多社区：本期只运行一个世界、一个社区。
- 旧架构的兼容义务：不复用旧项目的运行时结构
  （core/backend/edge 分层、LangGraph 编排、MCP 工具注册等），
  新系统按 plan 重新组织，旧代码仅作概念参考。

## 验收标准

- AC1 (F1): 以后端启动为起点，无需任何人工触发，世界按配置的心跳间隔
  持续产生新事件（演示模式下加速观察）；休眠时段内无新事件，
  休眠结束后自动恢复。
- AC2 (F2): 新增一份合法人格档案并重载，新居民出现在世界状态与信息流中，
  全程未改动代码；提交一份缺关键字段的档案，
  载入被拒绝且错误信息指名问题字段。
- AC3 (F3): 连续运行数日后，居民的对话或独白中引用了数天前发生的事件；
  重启服务后记忆与世界状态完整；能在居民记忆中观察到反思沉淀
  （如对某人的印象、对谜团的猜想）。
- AC4 (F4): 任意时刻查询世界状态：每位居民有确定位置、进行中的活动、
  当前时间段、关系倾向、谜团状态；两名居民同处一地时产生互动事件。
- AC5 (F5): 连续多日观察，居民作息符合人格（清晨备料、午后看店）
  且每日不完全重复；信息流中出现受天气/季节/背景人物影响的条目。
- AC6 (F6): 连续运行一周内至少出现一个日常之谜，并经历
  "出现 → 调查 → 揭晓"完整生命周期，揭晓内容温暖、无犯罪细节；
  季度大谜团（星野旧案）持续有阶段性推进。
- AC7 (F7): 信息流包含动态/对话/独白三类条目，每条含角色、时间、
  地点、类型；隐去作者名展示独白，能分辨出星野与七濑（口吻可区分）。
- AC8 (F8): 时间线接口分页倒序返回，与页面所见一致；
  居民接口返回公开人格信息；全部对外接口不存在可用写操作。
- AC9 (F9): 信息流页面嵌入静态博客后：倒序展示、按居民筛选、
  查看居民主页均可用；桌面与手机浏览器排版正常；
  页面无任何输入框或提交按钮。
- AC10 (F10): 修改心跳频率或休眠时段配置后新行为生效，无需改代码；
  可按天查看 LLM 调用用量与估算成本；
  演示模式加速运行时不产生公开条目。
- AC11 (F11): 构造含敏感主题或犯罪细节的待发布条目，全部被拦截、
  不出现在信息流，且留有拦截记录；管理员标记某条目下线后，
  API 与页面均不再返回；无管理员凭据执行管理操作被拒绝。
- AC12 (N2/N4): 全部服务在目标免费托管额度内稳定运行；
  模拟 tick 中断后，下一次心跳自动续跑，世界状态与故事进度无丢失。
