# Possibility 阶段二：活的世界 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为而非实现细节。
> 前置：`npm install` 已完成、`.dev.vars` 已同步 `ENGINE_TICK_SECRET`、`npm run db:migrate` + `npm run migrate:p2` + `npm run seed` + `npm run seed:demo` 已执行、`npm run dev` 三进程运行中。
> D1 查询在 `api/` 目录：`npx wrangler d1 execute possibility --local --command "SQL"`。

## 实现完整性

### 世界模型与迁移（spec AC1 / F1）
- [ ] 迁移后阶段一人物的聊天记录、记忆、分叉时间线全部可正常访问（验证：登录旧账号，打开人物详情与聊天页，历史消息与分叉列表正常显示）
- [ ] 每个世界含地点集与人物名单（验证：d1 查 `SELECT json_array_length(locations_json) FROM worlds`，旧世界 ≥3；`SELECT COUNT(*) FROM world_persons` = 世界数（旧数据）+ 6（演示世界））
- [ ] 同一人物分属两个世界时状态互不影响（验证：把一个人物加入第二个世界，两世界中其 personStates 的 location/activity 各自独立变化）
- [ ] 数据迁移幂等（验证：`npm run migrate:p2` 连跑两次，第二次输出处理行数为 0，无报错）

### 引擎与日程（spec AC3 / AC4 / F3 / F4）
- [ ] 世界时钟以 6 倍速推进（验证：记录 `GET /api/engine/status` 中某世界 simNow，10 真实分钟后再次读取，差值 60 分钟 ±20%）
- [ ] 无用户操作时世界持续运转（验证：不打开任何页面 30 分钟，事件流新增 ≥5 条，人物状态有变化）
- [ ] 停机不追赶（验证：停掉全部进程 30 分钟后重启，世界 simNow 从停机点附近继续推进，无一次性大跳——status 接口观察重启前后 simNow 差值 ≤15 虚拟分钟+重启后正常节拍）
- [ ] 人物详情可见当日日程（时间段+地点+内容）（验证：世界视图点人物 → 日程 Tab 有 6-10 项，睡眠项有标记）
- [ ] 执行日程中无 LLM 调用（验证：选一个处于日程项中段的人物，观察 2 拍，`llm_call_log` 无该人物新行）

### 相遇、对话与想法（spec AC5 / AC6 / F5 / F6）
- [ ] 同地点同窗口的两人物触发相遇，事件流出现对话事件（验证：将两人物 state 改到同地点，3 拍内出现 kind=dialogue 事件）
- [ ] 对话逐句生成、标注说话人、可展开（验证：事件流中对话事件展开，看到 ≥4 轮交替发言，每句有说话人；对话进行中打开还能看到逐句递增）
- [ ] 每句发言附带内心想法（验证：对话展开中每句可看到「想法」；d1 查 dialogue_turns.thought 非空）
- [ ] 对话结束后双方记忆流出现相关条目（验证：对话结束后查两人 memories 新增 type∈(relationship,timeline) 且 importance 有值的条目）
- [ ] 后续相遇能提及此前对话内容（验证：同一对人物再次对话，发言中提及上次交谈的话题——人工判读）
- [ ] 人物行动后想法流出现对应第一人称想法（验证：事件流出现新行动事件后，该人物想法流最新条目与该行动情境相关——人工判读）

### 介入与多时间线（spec AC7 / AC8 / AC9 / F7 / F8 / F9）
- [ ] 注入事件生效并被感知（验证：注入「突然下起暴雨」→ 事件流出现注入事件（高亮样式）→ 3 拍内身处室外的人物行为/想法/对话中提及下雨）
- [ ] 暂停/继续（验证：暂停后 status=paused、simNow 停走、`llm_call_log` 不再增长；继续后从暂停点恢复推进）
- [ ] Fork 后双线并行（验证：Fork 后时间线切换器出现新线；分别查看两线，simNow 都在推进、事件各自增长）
- [ ] 分叉记忆隔离（验证：分叉后继续运行产生新事件，再对比两线同一人物的记忆流——分叉线不含主线分叉点之后的记忆；d1 抽查可见性规则）
- [ ] 活跃线上限（验证：连 fork 使活跃线达 3 条后，第 4 次 fork 返回错误并提示需先归档；归档一条后可再 fork）
- [ ] 归档生效（验证：归档一条线后其 simNow 停走、事件不再增长；快照中标记为已归档）

### 记忆流与增长管理（spec F13 / plan D7–D9）
- [ ] 记忆带重要性评分（验证：引擎产生的新记忆行 importance 在 1-10 之间且不全相同——d1 抽查 20 行）
- [ ] 检索组合正确（验证：对某人物触发一次节拍，人工核对（临时日志或插桩）其上下文记忆 = 近期 12 + 重要性 top 8 + 最新摘要 ≤2，且不含 summarized=1 的条目）
- [ ] 压缩触发（验证：将阈值临时改小（如 5）触发一次 summary step，记忆流出现 type=summary 条目，原文 summarized=1，节拍上下文中原文不再出现而摘要出现）

### 成本护栏（spec AC13 / F14 / N1 / N7）
- [ ] 每拍上限（验证：TICK_CALL_CAP 临时调为 2，单拍摘要中某世界执行的 decide 数 ≤2，剩余决策点下拍继续）
- [ ] 每日上限触顶自动暂停（验证：DAILY_CALL_CAP 临时调为 20，跑至触顶：世界 status=capped、世界视图显示触顶提示、LLM 调用停止）
- [ ] 手动复位恢复（验证：触顶后点继续（resume），callsToday 清零、世界恢复 running）
- [ ] 引擎状态可查（验证：`GET /api/engine/status` 返回各世界 simNow/lastRealTickAt/callsToday/status/pauseReason）
- [ ] LLM 调用全部记账（验证：跑 10 拍，`SELECT COUNT(*) FROM llm_call_log` 与 worlds.callsToday 合计一致；purpose 取值均在 schedule/beat/dialogue_turn/injection/summary/chat/distill 内）

### 演示世界（spec AC14 / F15）
- [ ] 雾影庄开箱即在运行（验证：全新环境按 README 流程启动后执行 seed:demo，无需登录即可在首页看到世界运转：6 人物、7 地点、事件流随时间增长）
- [ ] 六个人物设定符合 spec 附录（姓名、身份、悬念钩子——人工对照 spec 附录表）
- [ ] 演示世界受每日上限约束且额度独立（验证：d1 查演示世界 callsToday 随运行增长；触顶行为与普通世界一致）

## 集成

- [ ] 世界服务写入 → 引擎消费（验证：注入事件/Fork 经 API 写入后，下一拍 pinger 日志出现对应 injection/fork 后续节拍——plan 流程 1/3/4）
- [ ] 快照与 SSE 衔接（验证：打开世界视图先拿到快照（近 1 世界日事件），随后 SSE 推送的新事件无重复无缺失地接上）
- [ ] 访客与主人同构视图（验证：同一演示世界，主人视图（登录）与访客视图（无痕）内容一致，仅控件差异）
- [ ] 单人步骤失败不阻塞（验证：临时把某人物模型改坏（如 locations 全删使其日程生成失败），观察同线其他人物节拍正常、pinger 日志有失败记录、后续拍自动恢复）
- [ ] 所有公开接口被真实使用（验证：前端世界视图/列表/向导/落地页全部走通，无"只在代码里存在"的接口——对照 client.ts 与路由表逐一核对调用点）
- [ ] 阶段一功能回归（验证：创建新人物 → 打电话聊天（流式正常、人物能记住对话内容）→ 从人物页发起 what-if 分叉 → 时间线详情正常；首页各区块正常）

## 端到端场景

- [ ] **场景 1：主人的一天**——登录 → 用一句话创建新世界（选 3 人）→ 世界视图中看着人物陆续起床/出门/相遇交谈 → 点开一个人物看他在想什么 → 注入「突然下起暴雨」观察人物收衣服/避雨 → 从当下 Fork 一条「如果暴雨引发山洪」的新线 → 两线并行观察各自的走向 → 暂停原线、切到新线继续观看（验证：全程可观察、每步结果符合预期，preview_screenshot 留证）
- [ ] **场景 2：访客的一分钟**——无痕窗口打开站点 → 直接进入雾影庄：看到世界时钟在走、大厅里有人、事件流在滚动 → 点开一段正在进行的对话逐句读 → 点开雾野透看他的想法流（最新想法与他正在做的事相关）→ 试图找到任何能写操作的入口（找不到）（验证：preview_screenshot 留证；curl 验证写接口 401/403/404）
- [ ] **场景 3：边界与恢复**——把每日上限调低触发自动暂停 → 看到触顶提示 → 手动复位恢复 → 杀掉全部进程 30 分钟 → 重启后世界从停机点继续（无时间大跳）、pinger 自动恢复打拍（验证：status 接口与 pinger 日志证据）
