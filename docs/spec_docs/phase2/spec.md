# Possibility 阶段二：活的世界 Spec

## 背景

Possibility 阶段一（MVP）已完成：用户可以创建人物（Version）、与 TA 文字交流、用 What-if 分叉时间线。但当前结构中 World 只是单个人物的容器，人物之间互不知道彼此存在，世界也没有"在运行"的感觉——所有推演都是用户到来时才懒惰追赶。

产品设计文档的完整愿景是「让多个人物生活在一个持续运行的小世界里，用户可以观察、介入、分叉」。阶段二要把"世界"从容器升级为一等公民：多个人物在同一个世界里按日程自主生活、相遇并产生完整对话，主人可以随时以旁观者身份进入一个正在运行的世界，看到人物、事件、对话和人物的内心想法。

另外，阶段二新增一个内置的演示世界（推理小说氛围的原创设定「雾影庄」），作为产品的公共橱窗：任何人免登录即可围观一个正在运行的世界。

## 目标

- G1: 世界持续运行——无需用户触发，世界按 6 倍于真实的时钟自主推进，人物按日程生活、移动、相遇、对话。
- G2: 人物有社会性——同一世界里的人物互相知道彼此，相遇时进行逐句生成的完整对话，对话进入双方记忆并影响后续行为。
- G3: 世界可观察——主人可以随时打开世界视图，看到当前时间、各地点的人物与活动、滚动的事件流与对话记录；点击人物可看到 TA 的状态、想法流、日程与近期记忆。
- G4: 主人可介入但不入场——可以注入世界事件、从当前状态 Fork 出新时间线，但不能以"我"的身份出现在世界里与人物对话（叙事一致性）。
- G5: 成本可控——事件驱动调度（无决策点不调用 LLM）+ 每节拍与每日调用上限，保证常跑引擎的 token 消耗有硬顶。
- G6: 产品可传播——内置演示世界免登录只读开放，访客零门槛体验"活的世界"。

## 功能需求

### 世界模型

- F1: **世界一等公民**。World 拥有名称、背景描述、地点集合（5-8 个）、3-6 个人物（阶段一人物各自迁入一个默认单人世界，历史数据不丢）。人物可属于多个世界（不同世界中的状态、记忆互相独立）。
- F2: **Quick World 创建**。输入一句话描述，系统生成世界骨架（名称、背景、地点集），主人从已有人物中挑选 1-6 人入驻后世界开始运行。创建时可编辑生成的地点与人物初始状态。

### 世界引擎

- F3: **常跑引擎，6 倍速，事件驱动**。世界时钟流速 = 真实 6 倍（世界一天 = 4 真实小时）。引擎按固定节拍（约每真实 10-30 秒）扫描活跃世界，仅在决策点调用 LLM：人物日程项结束、相遇发生、注入事件生效、对话进行中。引擎停机期间世界时间不推进（不做停机追赶），恢复后从停机点继续。
- F4: **人物日程**。每个人物每条活跃时间线持有一份当日日程（起床/工作/吃饭/睡觉等带地点与时间段的条目），由 LLM 在日程开始时生成、被事件打断时调整。人物处于"执行日程"状态时不产生 LLM 调用。
- F5: **相遇与完整对话**。同一地点、同一时间窗口内活动的人物触发相遇，进行多轮对话（每句由各自人物的 LLM 生成，受各自人格与记忆驱动）。对话有轮次上限；结束后对话内容分别进入双方记忆，并作为一条事件进入世界事件流。
- F6: **内心独白**。人物每次行动或每轮对话发言时，同一次 LLM 生成中顺带产出一条第一人称想法（在想什么、为什么这么做），存入想法流，可按人物与时间线查询。

### 介入与时间线

- F7: **注入事件**。主人在世界视图输入一句自然语言（如"突然下起暴雨"），作为世界事件生效：当前在该世界的人物于下一个决策点感知并自行反应，事件本身进入事件流。
- F8: **暂停/继续**。主人可暂停一个世界（时钟停走、不再产生 LLM 调用），随时继续（从暂停点恢复推进）。
- F9: **Fork 与多线并行**。从世界当前状态 Fork：复制世界设定、地点、所有人物的当前状态与记忆到一条新时间线，主线与分叉并行常跑。每个世界最多 3 条活跃时间线（达到上限需先归档一条）。记忆按时间线严格隔离，分叉只能看到分叉点之前的记忆。

### 观察视图（私人世界仅主人）

- F10: **世界视图**。展示：当前世界时间与时间线切换器；地点列表（每个地点显示在场人物及其当前活动）；滚动世界事件流（行动、相遇、注入事件，其中对话可展开查看逐句记录）；注入事件输入框；Fork 与暂停按钮。
- F11: **人物详情**。在世界视图中点击人物，展示：当前状态（地点/活动/情绪/目标）、想法流（倒序）、今日日程、近期记忆摘要。
- F12: **世界内不可对话**。世界视图不提供与人物对话的入口。与人物聊天保留在人物页，叙事定位为"打电话"——不需要"我"出现在世界里。

### 记忆系统（参考斯坦福小镇概念，基础设施减负）

- F13: **记忆流与增长管理**。人物经历的事件、参与的对话、产生的想法统一汇入记忆流（隔离键：人物 × 世界 × 时间线），每条带时间戳与重要性评分（写入时由 LLM 顺带打 1-10 分，零额外调用）。决策点取上下文时按 近期 N 条 + 重要性 top-K + 最新滚动摘要 选取；未压缩记忆超过阈值时，一次 LLM 调用将最老的一批蒸馏为摘要条目（原文保留在库中可回溯，不再进入提示词）。不引入向量检索，不做递归计划分解。

### 成本护栏

- F14: **调用上限**。每个世界每节拍 LLM 调用数有上限；每个世界每日 LLM 调用总数有上限，触顶自动暂停该世界并在世界视图给出提示，次日或手动复位后恢复。演示世界额度独立配置。

### 演示世界与访客

- F15: **内置演示世界**。seed 创建官方演示世界「雾影庄」（6 人 / 7 地点 / 独立世界观设定与人物模型，设定见附录），随系统开箱即用，由引擎常跑，无需任何用户操作。
- F16: **访客免登录只读访问**。未登录访客打开站点即进入演示世界视图：可浏览地点、事件流、展开对话、点击人物查看状态与想法流；无注入/Fork/暂停入口，不可见任何用户私有世界，访客数量不产生额外引擎成本（引擎只跑一份）。

## 非功能需求

- N1: **成本硬顶**。单世界每节拍 LLM 调用次数有限，单世界每日 LLM 调用总数触顶自动暂停。演示世界独立配置额度。任何单人物单次 LLM 调用的 token 预算沿用阶段一经验（推理模型，预算给足，避免 reasoning 烧光返回空）。
- N2: **响应体验**。世界视图为服务端实时推送：新事件、新想法、新对话在 2 秒内出现在打开的页面上，无需手动刷新。页面打开时先一次性加载当前世界快照（近 1 天世界时间内的事件），再接通实时流。
- N3: **多世界多线隔离**。各世界、各时间线之间的人物状态、记忆、想法、事件严格隔离；同一时间线内多个人物的并行决策互不阻塞（一人 LLM 调用失败不影响其他人，失败可重试一次后跳过该决策点）。
- N4: **数据演进兼容**。阶段一已有人物、世界、时间线、记忆、聊天记录自动迁移到新结构（每人迁入默认单人世界），迁移幂等、不丢数据、可重跑。
- N5: **兼容现有技术栈与本地运行**。继续 Cloudflare Worker + D1 + React SPA，本地一条命令启动全部功能（含引擎）；不引入新的外部服务。
- N6: **访客访问控制**。演示世界的只读接口不校验登录态，但只暴露演示世界数据（以世界标记位限定）；其余所有接口维持原有登录态与数据归属校验，不放宽。
- N7: **可观测性**。引擎运行状态可查询（每个世界的时钟、上次节拍时间、当日已用 LLM 调用次数、暂停原因），便于本地验收与调优。
- N8: **叙事一致性**。所有面向用户的文案沿用产品术语（Person/World/Timeline/Fork），不出现 Agent/Prompt 等概念；世界内不出现"用户突然在场"的表述，聊天功能统一以"打电话"叙事呈现。

## 不做的事

- **部署**：本阶段仍为本地开发/验收版本，不做线上部署。
- **语音**：不做实时语音，一切文字。
- **Visit（以角色进入世界）**：主人不能以任何身份"进入"世界与人物同场互动；介入手段只有注入事件与 Fork。
- **访客互动**：访客对演示世界纯只读，不能注入事件、不能对话、不能 Fork、不能做任何写操作。
- **地图/2D 可视化**：观察视图为文本+卡片（地点列表、事件流、人物详情），不做图形化地图与人物走位动画。
- **世界运行中的人物增删**：世界创建时定员 3-6 人，运行中不支持中途加入/移出人物。
- **显式关系系统**：不建关系图谱/好感度数值，人物间关系由记忆与对话自然承载。
- **向量检索与递归计划**：记忆系统参考斯坦福小镇的记忆流/重要性/reflection/planning 概念，但检索用新近度+重要性的方案（不引入 embedding 服务），计划只做到"每日日程"一层。架构不挡未来升级（schema 预留重要性字段，检索实现可替换）。
- **剧本化悬疑剧情**：演示世界只有悬念钩子，不预设案件与结局，不保证任何特定情节发生。
- **分享私人世界**：用户创建的世界仍仅主人可见，不做分享/公开。
- **世界模板市场、高级世界编辑器、开放脚本系统**。
- **多用户协作共建同一世界**。

## 验收标准

### 世界与创建

- AC1（F1）: 迁移执行后，阶段一人物的聊天记录、记忆、分叉时间线全部可正常访问；数据库中每个世界含地点集与人物名单；同一人物分属两个世界时状态互不影响。
- AC2（F2）: 输入一句话描述，生成含名称/背景/5-8 个地点的世界骨架；挑选 3 个人物入驻并开始运行后，世界视图中可见人物陆续开始生活。

### 引擎与日程

- AC3（F3）: 引擎运行 10 真实分钟，世界时钟前进约 60 分钟（±20%）；期间无任何用户操作，人物状态与事件流持续变化。重启后端后，世界从停机时刻继续推进，不补跳。
- AC4（F4）: 每个人物在详情页可见当日日程（时间段+地点+内容）；人物处于日程执行中时 LLM 调用计数不增长。

### 相遇、对话与想法

- AC5（F5）: 两个人物处于同地点同时间窗口后，事件流出现相遇事件，可展开查看多轮逐句对话（标注说话人）；结束后双方记忆流各自出现相关条目；后续的相遇对话中，人物能提及此前相遇的内容。
- AC6（F6）: 人物行动与对话发言后，其想法流中出现对应的第一人称想法条目，内容与当时情境相关。

### 介入与多时间线

- AC7（F7）: 注入"突然下起暴雨"后：事件流出现该事件；身处室外的人物在下一个决策点改变行为并在想法或对话中提及下雨。
- AC8（F8）: 暂停后世界时钟停走、LLM 调用计数不再增长；继续后从暂停点恢复推进。
- AC9（F9）: Fork 后新时间线与主线并行推进（两者时钟都在走）；分叉中的记忆严格隔离（不拥有分叉点之后的主线记忆）；创建第 4 条活跃时间线被拒绝并提示需先归档。

### 观察视图

- AC10（F10）: 世界视图显示当前世界时间、地点列表（各地点在场人物及其活动）、滚动事件流；新事件在 2 秒内出现在已打开的页面上，无需刷新。
- AC11（F11）: 点击人物显示：当前状态（地点/活动/情绪/目标）、倒序想法流、当日日程、近期记忆摘要。
- AC12（F12）: 世界视图中不存在与人物对话的入口；从人物页发起聊天（打电话）正常可用。

### 成本护栏

- AC13（F14）: 将每日调用上限临时调低并触发后，该世界自动暂停且世界视图显示触顶提示；手动复位后恢复运行。

### 演示世界与访客

- AC14（F15）: 全新环境执行 seed 后，「雾影庄」开箱即在运行：6 个人物、7 个地点、事件流随时间增长。
- AC15（F16）: 无痕窗口（未登录）打开站点直接进入演示世界只读视图；看不到注入/Fork/暂停控件；任何写接口调用被拒绝；无法访问任何用户私有世界的数据。

## 附录：演示世界「雾影庄」设定

向本格推理黄金时代致敬的原创设定（不使用任何现成作家的人物与情节）。

**世界**：山间温泉小镇「白雾町」，常年多雾。镇外半山腰的老洋房「雾影庄」建于大正末年，传闻三十年前的一个雪夜，这里"发生过一件事"，镇上人从不多谈。时代为架空的大正—昭和过渡期风貌（电话刚通、火车单行线）。

**人物（6 人，全原创）**：

| 人物 | 身份 | 悬念钩子 |
|---|---|---|
| 雾野 透 | 43 岁，流浪业余侦探，因一封匿名信借宿庄内 | 谁寄的信？信上写了什么？他从不示人 |
| 白川 宗一郎 | 68 岁，雾影庄主人，退休实业家 | 三十年前雪夜的"那件事"是他的逆鳞 |
| 小夜 | 56 岁，女仆长，在庄里服务三十年 | 她知道所有人的秘密，恪守"不多言" |
| 柊 一成 | 45 岁，镇上唯一的外科医生，每周出诊 | 当年雪夜，出诊记录上有一页被撕去 |
| 白川 怜 | 25 岁，宗一郎之侄，三个月前突然归来"写小说" | 他其实在私下翻查旧物，寻找什么 |
| 三田村 千鹤 | 28 岁，地方报社记者，借宿门房 | 为"白雾町十年间三起失踪传闻"而来 |

**地点（7 个）**：大厅 / 书房 / 餐厅 / 图书室 / 温室花房 / 门房小屋 / 后山散步道（通温泉）

**运行逻辑**：没有剧本。六人按各自日程生活，相遇时对话由各自人格、记忆和秘密驱动。悬念是否揭开、何时揭开，由涌现决定。庄主（admin）可注入事件搅动静水。
