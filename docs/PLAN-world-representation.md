日期：2026-10-25
状态：**计划草案，实验与实现未开工**。当前交付仅为架构评估、[设计草案](architecture/DESIGN-world-representation.md)和本计划。用户已明确本轮先写文档、做好计划，不立即实现。

本文展开 [主计划 P3-W](PLAN.md)；范围是世界表示与后续验证路径。RSI、训练通用模型、完整天气/经济/物理系统、实时视觉升级不在首轮范围内。

## 1. 想通过后续工作做出的决定

- 当前世界表示缺少哪些使目标效应成立的信息与语义？
- A“属性快照与文字过程”与 B“语义组件与显式过程”哪一种更适合本项目，或需要怎样组合？
- 既有 WorldState/ops/revision/store 能复用到哪里，正式集成必须改哪些接口与调度行为？

成功结果可以是选择 B、保留 A 或否决两者；不预设复杂方案必胜。

## 3. W1：先把表示问题写成可比较的样例

第一组范围：两处库存、一条运输道路、降雨与排水过程，以及一个中途改善排水的干预。角色的恐慌、交易意愿等由角色决定，不写成环境必须发生的后果。

W1 产物应包含：

1. **概念表**：对象身份、关系、属性定义/单位/信息状态、持续过程、机制及其适用范围。
2. **两份等义输入**：A 与 B 采用相同事实、规律、未知项和历史，只改变组织方式。没有提供给 A 的知识，不能悄悄放进 B。
3. **人工参考轨迹**：写清每步状态、过程进度、已发生事件、待评估后果及依据。参考使用显式声明的玩具规律，并与现实准确性分开。
4. **异常轨迹**：未知条件、单位冲突、重复推进、前提改变、无关对象误改，以及过程进行中的分岔。
5. **跨领域检查**：干/湿木桌遇火只做纸上表达，识别天气专用假设与需要开放的概念。

**GW1**：相同语义可分别写入 A/B；关键差异可被读取；未知与预测不冒充事实；过程与事件分清；新增概念不改写过去。未能表达的情形记录为缺口，再修订候选。

## 4. W2：后续的独立表示实验

预期位置为 `scratch/world-model-lab`，本轮不创建。使用独立数据和数据库，不连接用户正在使用的世界，不改正式 contract；不提前建设通用模拟框架。

以最小脚本观察和记录表示、检查与推进结果。先用玩具机制隔离模型随机性；它能验证表示与流程，不能证明 LLM 已具备环境推演能力。

**GW2 必须观察的行为**：

- 数据读写与已提交状态恢复后，实体身份、单位、未知值、过程进度及版本不丢失。
- 未知前提不被自动补成确定数值；诊断指向所缺的属性或依据。
- 资源转移有对应账目；单位不相容及明确非法状态被拒绝，拒绝不留下半个提交。
- 同一区间重复送达不重复结算；拆分时间步的结果按玩具机制声明的规则或容差比较。
- 干预后旧后果失效或重新验证；未受影响对象保持一致。
- 改变实体 ID、位置或参数后仍可解释，不依赖示例名称。

Schema/解析器的已知路径不一致须单独验证、记录并安排修复；不能绕过失败入口后声称正式协议兼容。

## 5. W3：后续的模型对照

最早建议用 6 个小场景、A/B 两种表示、每种重复 2 次：最多 24 次初始调用。是否允许返修、返修上限、模型和 token 上限在执行前固定。调用失败也保留，不靠反复重跑选最好结果。

对照纪律：

- 两种表示共享初态、历史、机制说明、未知项、输出任务与总预算；记录输入与模型版本。
- 参考轨迹与判定条件单独保存，不放进生成 prompt；模型结果由参考与程序检查，不能仅用其自我评价计分。
- 若增加可执行机制作为第三项干预，另作消融，分开回答“表示收益”和“机制收益”。
- 单步、持续多步和用户干预分别报告。不能把单步 JSON 合法率当成多步正确率，也不以文笔评分替代状态检查。

| 指标 | 用途 |
| --- | --- |
| 完整表达率与必须字段遗漏 | 判断表示是否装下必要区别 |
| 单位、引用、资源、时间等可判定违规数 | 判断已声明约束是否满足 |
| 依赖对象遗漏、无关对象误改、跨步漂移 | 判断后果传播与稳定性 |
| 未知项被编造、旧预测被误提交、验证误放行/误拒绝 | 判断不确定与失效处理 |
| 请求数、token、延迟、人工修订量、输入体积 | 判断收益是否值得成本 |

**GW3**：给出逐案例证据与失败清单，能够比较两种候选的收益和代价。小样本只支持下一轮决策，不宣称统计显著或通用可靠；不以强行选出赢家收口。

## 6. W4：后续如何验证当前架构的承载能力

在 GW2 后可并行准备接口影响分析，但正式接入以表示选择与调用策略收敛为前提。先通过实验适配层连接现有 domain/store，再验证 Runtime；不能一开始改完整生产链路。

| 集成面 | 必须验证或决定 |
| --- | --- |
| ops / Schema | 多字符路径与转义一致；对象属性与过程描述可无损保存；验证失败不修改事实 |
| Runtime / 时间 | 生成期间时间推进策略、迟到结果、空计划、时间窗、同一时刻事件顺序、暂停/恢复和错误处理 |
| 干预 / 延迟 | 对话或编辑改变读取前提后，旧预测如何失效；到期提交前复核基准、条件与机制版本 |
| fork | 父子线状态与机制隔离；持续过程继承进度，未发生预测重算；角色上下文继承与祖先日志分页 |
| 重启 / 事务 | 从保存进度续算，不重复扣资源；结果、进度、revision 与验证记录不会部分落盘；仅读历史不调用模型 |
| 角色输入 | 客观隐藏状态、未来预测、他人记忆不经 prompt/日志/证据引用泄漏；符合可见域的观察才进入角色输入 |
| 投影 / 编辑器 | 世界仍为唯一事实源；新增数据可编辑且不会破坏既有视图；环境视觉效果另列需求与验收 |
| 预算 / 审计 | 新调用仍受跨线总预算限制；可从基准、依赖、诊断追溯接受或拒绝的结果 |

**GW4**：区分已验证复用项、必要修复和需要新契约的能力，再提交正式设计与实现任务。跨模块字段/调用类型变化沿用现有契约变更协议，同步 Schema、fixtures 与消费者；本计划不提前豁免协议。

## 7. 执行顺序、分工与资源

- **先 W1，再 W2**：表示尚不清楚时不并行开发多个生产模块。W1 的领域样例、当前架构核对可轻量并行，由主负责人统一概念和结论。
- **W2 后可准备两项独立工作**：模型实验输入/参考检查与 Runtime 集成影响分析；不由不同执行者各自改共享 contract。
- **重型工作云端优先**：模型批次、构建、大规模回归、GUI/E2E 等按用户 AGENTS.md 安排。若拟用 GitHub Actions，执行前明确告知用途、需上传的内容与所需权限；取得许可后才调用。产品配置的模型端点及凭证不自动视为 CI 授权。
- **本机只做获准的轻量工作**：定向读取、文档检查和后续小脚本按实际负载控制。重型任务仅在云端无法覆盖时考虑本机兜底，并检查 MemAvailable、PSI、换页与 cgroup；临时文件走项目 `.tmp`，复用已有服务，不终止其他任务。
- **证据管理**：结果记录案例、输入/输出、规则与模型版本、费用或调用量、失败和未验证项。实验代码可删除，观察结论进入 docs；原型通过不直接等于生产实现完成。
