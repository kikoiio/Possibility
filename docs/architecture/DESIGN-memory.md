# Wispiva 记忆系统设计(送审稿)

日期:2026-10-25
状态:**已批准生效(2026-10-25)**——经用户逐条评审、两轮纠偏与五项最终裁决;已并入 ARCHITECTURE.md,契约改动已回填 CONTRACT-DRAFT.md。讨论过程与调研出处见 DISCUSSION-memory.md。

## 1. 问题定义

世界持续运转数周后,记忆与事件累积到 prompt 装不下。记忆系统的本质工作是**prompt 组装**:每次 beat/对话/编辑调用,用有界、相关、可审计的上下文装下"这个世界发生过什么"——同时保住故事的认识论(谁知道什么、带着什么眼镜)。

## 2. 核心原则

1. **记忆是主观信念,不是客观日志**。事实只在 revision 链(L0);记忆天生允许是解释而非录像。
2. **可见性靠存储结构,不靠过滤**:记忆按 owner 分行,"谁知道什么"= 按拥有者查询。墙即结构。
3. **偏见两段式**:编码时着色(写入带 owner 相对情绪),检索时偏置(心境一致性加权)。均为确定性计算,零额外调用——"agentic 触发、确定性执行"。
4. **编码与讲述的落差是故事资产**:原始记忆永不改写;"改口"只发生在叙事层(L2)。保留落差=保留反转。
5. **不建心理学,建主观性的数据结构**:结构归代码,解释与自欺从模型租。
6. **超预算显式失败,不静默删减**(既有原则,不变)。
7. **系统仿真人性,不干预故事**(2026-10-25 用户原则):偏置不设上限、不投放系统级反制事件;角色的偏执与和解是世界自己的事。极端化监视(若做)仅为 UI 可见性,永不自动行动。任何"为了故事好看"的系统行为都是越权。

## 3. 数据模型

### 3.1 三层记录

| 层 | 内容 | 存储 | 可变性 |
| --- | --- | --- | --- |
| L0 事实 | 事件文本、ops、世界快照 | revision 链 | 不可变 |
| L1 经验 | 每个 owner 的带色记忆行 | `memories` 表 | 不可变(再固化仅实验) |
| L2 叙事 | 角色"如今的讲法"(reflection) | `memory_reflections` 表 | 版本化重写 |

### 3.2 Memory 行(契约新形状)

```ts
type Memory = {
  id: string;
  owner: string;            // 实体引用,必填,单数(原 knownBy[] 废除,见 §9)
  text: string;             // owner 的带色要点,非逐字原文
  valence: number;          // -1..1,编码时情绪极性(owner 相对;维度骨架,供确定性计算)
  intensity: number;        // 0..1,情绪强度/唤醒度;抗 recency 衰减
  emotion?: string;         // 可选离散情绪标签;词表候选=Plutchik 情绪圈 8 类(喜悦/接纳/恐惧/惊讶/
                            // 悲伤/厌恶/愤怒/期待,理论支撑成对极性),供渲染与更细的心境匹配;
                            // LLM 情绪类别推理在对齐维度值时更稳(hybrid,Emotional RAG 同路线)
  importance: number;       // 1..10,写入时生成方打分
  about: string[];          // 实体引用;检索锚点(两跳展开的边)
  sourceEventId: string;    // 锚回 L0;三栏对照的 join 键
  atMinutes: Minutes;       // 世界时间(衰减按世界时间,非墙钟)
  lastAccessedMinutes?: Minutes;  // 排练强化用,store 维护
};
```

### 3.3 一次对话的存储实例

```
事件 #102「老舟问阿苇当年书院的火」
├─ { owner:阿苇, text:"老舟突然来查火,我差点露馅", valence:-0.8, intensity:0.9, importance:9, about:[老舟,火灾] }
├─ { owner:老舟, text:"阿苇在岔开话,她肯定知道什么", valence:+0.3, intensity:0.5, importance:7, about:[阿苇,火灾] }
└─ { owner:乙妹, text:"看见老舟和阿苇打听旧火", valence:0, intensity:0.1, importance:4, about:[老舟,阿苇] }
```

## 4. 写入路径

1. **beat 事件提交(T2)**:每个 PlannedEvent 落 N 行记忆(参与者+旁观者),text/valence/intensity/importance/about 由生成方一并声明,**按 appraisal 路径出值**(先答"这件事对 owner 的目标意味着什么",再写数值,理由随行可审计);domain 校验:owner/about 引用存在、importance∈[1,10]、valence∈[-1,1]、text 非空。数值标错无法硬校验,防线见 §10.3(appraisal 理由、聚合稀释、三栏人审)。
2. **用户对话(每轮)**:同一路径。事件 text 含逐字对白;台词不校验真伪(撒谎合法),仅 ops 与记忆行走校验。对话期间该线**降速至真实时钟**(进入与恢复均提醒用户,用户已定);期间世界时间以 1× 推进,到期的 beat 事件与对话事件按世界时间交错提交;纯对话轮不重复携带世界快照,期间若有其他事件提交则照常携带。
3. **创世前史**:创世对话(用户与 AI 聊出设定)产出前史记忆种子,校验与 premise 一致;世界温启动。
4. **集体知识**:"全村都知道" = 一次写入 N 行(可带各人色),无组记忆概念。

## 5. 读取路径(prompt 组装)

**分层,裁剪次序写死**:

1. 世界状态:全量,永不裁剪;
2. 近窗:最近 12 条事件 verbatim,永不裁剪;
3. 检索:超预算先减检索条数 K(记审计)→ 仍超显式失败。

**检索公式**(权重可调,全部本地计算):

```
score = R + I + Rel × C
R   = exp(-ΔworldMinutes / τ)   衰减按世界时间;τ 随 intensity 增大(闪光灯效应:细节忘了屈辱感还在)
I   = importance
Rel = 实体图两跳命中(场景实体 → about 命中 → 该行 about 的实体 → 其高分记忆)
      实现用 SQLite FTS5 trigram(中文实体名)+ about 索引;零模型成本、确定性
C   = 心境一致性:记忆 valence 与 owner 当前对该 about 实体的关系极性同号则 >1,异号则 <1
      (带怨检索,怨色记忆浮起;善意沉底——动机性记忆)
      关系极性默认由该 owner 关于该实体的记忆 valence 聚合推导(民主汇总,个别错标被多数稀释);
      显式关系字段可选,仅作覆盖与认知失调检测
      （对标:Emotional RAG arXiv:2410.23041 用 Plutchik 8 维情绪向量做查询-记忆一致性打分,与语义分
        相加或先语义后情绪重排融合,实验证实情绪因子提升角色人格一致性;其自述局限=记忆情绪无个性化
        区分——我们的 owner 相对着色正是补这一刀,且不依赖 embedding）
```

**可见域**:检索限定 `owner ∈ 在场角色`;叙述层(两段式第二段)用作者可见域(反讽依赖)。

**L2 reflection**:**情境触发,非计数器**(2026-10-25 用户二次纠偏)。区分两件事:「触景生情」是检索——场景实体触发旧忆,每个 beat 的 prompt 组装天然发生,无需另做;reflection 是"如今的讲法"的重构,真实触发条件是四种:
1. **过去闯入现在**(主触发):本 beat 检索浮上来的旧忆权重足够重(高强度 × 距今久 = 旧事压进当下)——触景生情深到一定程度,人自然开始重述自己;计算:top 检索行的 intensity×(当前时间-atMinutes) 超阈值;
2. **叙事破裂**:新事件与该角色现行 L2 讲法冲突(认知失调);
3. **闲时**:夜间/独处/行走(世界状态可判定,确定性);
4. **被问及**:用户对话或他角问起过去。
重要度累计阈值(GA 的 sum≥150)降级为后台兜底网,不再是主触发。触发后从 L1 幂等重建,绝不由旧 L2 再摘要。

## 6. 对话系统(应用层)

- **角色对话** = beat 事件,既有模型,粒度为叙述级(非逐字剧本);
- **用户对话** = 同一事件模型、作者换成用户,逐轮提交,可从任意一轮 fork("如果我从第三句改口");
- **记忆问询面板** = 只读渲染某角色的 L1+L2+透镜,不入史不留记忆;兼任三栏对照与调试审计 UI;
- 想开口先存在:入世对话要求附身/化身(见 DISCUSSION-presence.md)。

## 7. Fork 语义

- 记忆行与 reflection 均 line 归属;fork 时按线物化,前缀共享;跨线隔离(原型 v2 已验证);
- 对话事件在 revision 链上,天然可 fork;两线各自的角色记忆从分岔点各自生长。

## 8. v1 最小集 / 后置项

**v1**:owner 分行存储、valence/intensity/importance/about 四字段、偏置检索公式、FTS5+两跳、reflection(节奏先用保守默认)、显式失败、对话事件(chat call kind,若在场模型定稿)。

**后置(按证据启用)**:再固化(情绪改写 L1,仅实验)、认知失调检测(存量立场 vs 记忆聚合)、embedding 语义检索、受控 agentic 检索轮、在场减速时间语义。
