## 要解决的问题

世界持续运转数周后，事件与记忆累积到 prompt 装不下。记忆系统的本质工作是**prompt 组装**：在每次 beat 调用里，用有界、相关、可审计的上下文装下"这个世界发生过什么"。

## 讨论中提出的想法（按讨论顺序，均未定）

1. **分层记忆**：L0 原始记忆不可变（唯一事实源）→ L1 世界状态全量 → L2 近窗 verbatim + 本地检索（SQLite FTS5 trigram，零模型成本、确定性）→ L3 编年摘要（可选，永远从原始日志幂等重建，绝不由旧摘要再摘要）。裁剪次序：先减检索条数（记审计）→ 显式失败，世界状态与近窗永不裁剪。
2. **反对 v1 用 agentic RAG 驱动检索**：预算（循环=多次调用）、可复现（prompt 重放调试漂移）、调度形态（批式非交互）、失败模式（模型不知道自己忘了什么，不会主动搜"三年前那场火"）。
3. **触景生情的实现方向**（回应"平时想不起来的，trigger 下会被提起"）：写入时标注 `about` 实体（生成记忆时模型顺手声明，比读取时猜测可靠）；读取时确定性两跳实体图展开（场景实体 → about 命中的记忆 → 该记忆标注的实体 → 其关键记忆）；"此刻哪条重要"由 beat 模型的注意力在单次调用内取舍。
4. **可见性作为管理对象**（用户提出，方向未定稿）：记忆携带 `knownBy`（属主）与 `about`；一切检索（含日后受控 agentic 轮）限制在"在场角色可见集"内，查询以场景角色身份执行；agentic 沙箱=轮数上限+每轮审计+失败下界是"想不起来"而非"知道不该知道的"。双可见域：角色可见域（事实与行为）vs 作者可见域（叙述，反讽依赖），可映射两段式提案。

## 尚未讨论的问题

- **显著性 vs 可见性**：可见性回答"能不能知道"，不回答"此刻值不值得想起"。触景生情的核心是显著性；写入时标注重要度、按角色当前情绪检索、还是信任模型注意力——未讨论。
- **记忆失真**：knownBy 是二值（知道/不知道），没有"记错了"。而误记、心结、事后重构恰恰是故事金矿。要不要支持失真记忆、怎么校验——未讨论。
- **集体知识**："全村都知道的事"在逐人枚举的 knownBy 里怎么表达？组实体还是别的机制——未讨论。
- **about 标注的可靠性**：写入时标错谁审计？domain 只能校验实体存在，不能校验标得对。
- **agentic 轮与预算调度的交互**、摘要触发条件——未讨论。

## 调研：学界与业界的公认做法（2026-10-25，仍属讨论材料非结论）

- **显著性的公认公式存在**：Generative Agents（Stanford，Park et al. 2023，引用 8700+）的记忆检索 = recency（按最近访问时间指数衰减）+ importance（写入时由 LLM 打 1–10 显著性分）+ relevance（与当前情境的相关性），加权求和；并有 **reflection** 机制（周期性把记忆合成为更高层的洞见，洞见本身再成为记忆）。我们讨论的"两跳实体图展开"在学术界对应 HippoRAG（NeurIPS 2024）：知识图 + Personalized PageRank 作为扩散激活，单步完成多跳联想检索；HippoRAG 2（ICML 2025）延续。我们方案相对公认做法缺两项：recency 衰减、写入时重要度分。
- **可见性的公认做法是结构分离**：Generative Agents 用 per-agent memory stream（每个 agent 只从自己的记忆流检索，可见性由构造保证）；BDI/ToM 研究线（EMNLP 2023 ToM 基准、CMU 2025 博士论文）同样 per-agent belief base。我们的"共享表 + knownBy 过滤"功能等价，但存储/共享与结构正确性之间存在权衡（fork 前缀共享偏向共享表，防泄漏与简洁偏向结构分离）——真实的设计取舍，待讨论。
- **集体知识无统一框架，游戏界有成熟先例**：Shadow of Mordor Nemesis 系统 = 派系级集体记忆（NPC 记住与玩家的互动并互相传播，是"世界活着"感的来源；注意有专利）。学术界用认知逻辑的 common knowledge 形式化；另有多智能体"曼德拉效应"研究（集体错误记忆在 MAS 中自发传播——集体知识若做，失真是要防的风险面）。
- **记忆失真作为特性：没有公认做法**。工程界把 agent 假记忆当漏洞研究（提示注入种植假记忆、视觉攻击污染长期记忆）；没有"为了戏剧性故意让角色记错"的公开实践。若做，方向是事实层（WorldState）与信念层（per-agent beliefs）分离，"假记忆"= 与事实层冲突的信念——但这是未验证的新设计。
- **工程框架格局**（供参考，Wispiva 不直接依赖）：MemGPT/Letta = OS 式分层记忆管理；Mem0 = 生产级记忆固化管线（ADD/UPDATE/DELETE 决策）；Zep = 时序知识图（双时序：事件时间 vs 摄入时间——我们的 revision 链天然具备这个骨架，worldTime vs 墙钟同构）。厂商基准数字（Mem0 vs Zep）有争议，只作格局参考。

## 情感透镜：偏见与有色眼镜（2026-10-25 讨论，未定）

用户提出：久远记忆更依靠情感；情感一旦形成就像有色眼镜，人是偏见的、非全知的。对应认知科学的**心境一致性记忆**（mood-congruent memory），且情绪偏置有三条路径（编码/固化/检索，与 Duke 2023 博士论文的三 routes 同名）。计算侧已有起步：Emotional RAG（arXiv 2024-10）在角色扮演 agent 中按情绪一致性加权检索——但做的是聊天角色扮演，不是持续世界模拟；跨周、跨线、fork 后偏见随线分岔的场景没人做过。

提出的"情感透镜"设计（三层，均未定）：
1. **编码时着色**：记忆天生是主观信念，不是客观日志。同一事件按每个 knower 当时对相关者的立场，写入带 owner 相对 valence（极性+强度）的不同记忆——"乙送礼物"在感激的甲与忌惮的丙处是两条不同色的记忆。WorldState 事实保持客观。这重新回答了"失真"问题：失真不是伪造事件，而是编码着色的自然结果（同一事实的多个主观版本）；此前"失真是无人区"的结论据此修正为"有 Emotional RAG 起步、世界模拟场景仍空白"。
2. **检索时偏置**：三因子改造——情绪强度高的记忆抵抗 recency 衰减（闪光灯效应：细节忘了屈辱感还在）；relevance 乘以与当前关系极性的对齐度（心境一致性加权）。纯代码、确定性、可复现、零调用——偏见不需要 agentic，与"agentic 触发、确定性执行"原则一致。
3. **回想时再固化（实验性，候选 v2）**：被带情绪回想的记忆可被 op 轻微改写（reconsolidation），眼镜随使用加深。风险=反馈螺旋（世仇自我强化烧穿故事）；闸门=reflection 节奏 + 预算 + LLM 侧反制力量（第三者的善意事件）。此层依赖失真讨论收敛。
4. **立场存哪（开放）**：显式（关系是 WorldState 字段，LLM 用 ops 修改，可投影可审计）vs 涌现（从该角色记忆的 valence 聚合推导）。倾向：显式为主，聚合做一致性检查——存量立场与记忆聚合不一致 = 认知失调，既是故事信号也是漂移警报，检测器零成本。
5. **读者全知**：偏见之所以成为戏剧，因为作者可见域让观众看见真相而角色看不见（反讽）。产品面：角色记忆视图并排展示同一事件的多方着色记忆，让偏见可检查。

尚未解决：valence 与 about 同样只有写入方能标注、存在标错风险；偏置是否需要上限（全恨无爱会毁故事）；再固化是否进 v1。

## 后来的回看与改口：三层记录（2026-10-25 讨论，未定）

用户追加：认知逐步提升后再想起旧事怎么办；人总是去回忆里找自己想要的证据（动机性记忆），同一人的过去可以有不同讲法。对应心理学：动机性推理 + [McAdams 叙事身份](https://journals.sagepub.com/doi/abs/10.1177/0963721413475622)（自我=不断重写的人生故事，重构过去以服务当下自我）。

提出的**三层记录**（未定）：
- **L0 事实层**：WorldState / revision 链，客观发生了什么。不可变。
- **L1 经验层**：raw memory（含编码时 valence），"当时的主观体验"。不可变（考古层）。
- **L2 叙事层**：reflection——"如今的自我对过去的讲法"。可版本化重写，即叙事身份的实现载体；"改说法"永远发生在 L2，L1 不动。
- 后来想起旧事 = 偏置检索取回 L1 + 以当下立场在 prompt 内解读（模型自然完成，零机制成本）；认知成长 = L2 随时间被新版本覆盖。
- **核心原则：编码与讲述之间的落差本身是故事资产**（reveal 场景："你当时根本不是这么说的"依赖 L1 存在）。覆盖原始记录即失去反转，因此 raw 永不重写，再固化降级为仅改 L2 或保持实验性。
- 产品面：三栏对照视图（事实 / 当时的体验 / 如今的讲法）；fork 协同——叙事层是分岔后差异最剧烈处（同事实、不同讲法），天然接多元宇宙差异高亮。

## 记忆按 owner 分行存储（2026-10-25 对话讨论导出，未定）

对话是至少涉及两人的事件，双方记忆有差异。机制结论：**一次对话 = 一个事件 + N 行记忆**，每个知情者（参与者与旁观者）各存一行，全部锚回同一 `sourceEventId`：各行的 text（各自的带色要点）、valence、about、importance 独立。后果：
- 三栏对照 = 按 sourceEventId join 出多方版本；
- 可见性墙退化为 `owner ∈ 在场角色` 的查询，不需要额外隔离机制；
- 事后显著性检索在各自行上跑，差异自然涌现。

**契约含义（并入 Q11 一并评审）**：`Memory.knownBy: string[]` 与"编码时着色"冲突（一份文本带不进每人情绪色），应改为每行记忆带 `owner`（单人），"谁知道什么"按 owner 查询。顺带解决集体知识问题："全村都知道" = 一次写入 N 行（可带各人色），无需组记忆概念。

记录边界精确版：世内对话（用户对话逐轮 + 角色对话按事件）全进历史；审计永远全记；记忆问询面板只留审计不留历史。

## 复杂度控制原则（讨论中的共识候选）

不建心理学，建**主观性的数据结构**：不可变事实、记忆归属与着色时间、当下立场、版本化叙事——结构归代码，心理学从模型租（LLM 读遍人类文学，解释与自欺是它的本能）。v1 只取三件便宜物：编码 valence、偏置检索、reflection；再固化/失调检测等把玩出证据再启用。与场景生成实验同一教训：代码管结构与校验，人味交给模型。
