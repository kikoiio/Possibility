# 任务：设计 Wispiva v1 架构

你是架构竞赛的候选者。请阅读 docs/architecture/GROUNDING.md 与 docs/requirements.md，然后产出一份**完整架构设计文档**（Markdown），写到本文件同目录下你自己的候选文件中（由调度方指定路径）。

## 必须覆盖

1. 技术栈选型（前端、引擎/服务、存储、LLM 接入）与理由。
2. 模块划分与数据流：世界时间推进、LLM beat 推演、世界线分岔（如果…）、事件 log、多线并行、双渲染投影、编辑器。
3. 核心数据模型（TypeScript 类型草图即可）：WorldLine、WorldState、EventLog、Fork/如果操作、LLM 调用记录。
4. 持久化策略：快照 vs 事件溯源混合；重启恢复；多世界线数据不爆炸。
5. LLM 层：provider 无关（OpenAI 兼容）、节拍配置、成本控制、完整审计（prompt/response/model/seed 记录）。
6. 本机运行形态与未来云自托管的迁移路径。
7. 分阶段落地顺序（每阶段可验证）。

## 硬约束

- 不引入固定行为规则内核（用户明确拒绝）。
- 世界状态是可整体阅读、可整体替换的**文档**（"改任何东西"），不是散落的表行。
- 2D 与 3D 渲染器只能消费同一份投影，不得各自拥有世界状态。
- 第一版聚焦单用户本机；多用户/鉴权不在范围。
- 依赖尽量少、可长期维护；避免云厂商锁定。
- 原型已验证机制，你的设计要能承接已验证概念（tick/beat/offsetMinutes/内容级 diff）。

## 输出格式

Markdown 文档，面向未来维护者。结尾附「Alternatives considered」：你考虑过并否决的至少 2 个整体形态，以及否决理由。
