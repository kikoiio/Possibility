# 世界表示设计草案

日期：2026-10-25
状态：**仅文档与计划，未冻结、未实现、未做实验**。用户本轮明确要求先讨论怎么做，不立即实现。本文提出可比较的候选与架构衔接方式，不新增正式契约、模块或运行路径。

需求与研究依据分别见 [DISCUSSION-world-model.md](DISCUSSION-world-model.md)、[WORLD-MODEL-RESEARCH.md](WORLD-MODEL-RESEARCH.md)。后续工作的顺序与收口条件见 [PLAN-world-representation.md](../PLAN-world-representation.md)。

## 1. 首先要回答的问题

世界表示决定哪些效应可以被表达、持续作用和检验。当前优先级是明确表示，再验证 Simulator 与 Verifier；规律自动积累和 RSI 后置。

这里的表示包括：世界中有哪些对象、状态、关系与过程；这些内容有什么含义；未知信息如何保留；变化依赖什么条件。JSON、图、自然语言或程序是承载方式，单独选择格式不能解决上述问题。

判断表示是否足够的工作标准：**若两个场景在表示上完全一样，却应产生不同的目标后果，表示就漏掉了需要保留的区别。** 目标后果的范围也必须明确，否则会无限增加属性。

## 2. 当前架构支持到哪里

以下为 2026-10-25 的静态源码核对，未执行集成验证。

| 部分与源码依据 | 当前可复用 | 尚未提供 |
| --- | --- | --- |
| [`WorldState` / `Entity`](../../packages/contract/src/index.ts) | 世界与实体允许开放 JSON 字段；稳定实体 ID 可作引用 | 属性含义、单位、未知值、过程与机制的统一语义 |
| [`applyOps` / `validateWorld` / `validatePlan`](../../packages/engine/src/domain/index.ts) | 纯函数修改、路径与部分引用/时序检查、逐事件演算 | 量纲、资源账目、因果前提、过程依赖与效应幅度验证 |
| [`Store.appendRevisions` / `transaction`](../../packages/engine/src/store/index.ts) | 世界快照、revision 父链、原子写入 | 环境语义校验；实验元数据的正式持久化设计 |
| [`Runtime.confirm`](../../packages/engine/src/runtime/index.ts) | 固定草稿基准，创建子线，子线 `plan: null`，保留父线 | 持续过程、候选效应、机制版本与角色观察的完整分岔规则 |
| [`sampleClock` / `dueEvents`](../../packages/engine/src/clock/index.ts) | 世界时间采样、整数分钟、计划事件到期查询 | 持续过程积分、重复推进防护、前提改变后的重新计算 |
| [`LlmGateway` / prompt 组装](../../packages/engine/src/llm/client.ts) | 可替换调用入口、跨线预算与调用审计 | 角色与环境的独立输入、表示专用输出与验证记录 |
| [`projectWorld`](../../packages/engine/src/projection/index.ts) | 从世界状态派生视图，稳定实体身份可复用 | 任意新环境属性的视觉呈现；新增字段不会自动产生视觉效果 |

结论：**数据承载、状态修改和历史基础可以复用；环境语义、输入边界与调度仍需设计。** 最早的表示实验可保持在现有开放字段与独立实验数据内；正式接入是否需要契约变更，要在实验后判断。

### 集成前必须核对的现有问题

这些问题不阻塞纸上设计，不能因为已有测试曾通过就忽略，也不在本轮修改：

1. **Schema 与路径解析不一致**：[`op.schema.json`](../../packages/contract/src/schemas/op.schema.json) 当前正则每段只匹配一个普通字符或一个转义 token，不能覆盖 `/entities/road` 这类常用路径；domain 解析支持普通多字符段。后续必须验证并统一，不能以绕过 Schema 作为实验成功。
2. **延迟结果可能过期**：`performChatTurn` 提交变化后未清除已有计划，`commitDueEvents` 只重新应用 ops，没有检查生成结果的因果前提。需要定义失效与重验。
3. **时间策略未收敛**：`tick` 在生成或错误状态也可推进世界钟；`generateBeat` 未比较返回时的当前世界时间；`toMinutes` 尚不驱动计划过期，空计划也不会自然清除。持续过程不能直接沿用未说明的时间语义。
4. **角色输入仍含完整世界**：[`assemble.ts`](../../packages/engine/src/llm/assemble.ts) 和 chat 路径都传入全量世界；按 owner 筛记忆不足以阻止客观隐藏事实泄漏。角色隔离与现有“全量世界入 prompt”设计的适用范围需要一起修订。
5. **fork 的角色上下文需复核**：`confirm` 没有物化父线既有记忆与 reflection，查询又按 line 过滤；共享历史进入祖先部分后的分页游标也需验证。若实验涉及角色认知，不能把这些行为当成已实现的继承保证。

## 3. 候选表示与选择顺序

| 候选 | 组织方式 | 值得比较的收益 | 主要代价 |
| --- | --- | --- | --- |
| A 属性快照与文字过程 | 沿用开放实体属性，单位、条件和过程由文字说明 | 基线简单，接近当前输入，创作自由 | 跨步引用、未知值、重复执行与验证依赖容易含混 |
| B 可扩展语义组件与显式过程 | 属性有定义、单位和信息状态；过程有身份、进度、依赖；机制另行声明 | 可检查、可继承、可扩展，适合比较持续效应 | 需要管理定义、版本和过程生命周期；模型表达负担可能增加 |
| C 可执行机制优先 | 用程序或规划语言表达状态转移，模型构造和修订机制 | 适合重复计算与强约束检查 | 程序正确性、执行边界、开放性及作者使用成本更高 |

建议先公平比较 A/B，保留 C 为后续路线。B 是优先研究候选，尚未选定。第一轮不能同时加入更强模型、额外机制知识与不同预算，再把收益全部归因于表示。

## 4. 候选 B 的语义组成

以下是概念划分，不是字段名或 Schema 定稿。

| 内容 | 最少需要表达 | 边界 |
| --- | --- | --- |
| 实体与关系 | 身份、类别、位置、组成、连接、归属等 | 事实只有一个权威位置；几何产物与索引只引用或派生 |
| 属性定义与量值 | 含义、数据类型、单位、适用对象、值域、来源 | 可扩展属性也要有定义；未知不能默认为 0、false 或不存在 |
| 持续过程 | 身份、作用对象、启停状态、开始时间、已推进到的时间、过程内部状态 | 正在发生的过程可成为事实；预测的未来后果仍是候选 |
| 机制与世界规律 | 适用条件、输入输出、参数、例外、版本、验证依据 | 机制声明与可执行实现分别判断；一次赞同不等于确立规律 |
| 候选变化 | 基准线/revision/时间/规律版本、读取依赖、效果、依据、未知项 | 经验证与提交前不成为事实；不可混入已提交快照伪装为已发生 |
| 角色观察与信念 | 感知内容、发生/观察时间、owner、传播依据 | 角色输入从可见事实及自身记忆构造；沿用 L0/L1/L2，角色信念不能覆盖环境事实 |

“信息未知”还要区分：系统尚未定义或观测这个量，与某角色不知道已经存在的事实。系统估计须标明依据，角色的误解仍属于其信念。模型自报 confidence 不能替代概率校准。

### 持续过程与一次事件的区别

以降雨为例，开始下雨可以是事件，持续降雨是过程，道路积水量是状态。某时刻预测道路将被淹是候选后果；到期前排水条件发生变化时应重新判断。

第一轮须能描述“从上次推进的世界时间到本次时间”的变化，说明同一区间如何避免重复执行、何时停止、前提变化后如何重算。是否采用固定步长或事件驱动尚未定；最早验证保持在现有整数分钟尺度。

### 表示扩展与历史

以后新增腐蚀等机制，可能需要材料、涂层或介质。扩展应声明新增概念及其适用范围，允许旧实体的相关量为未知；不能悄悄将后来推测写成历史事实。必要的默认值或估计应成为有来源的新声明。

## 5. 如何放进当前架构

最早可探索的承载位置是实体开放字段中的语义组件，以及世界根开放字段中的定义、过程和规律引用。具体是否采用 `components` / `simulation` 等命名留待 W1 收敛。

- **只存一次事实**：实体的量值不再在全局过程表复制一份；过程引用实体与属性。现有位置及尺寸字段先作为衔接基准，不另建竞争性的坐标事实源。
- **候选包独立**：现有 `Plan` / `PlannedEvent` 没有因果与验证字段，且 [Plan Schema](../../packages/contract/src/schemas/plan.schema.json) 禁止额外字段。早期实验以私有候选包持有这些信息，验证后翻译为现有 ops/事件；不能声称现有 Plan 已表达完整语义。
- **分层归属**：表示解析与纯语义检查归 domain 方向；模型层只组输入并返回 payload；runtime 负责编排、基准检查与事务；store 仍是唯一数据库入口。是否新建模块由后续集成结果决定。
- **验证记录可追踪**：原始调用审计可以复用；最终接受/拒绝、依赖与规律版本的记录方式另行设计，不能只保留模型给自己的解释。
- **视觉后置**：首先证明表示可表达、推演、检查和分岔。环境状态进入新画面效果时，再评估投影与 RendererView 变更。

### fork 与重启的语义候选

子线继承分岔时已经发生的状态与仍在持续的过程，并采用分岔时可追踪的规律版本；未提交的未来预测需要重新计算。这意味着“子线 `plan: null`”与“子线所有过程停止”是两回事。

机制或条件被“如果…”修改时，仅影响新线后续演化；原线和共享过去不被改写。重启从保存的事实与过程进度续跑，防止同一区间重复结算；历史读取不重新调用模型。尚须明确候选失效标记、进度提交与 revision 的事务关系。

## 6. 第一批纸上样例

首先选降雨、排水、道路运力、运输与库存这一条有限因果链。模型数值以明确声明的玩具规律为参考，检验表示与流程，不据此宣称水文或经济预测准确。

| 样例 | 必须能表达或区分 |
| --- | --- |
| 同雨量、不同排水条件 | 明确输入差异及其后果依据，不能仅因故事措辞变化产生差异 |
| 排水能力未知 | 保留未知，定位受阻推演；不得填 0 后继续当成事实 |
| 单位相异与不相容 | 说明换算；量纲冲突给出诊断 |
| 多步影响库存 | 运输中的资源、出入账与延迟都有位置，无关实体保持原状 |
| 预测后修好排水、或中途停雨 | 原条件失效，后果重验；过程不重复积分 |
| 过程进行中分岔/暂停/重启 | 进度与规律版本可追踪，父子线不串状态，暂停不凭空结算 |

再用干/湿木桌遇火这一不同领域的纸上例子，检查是否只为天气定制了概念。第二领域不扩展为本轮完整模拟目标。

## 7. 收敛前必须决定的事项

1. 第一批效应的粒度、时间尺度与“真实”的依据，哪些采用玩具设定、哪些需要现实数据。
2. 实体、关系、属性、过程与机制的最小划分，哪些信息必须显式，哪些仍用自然语言。
3. 未知量如何处理：可补信息、可估计的条件，以及哪些依赖效应必须暂缓。不能默认未知意味着全世界一律停止。
4. 规律的采用、修订与分岔权限，以及定义/机制的版本归属。
5. A/B 的共享事实、参考结果和比较指标，避免把额外知识误算为格式收益。

这些决定收敛后才进入表示原型；本轮没有新增实验代码、修复现有实现或运行模型。
