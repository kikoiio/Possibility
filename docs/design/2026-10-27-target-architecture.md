# Wispiva 目标架构方案

Wispiva 为 wisps of ideas 提供持续存在、演化和产生后果的 simulation infrastructure。本文件描述目标模块职责、数据与时间语义、主观记忆、展示和接口方案；产品目标见[需求](../intent.md)，当前统一体验入口见[主原型](../../prototypes/README.md)，已整合原几何实验与营地模拟。

项目处于原型验证阶段。模块划分、数据结构、接口与技术选型通过实验检验，再用于产品实现；本文的方案不代表已有运行系统或验证结论。独立原型可以采用适合实验的最小结构，保留其与产品约束的对应关系。

当前实验安排、进度证据与交接要求见[工作计划](../PLAN.md)。

## 1. 总体形态与模块边界

部署方案采用本机优先的单进程 Node.js 24 + TypeScript 引擎，通过 Hono 提供 HTTP/SSE 并托管 React/Vite 静态网页，使用 `node:sqlite` 持久化。云自托管运行同一进程并挂载数据目录；观看端使用 Three.js 渲染 3D。模型调用使用薄 fetch client，连接用户配置的 OpenAI 兼容服务。

| 模块 | 职责 | 依赖边界 |
| --- | --- | --- |
| contract | 跨模块类型、JSON Schema 与测试样例 | 不含运行时业务逻辑，不依赖 engine/web |
| domain | 纯状态演算、世界修改、候选与记忆的约束检查 | 只依赖 contract，无 I/O、LLM、时钟源或数据库 |
| store | SQLite 唯一入口，revision、事务、日志、记忆与 reflection 读写 | 可复用 domain 校验，不做故事或模型决策 |
| clock | 运行时间采样与到期计算 | 不直接写库或调用模型 |
| llm | gateway、权限化输入的 prompt 组装、模型回退、预算与调用审计 | 可引用 store API 类型，不 import domain、不打开数据库、不应用世界修改 |
| runtime | 调度、状态机、基准检查、事务与模块编排 | 不含 HTTP 细节；独立业务规则归 domain/llm/store |
| http | 请求、响应与 SSE 适配 | 薄 DTO 转换，不决定世界演化 |
| projection | 从世界事实派生轻量 view 与语义 scene | 纯函数，不读库、不依赖前端或 Three.js |
| web | 壳、编辑、对话、记忆展示与 3D | 经 API 修改世界；展示层不推演事实，渲染器不自行发请求或持有第二份世界真相 |

世界修改统一经过 ops/domain、revision 与 store 事务，不得绕过该路径使用私有 patch 或临时 SQL。runtime 负责调用顺序和提交边界，不承载与编排无关的大块业务规则。产品实现中字段定义与函数签名集中管理，本文件规定其职责和行为约束；跨模块接口变更遵循 §9。

### 客户端与引擎解耦

网页是首个客户端，移动端与桌面客户端可以接入同一引擎。引擎部署位置与客户端形态独立：本机引擎或自托管引擎均维护权威世界、时间、记忆与历史，客户端通过接口读取和操作世界。单进程托管网页是首版部署方式，不应成为引擎依赖网页的理由。

domain、runtime、clock、store 与 llm 不依赖浏览器、UI 框架、客户端生命周期或渲染器。设备输入、页面状态、3D 渲染及桌面系统集成归客户端；引擎启动、停止与数据目录归宿主运行层。不同客户端通过同一契约和事实提交路径操作世界，界面缓存与显示插值不能成为事实来源。

HTTP/SSE 是首版接入方式，传输适配不承载模拟规则。远端与多设备接入需要处理连接地址、认证授权、安全传输、断线重同步及并发修改的基准校验；这些能力沿用同一引擎，不为每端另建模拟实现。3D 场景语义与渲染实现分开，允许按设备调整画质和资源预算，保持世界事实一致。

客户端退出或断线不停止仍在运行的引擎；重连按 §9 同步权威状态，不补算断线期间的历史。本机引擎退出后的冻结与恢复遵循 §3。手机本地运行完整引擎需另行适配运行环境、存储和后台生命周期，不作为首版或多端接入的前提。

## 2. 世界状态、候选变化与事实提交

### 世界与历史

`WorldState` 是开放 JSON 文档，`entities` 为实体对象表；实体 key 是稳定身份，`kind` 为开放字符串。根与实体允许扩展字段。位置、尺寸及影响演化的其他客观状态属于 world；主观记忆与 reflection 独立保存。同一事实只有一个权威位置，索引、视图与几何产物引用或派生该事实。

`Op` 使用相对 world 根的 JSON Pointer。`set` 携带直接 JSON 值并要求父路径存在；`remove` 要求目标存在且禁止携带值。路径、引用和世界不变量由 domain 检查，非法修改整体拒绝，不留下部分应用结果。

`Revision` 保存事件、世界时间、父 revision 与完整 world 快照。每个历史节点都保存完整快照，包括无客观状态变化的纯对白轮；相邻快照内容可以相同。存储采用逐节点完整快照，不以共享快照引用替代。共同历史通过不可变 revision 父链共享，事件与 revision 身份用于判断共同前缀，不按文字相似度猜测。

开放容器负责承载数据，不能单独证明属性含义、单位、因果或过程正确。表示须保留目标后果所依赖的区别，区分客观状态、观察、信念、未知与预测。未知不能默认为 0、false 或不存在；估计与假设需要来源，扩展概念不能将推测倒填为历史事实。世界表示、机制与方法比较见[世界模型研究](../research/world-models.md)。

### 角色、Simulator 与 Verifier

角色的意图、认知与自主行为由 LLM Agent 负责，输入包含其处境、关系、观察和可见记忆。系统不以固定角色行为脚本或指定剧情强迫其选择。

环境 Simulator 负责环境自身演化、角色行动的实际后果与跨系统影响。角色提出意图和尝试，环境裁定实际发生什么；Simulator 不代替角色决定想做什么。后果须落实为状态与后续影响，不能只存在于叙述中。

Verifier 检查候选的状态合法性、机制依据和后果传播。程序承担可判定的结构、引用、单位、数量、资源、时间及冲突写检查；基于 LLM 的环境推演配合语义验证。模型赞同不能豁免硬约束，也不能代替现实依据或幻想世界的设定。Verifier 不承担剧情导演职责，角色的谎言与误解不因背离客观真值而被拒绝。

这些是职责边界，不要求每项职责各占一个模型、进程或一次调用。llm 层返回 payload；runtime 调度检查及预算内返修，domain 执行纯检查，store 提交事实。任何模型输出都无权自行写入世界。

### 原型已验证的知情边界

原型把以下关系分开处理：客观存在、角色已经知道、当前观察到、当前允许执行，以及角色对经历的主观记忆。地点连接只决定可达和可观察的地点集合；资源与行动可以用声明式 `visibility: { actors, clues }` 限制角色视图，行动还可以用 `performers` 限制执行者。检查线索后，`clue.discoveredBy` 使列出的资源或行动对该角色可见；隐藏实体仍留在客观世界并继续参与环境过程。

观察投影、角色决定校验和权威执行必须共用同一套可见性解析。隐藏行动的直接尝试返回不包含行动名、资源名、数量或阈值的通用失败。行动依赖的资源对角色不可见时，已知行动可以保留在观察中，但只返回 `executable: null` 和通用的“条件不可见”，不暴露隐藏前置条件；隐藏行动本身不进入可执行列表。作者级状态接口可以查看完整世界；角色输入和未来角色级接口必须使用角色范围投影，不能把作者视图当作角色观察。

创世候选在进入确认前还要经过隐私审计：同一角色投影用于检查作者级叙述、隐藏实体标识和其他角色私有字段是否越权，公开文字与私有目标／隐藏机制的片段重合只作为有限启发式拦截。审计结果和局限随草稿保存；它不能识别同义改写、暗示或后续上下文推理，因此不能替代权限化输入和持续观测。

这是当前原型的最小契约，不等于最终的知识账本。动态知情状态目前由世界内 `discoveredBy` 等可回放字段表达；产品实现应逐步把角色的长期知识、信念与记忆迁入独立的主体记录，并保持其来源指向客观 revision。信息边界的研究依据与本轮《红发会》实测见[世界模型研究](../research/world-models.md)和[记忆研究](../research/memory.md)。

### 候选到事实

推演围绕固定的世界线、revision、世界时间和适用条件生成候选。候选须能追溯读取依赖、所用机制依据、效果、未知项及验证诊断；这不要求将所有信息塞入同一个 DTO。

`Plan` / `PlannedEvent` 表达未来事件及其 ops、记忆增量和发生时间。接受计划不等于事件已经发生：runtime 先核对基准，domain 在副本上逐事件演算，整段检查通过后事务接受；事件到期且条件有效，才通过事务产生事实 revision。拒绝、丢弃与返修原因进入审计。

对话、干预或机制变化改变读取前提后，依赖该前提的预测必须失效或重验。到期提交前核对适用条件，不能仅因 ops 仍能执行就认定后果仍然成立。未受影响部分保持连续。补信息、估计与返修均受明确依据和预算约束；无法获得可用结果时按 §3 等待，不默认通过或无限重试。

因果依赖、机制版本与验证记录属于可扩展的模拟协议。跨模块增加这些数据须遵循 §9；实验可以使用独立候选结构，接入产品时应显式定义和检查通信契约，不以私有字段绕过契约约束。

## 3. 世界时间、等待与调度

每条世界线独立调速、暂停，默认 24×，即一真实小时对应二十四世界小时。clock 按可运行的真实时长与倍速采样，内部积累小数，持久化提交整数世界分钟；计时避免定时器漂移。世界分钟与墙钟 epoch 毫秒分开，预算窗口、请求超时与 `retryAt` 使用墙钟。

世界时间只推进到有可用推演结果支持、能够确定并兑现后果的时刻。无可用结果、预算不足或验证失败时，受影响世界线停在可确定时刻，显示等待及原因。等待期间不空跑世界钟，不积累等待时长，恢复时从保存的世界时间续跑，不补算等待区间。手动暂停、等待和进程退出都保留事实及过程进度；进程重启也不追赶离线时间。

已接受计划可以支持世界线继续运行，但仅限其依赖条件有效、验证支持且能兑现的范围。为后续范围生成结果时，不必撤销这一有效范围；达到其边界而没有可用后续结果，就进入等待。无效、被干预破坏或无法验证的预测不构成推进依据。不能仅凭未来事件列表、`toMinutes` 或空 `events` 推断任意时间内都没有后果；无事件区间同样需要推演支持。计划接受与到期提交均不能越过事实可确定的边界。

等待按世界线生效，不因一条线受阻就暂停其他有可用结果的线；同一线内也不能先将统一世界钟推进，再把受阻过程留给事后补账。持续过程以保存的进度为起点推进，同一区间不能重复结算。预算恢复、重试或返修获得有效结果后，runtime 重设真实时间采样基准，避免把等待时间计入运行时长。

调度路径为：确定基准与可推进范围 → 申请全局预算 → 权限化输入并组装上下文 → 生成候选 → 检查与有限返修 → 事务接受 → 在有效范围内计时 → 到期复核并事务提交 → SSE 通知。异步返回须重新核对基准与运行状态；暂停期间可以保存仍有效的候选，但不能推进世界时间或提交未来事实。过期结果不得改写事实。

## 4. 主观记忆

### 三层记录与写入

| 层 | 内容 | 保存与可变性 |
| --- | --- | --- |
| L0 客观事实 | revision、事件原文、ops、完整世界快照 | 不可变历史 |
| L1 当时经验 | 每个 owner 的带色记忆行 | 独立记忆表，原始经验不被后来的解释覆盖 |
| L2 如今讲法 | 角色的 reflection | 独立、版本化，从 L1 重建，不反复摘要旧 L2 |

一个事件可生成 N 行不同主观经验，每行只有一个 owner，共同锚回来源事件；集体知识也按人分行。记忆记录保留身份、拥有者、主观文本、相关对象、世界时间与来源事件，检索访问元数据由存储层维护。`valence` 表达 [-1,1] 的情绪极性，`intensity` 表达 [0,1] 的强度，`importance` 为 1–10 整数，`about` 为实体引用，可选 `emotion` 表达离散情绪标签。提交路径回填来源事件身份及存储元数据。

编码按 owner 的目标进行 appraisal：先解释“这件事对我意味着什么”，再产生主观要点与数值，保留可审查的理由。domain 检查引用、范围、空文本与结构；情绪解释是否恰当通过评价理由、记忆聚合和客观事实／当时经验／如今讲法三栏对照审查，不单独建设错标审计界面。

事件保存逐字对白及当次记忆增量，各人的主观要点留在各自记忆中。记忆与 reflection 不内嵌 world；每个对话 revision 仍按 §2 保存完整 world 快照。创世前史产生与世界设定一致的记忆种子，角色从已有经历开始生活。

### 可见域与预算组装

输入先按职责和主体权限构造，再计算预算。角色的 world、近窗事件、记忆、reflection 及其引用证据都限定在其知情范围；自身记忆和实际获得的观察可以包含误解，但隐藏事实、他人私有经历与未来预测不得从其他输入通道泄漏。按 owner 查记忆不能替代对整个输入的权限约束。多角色共同在场不等于彼此共享内心经验。

环境推演和作者叙述可以使用各自职责所需的全局域；全局信息不直接进入角色决策。作者观察与附身角色的知情范围分开。

在权限化上下文中保留世界状态与最近 12 条可见事件逐字原文，加入可见域内检索结果及对应 L2。超预算先减少检索条数 K 并记审计，仍不足则显式失败并按 §3 等待；不靠静默删除关键事实、缩短必需近窗或放宽权限来凑预算。权限选择发生在预算裁剪之前。

### 检索与反思

检索由本地确定性计算执行：

```text
score = R + I + Rel × C
R = exp(-ΔworldMinutes / τ)，intensity 越高，τ 越长
I = importance
Rel = FTS5 trigram 文本命中 + about 实体图两跳关联
C = 记忆 valence 与 owner 当前关系极性的一致性加权
```

`Rel` 从场景实体、记忆的 about 引用及其两跳关联中获取相关性；检索始终在授权集合内进行。关系极性默认由 owner 对相应实体的记忆聚合推导，同号提高一致性权重、异号降低；显式关系可作覆盖与失调检查。检索访问时间由 store 维护，衰减按世界时间计算，等待和离线时间不使记忆额外老化。

偏置不设系统上限，不自动投放反制事件；人物的偏执与和解由世界内经历发展。聚合可稀释个别错标，但不构成标注正确性的证明。

reflection 由情境触发：强烈旧忆闯入现在、当前事件与已有讲法产生叙事破裂、夜间／独处／行走等闲时、被问及过去。普通触景生情首先是检索，不必每次调用模型。旧忆强度与距今时间的乘积可作为第一类触发的阈值指标；累计重要度只作后台兜底。reflection 从授权 L1 重建并版本化保存，不覆盖原始经验。embedding、受控 agentic 检索、L1 再固化等方法的比较见[记忆研究](../research/memory.md)。

## 5. 创世、附身、对话与分岔

### 创世与编辑

用户与 AI 对话形成世界、人物过去及记忆种子，经过结构、引用、场景、运行和候选隐私检查后确认起源。编辑采用固定基准草稿、模型提议、差异预览与用户确认；模型不能跳过确认直接修改父线。隐私检查是可复用的有限审计，不是自然语言语义安全证明。

### 在场与追更

附身统一支持任意角色，长期使用同一身体只是使用方式，不设用户专属角色的特殊引擎路径。无人接管时角色照常自主活动。视角负责观察与交互身份，不能成为操纵剧情或授予角色全知信息的通道。

入世对话需要世界内身份，逐轮提交事件、保存逐字对白并生成各方主观记忆，支持从任意轮分岔。台词可以撒谎、误记和改口；客观修改及记忆结构依然接受检查。对话／实时交互进入前提醒该线降速至 1×，结束后恢复原速并提醒。1× 同样受 §3 的可推进边界约束，等待不积累时间。

到期事件与对话按世界时间和提交基准协调，不允许并发结果覆盖对方。交互改变计划读取前提时，按 §2 使相应预测失效或重验。只读记忆问询不入史，不制造新记忆。

缺席追更采用重要事件新闻播报，复用事件与记忆的重要度信息，并链接实际历史。摘要不能重新创造离开期间的事实。

### 固定基准 fork

创建 draft 固定 `baseRevisionId`、世界时间、speed/paused 与 world；父线在编辑期间按自身运行条件继续推进。确认在事务中创建 edit revision 与子线，新线从固定基准及改动出发，不继承基准之后的父线事件或未到期 Plan。

子线继承分岔点已发生的状态、持续过程进度、可追踪的规律依据、角色记忆与 reflection，此后按线隔离。未来预测按新条件重新评估；`plan: null` 不表示所有持续过程停止。机制与条件的修改只影响新线后续，不改写共享过去。记忆继承仅包含分岔点之前的经历，不能从编辑期间继续运行的父线导入后来的经验。

## 6. 3D 场景与投影

实时 3D 使用共享语义 `SceneDocument` 与确定性构造。solid 为主后端，voxel 为第二后端及编辑辅助视图，二者围绕相同世界与场景语义工作。生成、几何与视觉方法的比较见 [3D 研究](../research/3d-generation.md)。

位置、尺寸、朝向及影响模拟的空间参数属于 world 事实。`projectWorld` 从 world 派生两类输出：轻量 `RendererView` 供壳层总览、定位与连线使用；`SceneDocument` 供 3D 场景编译与渲染使用。view 与 scene 不是同一种结构，也不是第二个事实源。场景及几何缓存可重建，不能作为独立持久事实修改。

3D 渲染器只消费 scene 及其编译产物，不直接读写 world；壳层负责 API 交互与数据分发。scene 的跨 HTTP 形状纳入 §9 的通信契约，不能靠前后端私有约定绕过版本与消费者同步。共享场景语义及编译实现见[主原型场景文档](../../prototypes/geometry/scene-document.js)与[编译器](../../prototypes/geometry/scene-compiler.js)。

几何按 recipeHash 内容键做部件级增量重建，移除对象时释放对应资源。未知 kind 可进入 view.others，缺省几何用于降级显示；简单占位不能替代视觉质量要求。创世与局部编辑均经 ops/revision 后重投影，局部修订后执行完整结构与空间复检；生成返修受总预算限制。

3D 在观看端浏览器渲染，无人观看时服务端只推进世界，不持续渲染各条线。基本创世不依赖用户安装 Blender、CUDA 或下载大型模型权重，普通常驻服务不要求 GPU。场景构造任务与世界时间调度隔离并设资源预算。几何实验入口见 [Geometry Lab](../../prototypes/README.md)。

## 7. 持久化、事务与恢复

store 统一维护 lines、revisions、drafts、llm_calls、memories/FTS5 与 memory_reflections。每个 revision 独立保存完整 world，主观记忆独立存表，事件保留当次记忆增量与来源关联。

| 事务边界 | 原子完成的内容 |
| --- | --- |
| T1 接受推演 | 调用结果状态、接受的计划与线运行状态 |
| T2 提交事件 | 新 revision 及完整快照、记忆增量、相应过程进度、线 head/worldTime/plan |
| T3 确认分岔 | 删除 draft、edit revision 及完整快照、新线与分岔点记忆／reflection 继承 |
| T4 控制与配置 | 调速、暂停、重命名、重试等相应修改；配置写入遵循其持久化边界 |

事实、进度及决定接受该变化的验证依据须保持一致，不能出现世界状态已修改而过程进度或提交记录缺失的半个结果。日志分页沿不可变 revision 父链读取，跨祖先分页保留事件身份与顺序，不重复或漏掉共享历史。

恢复将未完成调用标记为失败，保留失败原因，不捏造结果；已接受计划保留后按其基准与依赖检查可用性。世界时间从保存的可确定时刻续接，等待与进程离线时长均不补算；持续过程不重复结算。读取历史使用保存的事件与快照，不重新调用模型。调用审计不自动删除。

容量评估需要采集完整快照大小、revision 频率和深 fork 链分页延迟。不以假定容量或固定父链深度预设压缩，也不通过修改存储方式削弱完整历史和上层接口语义。

## 8. 模型调用、预算与审计

模型 gateway 为推演、编辑和对话提供调用入口；角色、环境和验证职责共享模型调用基础设施。应用侧始终检查 payload；提供方结构化输出可辅助约束格式，不能替代 domain 与语义验证。模型层不 import domain，检查、返修与事实提交由 runtime 编排。

模型回退只在用户配置的候选列表内进行，对 404/429/503、retry-after、等待间隔与单次请求超时分别处理。请求失败、预算耗尽与校验失败明确区分，不生成占位故事来冒充结果。

按用户选择，当前不设应用侧 key 调用额度、程序总超时或输出 token 上限，额度由 key 管理方管理。使用流式 Responses，保留取消、调用审计和失败等待，不自动重试。调度仍需串行提交同一世界线的变化，避免并发覆盖；这是事实一致性要求，不是 key 配额。报告请求数、token、延迟与失败原因；服务端拒绝、截断或连接中断时，未通过的结果不能提交。未来若需要可选预算或返修策略，须由用户显式配置，不恢复固定的默认额度。

审计保留输入、每次尝试的模型、请求响应、状态、延迟、用量、失败或丢弃原因，以及候选接受／拒绝与基准、依赖和诊断的关联。审计用于追查，不等于允许角色读取所有调用内容。SSE 只推裁剪的 CallSummary，不广播完整 raw prompt。

API key 由本地配置或进程环境提供，不进入世界数据、数据库、调用请求审计或代码提交；本地配置文件限制访问权限，配置 API 只写不读。

## 9. 接口语义与变更协议

产品实现中的跨模块字段定义由 contract 统一维护类型、Schema 与测试样例，内部 store/gateway/clock 等函数签名归各模块管理。类型、Schema 与消费者应保持一致；文档中的职责要求不能作为实现或验证完成的证明。原型可以独立探索通信形状，集成时再统一契约。

`Minutes` 表达整数世界分钟，`EpochMs` 表达墙钟毫秒。版本位由跨模块封套管理，StateSnapshot/EditProposal 使用 `schemaVersion`；不由此推断所有 DTO 或 view 都有独立版本字段。`LogEntry` 是剔除 world 的历史输出版；完整 world 在草稿编辑等需要的场景按需传输，总览、日志与常规渲染不广播完整世界快照。这一传输约束不改变每个 revision 保存完整 world 的存储规则。

产品 HTTP 接口方案如下，原型只实现验证问题需要的入口。

| HTTP 入口 | 接口语义 |
| --- | --- |
| `GET /api/state` | 线元数据、轻量投影与近期日志，用于状态对齐 |
| `GET /api/lines/:id/log` | 沿 revision 父链分页读取历史，返回 LogEntry |
| `GET /api/events` | SSE 快照与线、revision、调用等增量；重连先全量对齐再消费增量 |
| `POST /api/settings` | 写模型与预算配置，密钥不回传 |
| `POST /api/draft` | 创建固定基准草稿，按需返回完整 world |
| `POST /api/edit` | 生成草稿修改提议与可读差异，不直接改变父线 |
| `POST /api/confirm` | 确认提议，事务创建 edit revision 与子线 |
| `POST /api/control` | 调速、暂停、重命名与重试等线级控制 |
| `POST /api/chat` | 入世对话，验证后逐轮提交事件与记忆 |
| `POST /api/presence` | 设置或清除该线附身身份 |
| `GET /api/lines/:id/digest` | 从实际历史生成重要事件播报条目 |

附身视角、降速提醒、等待原因与场景传输属于跨模块通信，随对应 DTO/SSE 一起维护；不得只在 runtime 或网页一侧添加隐含字段。网络可见的数据与模型输入分别遵守其权限边界，作者的全局观察权限不自动赋予角色。

契约改动独立成 PR，不与消费实现混杂；同步 Schema、fixtures、受影响消费者与并行任务约定。v1 默认 additive 演进；字段改名、删除、可选性收紧或语义改变视为破坏性变更，一次对齐所有消费者，避免长期双版本。通信形状由 contract 管理，WorldState 内部不变量由 domain 管理；环境候选与验证协议扩展同样遵循这一边界。

### 2026-10-27 原型架构实测：案件主题与渲染边界

《红发会》重做验证了一个实际边界：案件主题应由世界定义、场景文档和壳层视觉共同表达，但不能让 UI 另建一套世界事实。当前页面直接读取已有 `world`、`activity`、`scene` 和 SSE 状态；“红发会、当铺、地下室、银行”的标题、时间线、资源标签和三维地点都来自同一份起点存档。

三维渲染的浏览器 URL 与源码文件路径不等价。原型曾把 `world-scene.js` 的动态模块写成源码相对路径，浏览器因此请求了不存在的 `/prototypes/geometry/*`，页面仍保留可用文字但场景为空。修复为服务暴露的 `/geometry/*` 入口后，Three.js 画布、资源标签和场景编译均恢复。这说明静态资源路由必须和模块消费者一起做 HTTP 冒烟，不能只用 Node 的 import 检查。

红发会场景还暴露了取景的产品约束：按支撑岛屿半径取景会让三个小房间在大面积地面中缩成一团。把地点位置、房间边界和地形半径作为同一份场景文档的可验证事实，再以内容包围盒取景并在默认镜头中缩短距离，能让观察对象成为画面主角。缩小地形不能越过房间支撑和角色绑定检查；本次调整后候选仍通过世界、空间、几何和运行校验。

视觉层可以更换色板、版式和案件文案，不应改变事实提交、角色观察或动作权限。当前截图验证了这一点：UI 重做只改 `prototypes/ui/`，红发会夹具只补充场景布局和陈设，角色级秘密、过程阈值和动作执行边界仍由同一套运行时检查。
