# 创建起源与受控资源的版本化集成契约

状态：设计提案，2026-10-29。本文的“必须”规定待实现的 v1 契约，不表示已经实现或通过验收。范围是一个 `WorldStore`、一个进程内的单写入者，以及受控隔离区域上的假引擎；不声明 Luanti 落盘、真实角色、记忆检索、空间通行或生产级恢复能力。依据 [实施计划](../PLAN.md) 与 [静态集成审查](2026-10-29-origin-integration-audit.md)。

## 当前事实与设计选择

现有 `genesis/store.py` 把确认草稿投影为首事件 `genesis.created` 和包含地点、布局及角色目标、记忆种子的快照；事件本身只有草稿引用和摘要。现有 `world/reconcile.py` 则要求空库、首事件 `resource.init`、固定的资源专用快照，并拒绝其他事件。`world/store.py` 同库原子提交一个事件、完整替换快照和时钟，按版本与请求去重；它不自动验证业务事件的语义，也不能原子提交引擎状态。假引擎协调器已有身份检查、资源历史对账及未知值拒绝；这些能力还没有与起源集成。

比较过两个形状：独立起源库与资源库需要跨库提交、恢复及角色映射协调；单库统一事件流则可利用现有单库事务，代价是必须修改协调器的历史重放和快照处理。v1 选择后者，保留现有存储的事件外壳；资源分区由协调器管理，起源和私有角色分区由统一应用层保留。不可通过把旧快照覆盖成资源快照来接入。以下接口、数据和状态机均为目标。

## 身份、空间与所有权

- `world_id` 是创建时由调用方生成并持久保存的随机 UUID（规范小写 UUID 字符串），全球范围不复用。创建请求、起源、每个事件、快照及假引擎独立身份均须相等；空值、无效值、读取失败或不匹配，在任何投影或提交前拒绝。假引擎身份由独立持久化的测试夹具提供，不从待验证的数据库或请求参数回显。随机生成本身不能证明全球唯一；创建者负责防止已知 ID 重用。
- 草稿 `actor.id` 是世界内稳定 `character_id`；连同 `world_id` 唯一标识角色。起源一次性分配正整数 `runtime_id`，从 1 开始按确认时 ID 字典序分配，映射作为起源数据持久化；此后只读持久映射，不根据名单重新排序计算，不复用数字。v1 不支持增删角色；恢复必须验证映射双射、ID 和范围。引擎库存键使用 `character_id`，数字只供未来适配器使用。
- `place_id` 沿用确认草稿的地点 ID，世界内唯一；连接及角色起始地点必须引用有效地点。语义网格与实际节点坐标是不同空间。v1 的资源 `node_key` 采用 `x,y,z` 三个规范十进制整数、逗号分隔，无空格、前导零或负零；坐标系名固定 `fake-grid-v1`，整数表示假引擎节点位置。资源登记显式给出节点，不从地点网格推算可通行几何。相同规范化坐标不得重复。
- 数据库中的已提交事件和快照是受控资源目标的权威；假引擎是可验证的投影。调用方负责独占写入、冻结区域及隔离全部投影读者，从初始化前到对账完成及每次提交投影完成均须维持。若不能保证排他，拒绝启动。假引擎单进程锁只是测试前提，不证明真实世界排他。

## 数据、版本与事件

`WorldStore` 的 SQLite `user_version=1` 是存储格式版本，`version` 是连续递增的提交序号；二者不等于本契约版本。v1 保持 `commit(event, expected_version, world, characters, elapsed=0, paused=None)` 的外壳：事件严格为 `{id, type, data}`，契约元数据放入 `data`。事件 ID 为非空字符串，在该世界的整个日志中唯一；每项事件 `data` 都有整数 `contract_version: 1` 和 `world_id`。所有对象是有限 JSON，字段未列为可选即必填；v1 禁止未知字段、未知事件类型及未知版本，避免静默丢失语义。存储库结构未改变不等于旧协调器可读取新数据。

按顺序只能出现一次 `genesis.created`、一次 `resource.registered`，随后零个或多个 `resource.change`；前者提交版本 1，登记提交版本 2。日志的记录版本就是事件序号；每次提交的 `expected_version` 为上一版本。各事件的 `data` 精确结构如下（示意中的 `…` 代表下文定义的完整值，不是可省略字段）：

```json
{"id":"create-1","type":"genesis.created","data":{
  "contract_version":1,"world_id":"<uuid>",
  "draft_id":"<id>","draft_revision":1,"draft_sha256":"<sha256>",
  "origin": {"draft": {"schemaVersion":1,"title":"…","description":"…",
    "places":[],"actors":[],"memories":[],"rules":[],"layout":{"places":[],"connections":[]}},
    "runtime_ids":{"<character_id>":1},"coordinate_system":"fake-grid-v1"}
}}
{"id":"register-1","type":"resource.registered","data":{
  "contract_version":1,"world_id":"<uuid>","origin_event_id":"create-1",
  "nodes":{"0,0,0":"ore"},"initial_nodes":{"0,0,0":"ore"},
  "initial_inventories":{"<character_id>":{}}
}}
{"id":"change-1","type":"resource.change","data":{
  "contract_version":1,"world_id":"<uuid>","kind":"gather",
  "node":"0,0,0","character":"<character_id>"
}}
```

起源 `draft` 是通过现有草稿校验且经用户确认的完整原始内容，按其 `schemaVersion` 保留全部字段，包括规则和私有记忆；不能只保存摘要或公开视图。v1 额外要求至少一个角色，才能满足资源协调器的登记前提。示例中的空数组仅说明形状，不代表满足草稿校验。`draft_revision` 是确认的正整数版本；摘要为确认草稿的 UTF-8 JSON，使用 `genesis/store.py` 的 `_encode`（键排序、紧凑分隔、`ensure_ascii=False`）后 SHA-256 小写十六进制；重放时重新计算。`draft_id`、revision、摘要、确认操作 ID 必须在持久创建请求中绑定，不能对另一修订复用。起源载荷含私密数据，事件日志和备份不能作为公共观察或普通角色上下文直接暴露。

登记 `nodes` 是非空映射：节点到非空资源名，资源名不得为 `air`；`initial_nodes` 的键集必须相同，每项只能是对应资源名或 `air`。`initial_inventories` 的键集恰为全部起源角色；每个库存仅含登记资源名，数量为 1 至 2147483647 的整数，零数量不存键。登记仅一次，不动态扩容。`change` 只支持现有语义：`gather` 要求节点为登记资源且库存不溢出，置 `air` 并加一；`build` 要求节点为 `air` 且库存至少一，放回登记资源并减一，零时删除键。非法引用、前提失败及溢出拒绝，不能记录为成功。事件必须在真实数据库事务中连同其结果快照一起提交。

快照为完整替换值，建议精确形状如下；没有登记时 `resources` 为 `null`、各 `inventory` 为 `null`，登记后为对象。`clock` 仍由 `WorldStore` 管理，不放进 `world`：

```text
world = {contract_version: 1, world_id, origin_event_id,
         origin: <genesis.created.data.origin>,
         resources: null | {registration: <nodes>, nodes: <current_nodes>}}
characters = {character_id: {runtime_id, name, role, goal, place_id,
                              memory_seeds: [{seed_id, text, source}],
                              inventory: null | <inventory>}}
clock = {time: 0, paused: true}
```

角色字段从确认草稿确定性派生；每条记忆种子按该角色在原始 `memories` 数组中的顺序从 0 编号，`seed_id` 为 `origin_event_id + ":seed:" + character_id + ":" + 十进制序号`，`source` 精确为 `{event_id: origin_event_id, kind: "genesis.seed"}`。种子只属于对应角色，文本即原文；它是私有起始材料，不宣称已导入 L1 或证明其真实性。其他角色和公共投影不可见；服务端输出采用显式字段白名单，作者视图必须经过单独授权。公开描述可能含敏感文本，结构过滤不能替代语义审查。

每次业务提交必须从最新完整状态复制并仅修改所属分区，保留所有未变的起源、角色字段及私有数据。重放器从起源事件重建完整快照，再依序应用登记与变化，验证引用、规则、身份和最终快照深度相等；不能只用最后一条全量快照代替业务重放。v1 所有提交 `elapsed=0` 且 `paused` 不变，时间始终为暂停的零；不接入引擎时间、离线补算或运行时记忆。若已有非零时钟或其他事件，拒绝 v1 恢复。

## 创建、登记及调用契约

以下为待实现的调用形状，非现有 API：

```text
create_origin(store, engine, world_id, operation_id, confirmed_draft_ref) -> {version: 1, event_id}
register_resources(store, engine, world_id, operation_id, nodes, initial_nodes, initial_inventories) -> {version: 2, event_id}
apply_resource(store, engine, world_id, operation_id, expected_version, kind, node, character) -> {version, event_id}
open_and_reconcile(store, engine, world_id) -> {phase, version}
```

1. 创建者持久保存世界 ID、确认引用及操作 ID；取得排他并冻结假引擎。检查全新空库版本 0、草稿确认及修订和摘要、草稿全部引用与映射、假引擎独立 ID，然后在单库事务提交起源事件及完整起源快照。此时状态为 `ORIGIN_ONLY`，无资源动作可执行。
2. 登记先核对身份、起源、注册集合和初始值，再读取全部假引擎节点及库存，要求与调用者给出的初始值完全一致；不通过则不写引擎或数据库。以版本 1 原子提交登记事件及包含库存的完整快照，随后完整对账。只有对账成功才进入 `READY`。
3. 每个资源动作在 `READY` 中先冻结并撤销 ready，验证身份、重放历史及现有投影与最新快照完全一致，按 `expected_version` 检查并计算新快照，原子提交后投影并回读。全部回读一致才返回成功并重新开放。数据库提交成功但投影未完成时，返回“已提交、投影待恢复”或明确的未知提交结果，不得报告动作已完全完成；保持冻结。
4. 外部操作 ID 和完整原始请求（包括世界、类型、载荷及首次的 expected version）在重试期间固定。同 ID 同请求返回原提交版本，并在返回完成前重新对账；同 ID 不同请求为冲突，不追加事件。对已提交操作的去重必须先于最新版本检查；不同 ID 的过期 `expected_version` 不提交，调用方读取最新状态后作新的业务决定并使用新的 ID。不得把同一 ID 换参数重试。为适配现有 `WorldStore.commit` 对完整请求字节的比较，集成层须保存或重建首次完整提交请求；不能用当前快照或新 expected version 直接重试底层 commit。

## 恢复与失败边界

打开时从 `CLOSED` 进入 `FROZEN`，先检查独占、请求／数据库／假引擎身份、存储完整性、版本及全量业务重放。空库是未创建；仅有合法起源返回 `ORIGIN_ONLY`，等待原登记请求或明确的首次登记；任何其他缺失、乱序、重复、未知版本、损坏或快照不一致均停在冻结状态。严禁为了通过恢复而重建起源或覆盖数据库。

已登记时，先读取全部注册节点和库存并完成全局预检：每项的当前值必须等于该项在已提交历史中出现过的值（含初值）。读取失败、无效值或未知值导致零修复写入并保持冻结；不能把不可读取伪装成 `air` 或空库存。预检通过后将各项写到最新提交目标，每次检查世界身份、写入结果并立即回读；完成后再次读取全部项，与目标逐项比较，成功才为 `READY`。历史值可接受仅因为排他假设，不能证明值一定是本协调器写入。写入异常、返回 `False`、回读不符、身份变化或最终复核失败均保持冻结；可能已有部分投影写入，排除故障后从头预检重试，不能回滚已提交事件或开放部分状态。

崩溃窗口的预期：事务前失败不产生事件；数据库事务中断由存储恢复为提交前或完整提交后，调用方用原操作 ID 查询结果；提交后、任何一项投影写入前或写入中崩溃，重启按历史预检并对账；最终读回后但答复前崩溃，同 ID 重试返回原结果且不重复资源变化。假引擎须提供可跨测试重启的独立状态和故障注入；这里的重启验证只证明测试夹具的持久模型，不证明真实引擎写盘。

备份／恢复须在冻结状态取得同一提交点的数据库和假引擎身份及投影，恢复后保留 `world_id`，先完整对账。禁止让原件与恢复副本同时作为同一世界的可写实例；未能保证单写入者则不能开放。克隆是新世界：分配新 ID，生成新的起源及映射和新的事件 ID，并在受控新假引擎上登记；它不复制旧日志为新世界日志，也不暗示继承历史或记忆来源。若需要保留分叉历史，另行设计版本化血缘契约，v1 不支持。

## 兼容与迁移

新建 v1 世界使用上述事件序列；当前创建器和当前资源协调器都不能直接读写该序列，需共同改造、增加业务重放与分区保留，并保持 `WorldStore` 事务边界。旧的仅起源库缺少世界 ID，旧 `resource.init` 库缺少起源；即使存储 schema 同为 1，也不能自动升级、猜测身份或拼接日志。默认只读拒绝作为 v1 打开；如果要迁移，须另定可审计的离线迁移工具、来源与 ID 绑定、私有字段保全、原数据备份和验收，本文不授权或声称已实现迁移。未知契约版本、事件、字段或不支持的草稿版本一律拒绝，不忽略后继续写入。未来升级须定义显式版本转换及重放规则，成功验证后才允许写入。

## 假引擎验收矩阵（待实现、待运行）

所有用例均使用独立读取身份、排他冻结、可持久重启和可注入失败的假引擎，断言数据库事件、完整快照、投影及返回状态；这些是验收要求，不是现有通过记录。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 确认草稿创建并登记 | 序号 1、2 连续，字段及摘要可重放；地点、布局、规则、每人目标和种子原文完整保留；登记与假引擎初值一致后 ready。 |
| 稳定身份 | 重排草稿输入或重启后读取已保存映射不变；重复角色 ID、数字冲突、无效地点或空间键拒绝，绝不部分创建。 |
| 知情隔离 | 两人有不同种子，分别获取仅本人授权投影；公共与第三人视图不含其他人种子、目标及原始私有事件，来源 ID 在重启后不变。公开文本泄密须作为独立语义审查问题报告。 |
| 同 ID 重试和冲突 | 起源、登记、变化各在提交后答复丢失时重试，原版本只出现一次；同 ID 改载荷或世界拒绝；不同 ID 的过期版本不追加。 |
| 前提及身份失败 | 非空库、登记不匹配、非法库存、资源动作前提失败，或请求／数据库／引擎 ID 缺失、不匹配，均不发生不应有的提交或投影写入。 |
| 崩溃及部分投影 | 在事务前、事务中、提交后、每个节点／库存写入前后、最终回读前后分别注入失败并重启；已提交事实仅一次，已知旧值收敛到目标，失败期间保持冻结。 |
| 未知与读取失败 | 任一节点或库存未知、读取报错或身份变化时不开放；预检阶段任何一项未知时所有修复写入数为零。投影途中失败允许已有部分写入，但重启须重新全局预检。 |
| 篡改与兼容 | 缺事件、序号断裂、快照／历史不符、重复登记、未知版本／字段／类型、旧起源或旧资源库、非零时钟均拒绝，不自动改写。 |
| 备份与克隆 | 冻结备份恢复保留身份和状态并先对账；克隆具有新身份和新事件，旧假引擎不能用于新世界；无法确保独占时不开放。 |

单元与故障注入通过后才可称假引擎契约已验证；Luanti 适配、实际地图独立身份及持久化、排他和落盘崩溃验证仍须按审查中的后续顺序单独完成。
