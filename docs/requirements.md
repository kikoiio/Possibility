# Wispiva 需求基线

日期：2026-10-25
状态：基线已确认，正在补充创世、视觉与环境模拟需求。2026-10-25 根据用户提供的分享讨论补充世界模型方向；具体表示、验证器与调度方案仍待讨论。

## 1. 产品定位

Wispiva 是第一用户（作者本人）的平行世界模拟器。核心乐趣是：模拟事件 → 观察结果 → 改条件 → 看世界变成什么样，像改写小说的平行世界。

成功标准是"好玩、满足幻想与好奇心"，不服务其他假设用户。

## 2. 世界与时间

- 世界持续运转，时间与真实时钟耦合（真实时间耦合模式）。
- 倍速按世界时间/真实时间定义：默认 24×，即 1 真实小时 = 24 世界小时（1 世界小时/2.5 真实分钟）；可加速、可随时暂停。
- 用户离开观看的平行世界继续运转；回来时可回查"离开期间发生了什么"的 log。

## 3. 世界线与多元宇宙

术语体系：

- **世界线**：一条持续运转的世界；初始线默认命名**α线**，分岔线按 β、γ…编号，可随时改名。
- **如果…**：开辟动作。用户修改任意条件并提出一个"如果"，点击「确认」后生成新世界线（内部实现可沿用 fork 概念）。
- **多元宇宙**：所有世界线的整体与总览视图；支持同屏对照，共同历史交汇、分岔后各自延展。

- 任意时刻可发起"如果…"。
- 用户可自由修改任何东西：角色、事件、世界设定皆可；支持一次批量修改多项。
- 用户点击「确认」后，生成一条修改后的新世界线继续运行；原世界线不受影响。
- 所有世界线持续运转，随时切换观看与对照。

## 4. 事件引擎与环境模拟

- 角色的意图、认知与自主行为由 LLM Agent 负责，不预设固定行为脚本；输入应携带其现状、关系、观察与可见记忆。
- 世界模型承担环境 Simulator 的职责：推演环境自身的演化、角色行动的实际后果与跨系统的复杂效应，让影响落实到持续的世界状态。
- 优先探索文本与结构化数据表示、基于 LLM 的 Simulator，并加入 Verifier 检查候选变化。表示协议、确定性约束、因果与动力学审查的具体组合尚未选定。
- Simulator 不替角色决定意图；模型提出的变化通过验证与引擎提交后才成为事实。状态一致性与世界约束可由确定性代码保障，旧版“纯 LLM”表述不再排除这类验证。
- LLM 调用节拍与成本上限由用户自行配置；角色、环境推演与验证共享总预算。

需求来源、现有实现差距、研究入口与开放问题见[世界模型讨论](architecture/DISCUSSION-world-model.md)。规律自动积累、因果图、微调和专用模型训练仍为研究建议，未列为第一版必需。

### 待原型验证的假设

模型非确定性下，fork 对比是否依然"好玩"——差异来自用户的修改还是模型随机性，仍需验证。环境模拟还需对照多步状态一致性、因果传播、验证误判与总调用成本。固定种子、混合模拟内核和规律学习的采用方式尚未确定，不能仅凭结构校验通过认定模拟可信。

## 5. 呈现

- 观看必须是实时的 3D 画面，不再要求独立 2D 模式。
- 好看与有吸引力是核心体验要求，不能用简单几何占位或文字补白代替视觉质量验收。
- 完整历史 log：随时回查任何一条世界线发生了什么。
- 多元宇宙支持多线同屏对照：共同历史交汇，分岔后各自延展，差异高亮。

## 6. 世界创建

- 带 LLM 的编辑器：用于创建和编辑世界与角色的初始设定。
- 用户通过文本表达想要的世界，由接入的模型参与构造 3D 内容。多模态模型也可参与创建与检查，具体方案仍在调研。
- 系统提供结构化表达与语义工具，降低生成难度。创建自由度不能仅依赖预制成品资产的数量，具体几何表示尚未确定。

## 7. 运行与部署

- 默认本机运行：进程不在则世界冻结。
- 架构支持自托管云服务器实现 7×24 常驻（用户自己配服务器，或付费由作者部署）。
- 云端常驻是可选部署形态，不是第一版必需。
