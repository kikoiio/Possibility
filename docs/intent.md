# Wispiva 项目意图与产品需求

当前工作进度与交接入口见[工作计划](PLAN.md)。

## 1. 核心概念：wisps of ideas

**Wisp 是一缕想法，Wispiva 为想法提供能够生存和演化的世界。**

一个 Wisp 可以是人物、地方、世界设定、关系、规律或问题，不限定为自主角色或灵体。这个概念描述创作的起点，不预设数据结构，也不要求每个想法都对应一个模拟实体。

想法可以从模糊、不完整的状态开始。例如“一座建在巨兽背上的城市”，最初不必已经定义好所有细节。Wispiva 需要帮助想法逐步具体化，形成能够持续演化的世界，同时保留已确立的事实与规律。

第一用户是作者本人。目的在于让想法活起来，满足幻想、好奇心和探索欲；不为假设的其他用户增加需求，也不规定所有想法都必须成为同一种游戏。

## 2. 产品核心：simulation infrastructure

**做好模拟是当前首要、最核心的任务。** Wispiva 提供让世界持续存在、演化和产生后果的基础设施。环境、对象及其关系构成世界；当想法涉及生命或行动主体时，它们的行动、认知与记忆也属于模拟。

| 基础能力 | 要满足的需要 |
| --- | --- |
| 存在 | 想法能形成有含义的对象、环境、关系与规律，保留对演化有影响的区别 |
| 持续 | 世界具有连续的状态、时间与历史，已发生的事和进行中的过程不会无故消失或重置 |
| 演化 | 环境能够变化；存在行动主体时，它们能够形成意图、行动并相互影响，世界不依赖用户逐轮指定剧情 |
| 后果 | 变化和行动落实为实际状态，影响相关对象与后续过程；尝试不等于成功 |
| 经历 | 过去影响现在；涉及认知与记忆时，经历通过主体实际获得的信息影响后续判断与行为 |
| 可检查 | 能够读取并核对状态、变化与相关依据，判断模拟是否正确，暴露未知与失败 |

用户可以只创造一个世界并让它演化。改变条件、观察对照和探索平行宇宙是与世界相处的玩法，不要求每次使用都经历同一循环。模拟的检查能力与实时 3D 体验分别验证。

## 3. 模拟质量

“足够真实”围绕所模拟的现象、世界设定及其后果判断。现实世界模拟需要相应依据；幻想世界也需要遵守自身确立的规律与例外。覆盖范围、简化假设与能力限制应明确可见。

| 质量 | 要求与验证方向 |
| --- | --- |
| 连续性 | 多步演化保留对象身份、状态与过程进度；已发生变化继续影响后续世界 |
| 因果与传播 | 变化依据当时条件发生，并传播到相关对象；无关对象不无故改变，重要后果不能只存在于叙述中 |
| 规律一致性 | 数量、资源、时间、空间与机制按该世界的设定成立；例外有依据，不能每轮随意更换规则 |
| 主体自主性 | 存在行动主体时，其行为联系自身处境、认知、动机与经历；系统不为指定剧情强迫其决定 |
| 信息边界 | 区分客观事实、观察、信念、未知与预测；主体不会凭空知道秘密、他人经历或未来 |
| 条件响应 | 影响演化的条件变化后，依赖它的后果随之调整；已失效的预测不能强行发生，未受影响部分保持连续 |
| 不确定性 | 缺少前提时能指出缺口，区分假设、估计与事实，不把未知默认为零或凭空补成确定事实 |
| 可追查性 | 能检查状态如何变化、相关条件与依据；历史读取不重新生成已发生的结果 |
| 可持续性 | 在明确的资源与调用预算内运行；失败、等待与成本可见，不能通过无限重试或增加调用掩盖问题 |

真实度不按属性数量、文字生动程度或画面细节衡量。如果两个局面应当产生不同后果，模拟就要能够表达并使用造成区别的条件。允许以有限范围开始，再根据证据扩大覆盖。

涉及主观经验时，人物可以误解、撒谎、自欺和改口。主观说法不能覆盖客观历史，系统也不通过自动投放事件来纠正人物立场或追求戏剧效果。角色的记忆影响其判断与行动，客观事实、当时经验与如今讲法分别保留。

## 4. 自主角色、环境后果与验证

角色的意图、认知与自主行为由 LLM Agent 负责，不靠固定行为脚本。输入需要提供其处境、关系、观察与可见记忆，保持角色知情范围。角色的目标与经历影响其选择，系统不为指定剧情强迫其行动。

环境 Simulator 负责环境自身演化、角色行动的实际后果与跨系统影响。角色提出意图和尝试，环境裁定实际发生什么；Simulator 不替角色决定想做什么。后果落实为持续状态，不能只停留在叙述里。

模型提出的候选变化需要验证，再由引擎提交为事实。基于 LLM 的 Simulator 需要 Verifier；确定性代码可以保障结构、引用、数量等约束，不能以“纯 LLM”为理由排除检查。

职责分开不要求每种职责分别对应一个模型、进程或一次调用。世界表示、环境推演与验证的方法见[模拟研究](research/world-models.md)，模块与提交边界见[架构](design/2026-10-27-target-architecture.md)。

## 5. 持续时间、运行与恢复

- 世界与真实时钟耦合，倍速按世界时间／真实时间定义。默认 24×，即 1 真实小时对应 24 世界小时；可调速、加速与随时暂停。
- 用户离开观看时世界继续运行，模拟不依赖观看页面常开。回来可以回查离开期间发生的事。
- 没有可用推演结果、额度不足或验证失败时，该线停在可确定的世界时刻，明确显示等待及原因；恢复后从该时刻续跑，不把等待时长补算为世界进度。其他具备推进条件的世界线独立运行。
- 默认本机运行，进程退出则世界冻结；重启从保存的世界时间和状态继续，不补算离线时间。
- 暂停与恢复保留已发生的事实和过程进度，不重复结算，也不把未来预测直接当作已发生的结果。
- 可选自托管服务器实现 7×24 常驻，云端常驻不是基本使用的前提。产品先按单用户、作者本人使用设计。
- 持久化恢复与读取历史使用已保存的结果，不通过重新调用模型重造同一历史。

### 产品形态与多端扩展

首个产品形态是网页应用：模拟引擎独立运行，网页提供观察、编辑、交互与实时 3D 展示。后续可扩展至移动端和桌面客户端，各端访问同一个引擎及其世界数据，复用模拟能力与一致的交互语义。

引擎运行位置与访问设备分开设计。引擎可以运行在本机或自托管服务器上，客户端的打开、关闭、切换或断线不决定世界是否运行；世界是否推进取决于引擎运行状态及推演条件。客户端恢复连接后从引擎同步事实与运行状态，不自行补算历史。

世界演化、时间、记忆、历史与模型调度独立于网页界面、设备交互和 3D 渲染。增加客户端应通过接入和展示适配完成，避免复制模拟规则或形成另一份权威世界状态。移动端需要适配触控、小屏布局与设备性能，保留实时 3D 体验。

首版交付网页应用；移动端和桌面客户端按后续需要建设。手机本地运行完整引擎与离线模拟属于独立扩展范围，不作为多端访问的前提。

## 6. 主观记忆

记忆是角色的主观经验。角色不仅受到发生过的事影响，也受到自己怎样理解、回忆和讲述这些事的影响。

- 区分 L0 客观事实、L1 当时主观经验、L2 如今的讲法。L0 与原始 L1 不可被后来的解释覆盖；L2 可版本化更新，从 L1 重建，不反复摘要旧 L2 累积漂移。
- 记忆按拥有者独立归属。同一事件可以留下多份带有不同情绪与解释的经验，锚回同一来源事件；集体知情也保留每个人的主观版本。角色只能使用其可见信息与自身记忆，不能凭空知道他人经验或隐藏事实。
- 编码时保留事件对该角色意味着什么，包括情绪极性、强度、重要度和相关对象，以及可审查的评价理由。回忆受时间、相关性、情绪与关系影响，允许动机性回忆与偏见。
- 反思以情境触发：过去闯入现在、叙事破裂、闲时、被问及过去；累计重要度只作后台兜底。普通触景生情首先是检索，不必每次触发新反思。
- 偏见不设系统上限，不投放系统级反制事件，不为剧情效果操纵人物。人物的偏执、成长与和解由其经历及世界内事件发展。
- 可并列查看客观事实、当时经验、如今讲法；先用评价理由、记忆聚合与三栏对照检查错标，不单独建设错标审计界面。
- 发生对话时，逐字对白保留在事件历史中，各方留下自己的主观记忆。只读记忆问询不制造世界事件或新记忆；前史记忆与世界设定保持一致。
- 上下文有界、相关且可审计。超预算先减少检索量并记录，仍不足则明确失败，不静默删掉关键事实或伪造记忆。作者可见域与角色可见域分开，不能借完整世界输入泄漏隐藏信息。
- 分岔继承分岔点的记忆与反思，此后按线独立发展，不把另一条线的经历当作自己的事实。

归属、编码、检索、反思与保存机制见[架构 §4](design/2026-10-27-target-architecture.md#4-主观记忆)。记忆再固化、多跳检索与分层管理的研究见[主观记忆研究](research/memory.md)。

记忆验收需要检查多主体知情隔离、同一事件的不同经验、偏见与中性记忆的行为对照、情境反思、三栏对应、长期检索效果及分岔继承与隔离。数值合法或有记忆表不能替代这些证据。

## 7. 创世与 3D

用户通过文本表达想要的世界，由模型参与构造可持续运行的世界与实时 3D 内容。画面好看、有吸引力是核心验收项。

用户与 AI 对话形成世界、角色初始设定及前史记忆种子，支持带模型的世界与角色编辑器。前史与世界设定保持一致，角色从已有经历开始生活。创建可以从一句话开始，再逐步展开地点、人物、历史与规律；不要求先填写完整的世界表格。

- 用户通过文本表达想要的世界，由模型参与构造 3D 内容。创建自由度不能只依赖预制成品资产数量。
- 必须提供实时 3D 画面。简单几何占位或文字补白不能替代视觉质量验收；不要求独立 2D 模式。
- 画面应与模拟中的对象、空间和状态变化一致，不能独立编造另一套世界事实。
- 基本创世不应要求用户安装 Blender、CUDA 或下载大型本地模型权重；无人观看时仍能推进模拟，普通常驻服务不应被迫配置 GPU。
- 用实际文本场景的构造结果、修改后的完整性及用户对成品画面的评价检验质量；运行表现需要在明确的目标设备与场景规模下验证。

模拟正确性与视觉吸引力需要各自的证据，不能互相替代。几何表示、构造、视觉反馈与成本比较见[3D 研究](research/3d-generation.md)。

## 8. 完整历史、模型预算与审计

世界保留完整历史，可以回查任意一条世界线发生过的事件。每个历史节点保存完整世界快照，纯对白轮也按同一规则保存。对白原文、客观变化与主观记忆有可追查的关联，后来的摘要或讲法不能覆盖原始历史。

用户可配置模型服务、候选模型、调用节拍与成本上限。角色、环境推演、验证等调用共享总预算；多线运行时预算跨线共享，不能通过拆分调用绕过限制。候选模型回退限于用户配置的范围。

失败、超预算、等待与调用消耗必须明确可见，不静默删掉关键事实、不无限返修，也不假装世界已经发生变化。调用输入、输出、各次尝试、用量及失败或丢弃原因应保留可追查记录，不自动删除调用审计。

密钥仅保存在本地配置或进程环境中，不进入世界数据或数据库，不通过配置 API 回传，不进入提交的代码与数据。配置与保存规则见[架构](design/2026-10-27-target-architecture.md)。

## 9. 在场与平行世界

用户可以观察世界、以世界内身份参与生活，也可以改变条件探索其他可能性。这些体验建立在持续模拟之上。

### 在场、附身与对话

- 在场包含缺席追更、半在场对话与完整附身。用户可以与任意角色对话。
- 统一使用附身任意角色的机制。固定化身只是长期使用同一角色的用法，不在引擎中设置“用户专属角色”的特殊路径；无人接管时，该角色与其他角色一样自主活动。
- 镜头与当前或上次身体关联，不另设操纵故事的导演机制。作者观察与角色知情分开，观察信息不能自动变成角色知识。
- 入世对话需要世界内身份，逐轮进入历史并留下各方主观记忆；可以从任意一轮尝试另一种说法。只读记忆问询不作为世界事件，不制造角色经历。
- 对话或实时交互期间，该线降速至真实时间 1×；进入前提醒，结束后恢复原速并提醒。对话与环境变化使用同一个世界时间；条件变化后，相关未来预测重新评估。

### 缺席追更

追更采用主要事件的新闻播报式摘要，并能回查实际历史。摘要反映记录中的事件，不能重新创造离开期间的事实。

### 自由分岔与多元宇宙

- “世界线”是一条持续运转的世界；初始为 α 线，分岔按 β、γ……命名，可随时改名。“如果……”是确认改动并创建新线的动作，“多元宇宙”是所有线及其关联的总览。
- 任意时刻可提出“如果……”，自由批量修改角色、事件和世界设定，不限于预设选项。
- 编辑以发起时的固定基准为准；确认后新线从该基准及改动继续运行，父线不受影响。编辑期间父线新增的历史不能悄悄改变新线的出发点。
- 新线继承分岔点已发生的历史、状态、过程进度及角色记忆和反思，之后各自演化、不串线；未来预测按新条件重新评估。
- 各线持续运转，可切换观看、同屏对照、查看完整历史与差异。共同历史交汇，分岔后的事件分别延展。

分岔建立在模拟能力之上，不限定唯一主循环。干预效果与模型随机漂移需要分别评估；固定种子本身不保证可复现或因果归因。

## 10. 开发重点与验收

项目处于原型验证阶段。通过小而独立的实验分别检验持续过程、行动后果、信息隔离、记忆与新规律扩展，再根据证据收敛正式架构和实现。原型可使用最小脚本与轨迹检查，涉及画面一致性和视觉质量时接入实时 3D；不要求每个实验先搭建完整应用。

做好 simulation infrastructure 是首要任务。先以有限范围检验世界表示、连续演化、环境后果、角色自主性、主观记忆与信息边界，再扩大范围，完善创世和实时 3D，并逐步接入附身、对话、追更、分岔与多线对照。基础模拟和完整产品体验都要取得各自的证据。

世界规模服从一致性和可理解性，不以属性数量、事件数量或无限地图作为成功标准。改变条件不是唯一玩法，陪伴、经营和探险也不规定为所有世界都要具有的流程。

| 验收面 | 需要的证据 |
| --- | --- |
| 模拟可信性 | 连续多步轨迹、后果传播、不同条件的结果、资源与时间约束、未知及预测失效案例，明确依据与限制 |
| 主体与记忆 | 知情隔离、同一事件的不同经验、偏见与中性记忆的行为对照、情境反思、三栏对应及长期检索效果 |
| 时间与恢复 | 24× 换算、调速暂停、离开后运行、进程冻结与重启续接，不丢失或重复后果，不补算离线历史 |
| 多端边界 | 模拟逻辑独立于展示端；客户端断开不终止运行中的引擎，重连可恢复事实与运行状态；后续客户端沿用同一世界与操作语义 |
| 创世与 3D | 从文本形成设定与一致前史、陌生场景的构造和修改、成品视觉吸引力及指定设备表现 |
| 长期使用 | 历史读取、全局预算、失败可见、调用审计与密钥边界，以及作者实际使用后的趣味与探索意愿 |
| 在场与平行世界 | 入世身份、逐轮对白与记忆、1× 提醒和恢复、追更准确性、固定基准分岔、继承隔离与多线对照 |

JSON 合法、单次回答合理、组件测试通过或模型互相赞同不能单独证明模拟可靠；局部场景的成功不能外推为任意世界的通用真实性。实际体验还要判断作者是否觉得好玩、是否愿意长期返回和探索这个世界。
