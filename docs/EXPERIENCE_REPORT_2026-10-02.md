# Possibility 产品体验报告（2026-10-02）

## 体验范围与方法

- 仅启动本地项目，通过浏览器以普通用户身份点击、输入、观察页面；未阅读应用实现代码。
- 使用全新本地测试账号体验，LLM 使用项目已配置的平台兜底。共记录 23 个问题，以下均来自实际点击或运行观察。
- 严重程度：P0 阻断核心使用，P1 高影响，P2 中影响，P3 细节。

## 已发现问题

### 1. 新用户创建世界时，「人物」提示没有可点击入口（P2）

- **路径**：注册新账号 → 自动进入「新的世界」。
- **实际表现**：页面下方提示“先到「人物」页创建一位，再回来为 TA 准备生活的地方”，但这个页面没有人物页链接或导航。用户必须先点右上角「设置」，再从设置页导航到「人物」。
- **期望**：提示中的「人物」直接可点击，或在创建页保留全站导航；完成创建人物后能方便返回未完成的世界创建表单。

### 2. 自定义模型提供方继承上一个预设的端点和模型（P2）

- **路径**：设置 → 依次点 DeepSeek、OpenAI、自定义。
- **实际表现**：切到「自定义」后仍显示 OpenAI 预设的 `https://api.openai.com/v1` 和 `gpt-5`。界面没有提示这些值来自刚才的选择，用户容易把它当成自己的自定义配置。
- **期望**：自定义选项恢复用户上一次保存的自定义值；首次使用时字段留空或明确标注示例值，避免误保存。

### 3. 空 API Key 的模型配置也提示“已保存”（P1）

- **路径**：设置 → 选 OpenAI → 再选自定义 → API Key 保持空白 → 点「保存」。
- **实际表现**：页面显示“已保存”，「删除配置」从禁用变为可用。用户无法从反馈判断模型是否真的可用，也不知道后续调用会走自定义端点还是平台兜底。
- **期望**：若 Key 必填，应阻止保存并明确指出缺失字段；若允许无 Key，应在页面说明实际调用路径，并提供连接测试。体验后已删除这条测试配置。

### 4. 未配置有效个人 Key 也能保存「不限」日预算（P1）

- **路径**：上述空 Key 配置状态下 → 勾选“不限(自己 Key 的世界可长期运行)” → 点「保存预算」。
- **实际表现**：页面显示“今日已用 0 / 不限 次调用”与保存成功。此时没有填写个人 API Key，和选项文案中的前提冲突；若实际回落平台配置，可能造成平台兜底被无限调用。
- **期望**：只有验证过个人 Key 后才能启用「不限」；否则明确拒绝并说明条件，且预算显示应与真实执行规则一致。体验后已恢复 400 次日限额。

### 5. 长人物表单的校验错误远离出错字段（P2）

- **路径**：人物 → 创建人物 → 手动填写 → 保持全部为空，点底部「确认创建人物」。
- **实际表现**：页面在按钮上方显示“姓名不能为空”，但姓名输入框在页面最上方；页面没有滚动到该字段，也没有把焦点交给它。表单较长，需要用户自己回找。
- **期望**：错误与姓名字段相邻显示，同时自动滚动并聚焦首个错误字段。

### 6. 手工创建人物后自动出现一个没有场景的世界，多个入口通向死路（P1）

- **路径**：人物 → 手工创建「林岚」→ 人物详情/人物时间线 → 「返回世界」「世界地图」或「＋ 创建一个 What-if 分叉…」；也可从「世界」列表点自动出现的「海边小镇」。
- **实际表现**：这些入口均进入“这方天地还没有可渲染的场景。”页面，只有「重试」按钮；重试后仍是相同画面。世界列表将该世界显示为已暂停，但没有解释如何补建场景。人物详情的「打电话」仍可点击，点击没有任何效果，只显示“世界已暂停，恢复后才能继续”，此处又没有恢复入口。
- **期望**：手工人物创建后明确引导用户为其创建场景；没有场景时提供「创建场景」入口，或不要把不可进入的世界与功能按钮当成可用入口。暂停时提供直达恢复操作，并将不可执行的电话按钮禁用及解释原因。What-if 按钮也应在满足前提后才可用。

### 7. 同一世界时间在不同页面相差 8 小时（P2）

- **路径**：打开「林岚」详情和时间线，再看「世界」列表。
- **实际表现**：人物状态栏显示 `10/2 00:34`，时间线与世界列表显示 `2026-10-01 16:34`；两者看起来是同一时刻的上海时间与 UTC，却没有时区标注。用户会误以为世界时间倒退了 8 小时。
- **期望**：统一按用户本地时区显示，或所有时间都清楚标注时区。

### 8. 按正常引导创建世界连续 4 次生成仍无法通过校验（P0）

- **路径**：世界 → 创建世界 → 勾选已有角色「林岚」→ 输入“海边旧车站旁有一条短街。车站北侧是一家独立书店，东边隔着一条石板路是小咖啡馆，街尾有一座能看见海的公共花园。请搭建可步行的小镇场景。” → 「开始创造」。
- **实际表现**：页面先显示“正在构思世界骨架”“正在校验新世界”，约数十秒后报错：“世界生成 4 次仍未通过校验：通行格净空不足 2 格(门洞/走廊过矮)”。没有可预览结果或可修正的具体地点，只有再次「开始创造」及「前往设置」。用户无法理解改哪句话能修复“通行格净空”。
- **期望**：生成器自动修正空间约束，至少提供一份能进入的保底场景；若失败，明确展示用户可改的描述建议，而不是内部校验术语。「前往设置」应只在配置出错时出现。
- **复测**：改用更简单的“一片平坦草地，中央有一条宽阔的道路。道路旁有一栋小房子。”仍连续尝试 4 次后失败，此次报“缺少合法的 size”。同一功能在两种正常描述下均失败，阻断稳定复现。

### 9. 生成失败后点「前往设置」，返回时创建内容全部丢失（P2）

- **路径**：发生问题 8 → 点击错误提示中的「前往设置」→ 浏览器返回创建页。
- **实际表现**：之前输入的整段场景描述和已勾选的「林岚」均清空，错误详情也消失。设置页显示今日已用 5 次调用，说明失败本身已经消耗调用额度。
- **期望**：创建草稿在站内跳转与返回后保留；错误和已消耗次数在创建页清楚提示，让用户能在原输入上修改重试。

### 10. 演示世界场景过暗，主体几乎看不清（P1，视觉）

- **路径**：退出登录 →「返回演示世界」；观察雾影庄外景的默认等角地图。
- **实际表现**：地块和建筑接近黑色，人物与地面细节难以辨认；大面积紫灰色空背景占去画面，实际可探索区域偏小。顶部地点导航也很淡、字很小。我的直观评价是**难看且难用**：第一眼看不出哪里能点，更谈不上想探索。
- **期望**：提高环境光与建筑/道路/人物对比，给可交互地点清晰标记；让世界主体占更多视窗，空背景退后。即使设定为雾夜，也应保留足够的可读亮度。

### 11. 行动输入的能力边界和错误反馈不符合用户语言（P2）

- **路径**：访客演示世界 → 进入书房 → 展开「尝试一个行动」→ 输入“我走到书架前，查看桌上的旧车站资料。”→「生成提议」。
- **实际表现**：返回“该动作不在允许的 move 或 inform 范围内，且‘书架前’不是给定地点。”用户事前看不到仅支持的动作类型，也看不到“给定地点”清单；`move`、`inform` 是内部术语。再输入有效地点“我想去温室花房”及“去温室花房”，两次都显示“世界状态或行动条件已变化；请重新描述这个行动”，没有可执行提议。
- **期望**：在输入前用自然语言列出支持的行动及地点，并给出可点选示例；过期时自动刷新世界状态再生成，或说明具体变化并允许一键重试。

### 12. 演示世界时钟与人物对话冲突（P1，叙事一致性）

- **路径**：访客演示世界顶部显示“12:59 宇宙”→ 进入书房对白川宗一郎说“你在研究什么？”→ 再问“现在是几点？”。
- **实际表现**：角色先说“天还没亮透”，随后明确回答“寅时末了，再过一刻便是五点”，与顶部 12:59 相差约 8 小时；玩家无法判断哪个时间可信。人物状态文案与即时世界时钟似乎没有同步。
- **期望**：对话生成时向角色提供当前世界时刻，且显示与对白采用同一时区和时间线；对已有演示历史做时间一致性整理。

### 13. 成功反馈泄露版本术语（P3）

- **路径**：访客演示世界 → 进入书房 →「明确告诉现场某人一条消息」→ 给白川宗一郎发送“旧车站线索”。
- **实际表现**：成功提示是“对方已听到这条消息（v2）”；`v2` 对玩家没有含义，破坏沉浸感。
- **期望**：显示“白川宗一郎听到了这条消息；它目前是传闻”之类的具体反馈。

### 14. 居民卡的「以访客身份进入」没有带用户去该居民所在地（P2）

- **路径**：先从演示世界进入书房 → 切到室内地图 → 点雾野透 → 点「以访客身份进入」。
- **实际表现**：雾野透的资料卡明确写他“现在在大厅”，但弹出的「进入世界」仍显示“你在书房”，没有预选大厅或提示两人并不在同一地点。这个按钮的含义与实际效果不符。
- **期望**：从人物卡进入时预选其当前地点，或把按钮改成“打开进入世界面板”，并提示需前往大厅。

### 15. 「重新开启导览」只显示完成页，无法从第 1 步重玩（P2）

- **路径**：演示世界导览进行到第 6/8 步 → 点「跳过」→ 点「重新开启导览」；另试右上设置里的同名操作。
- **实际表现**：两处操作都只显示“导览已完成 已完成全部步骤”，无法回到第 1 步。首次体验中导览还从第 2/8 步直接跳到第 6/8 步，中间步骤没有给出清楚反馈。
- **期望**：重新开启时重置为第 1 步；跳步时说明哪些操作已经完成了对应步骤。

### 16. 第一视角的室内画面像未完工模型（P2，视觉）

- **路径**：演示世界主楼室内 → 点「进入第一视角」。
- **实际表现**：正午 12:59 的室内能看到大面积紫色星空和没有屋顶的墙体；材质与家具多为灰色方块，近景还有大块单色几何面遮挡。视觉上**难看**，也削弱了“进入房间”的空间感。
- **期望**：第一视角提供完整室内边界、符合世界时间的天空与光照，以及可以辨认的家具和入口；近景遮挡物应避让镜头。

### 17. 体验过的访客世界无法「登录并保存」（P1）

- **路径**：访客演示世界中进入书房、发一条现场消息、尝试行动、对话、创建一个分叉 → 点「登录并保存」→ 使用刚注册的测试账号登录。
- **实际表现**：服务可用时登录成功，但停留在登录页并显示“已登录，但演示世界暂时无法保存：请求失败（500）”；重复一次相同。启动日志对应的保存请求是 `/api/demo/session/claim` 500，数据库提示 `universe_evidence_incomplete`。登录后再点“返回演示世界”则进入个人账号的无场景世界，既没保存访客进度，也失去当前入口。
- **复测**：经你授权点击「重新开始」，全新访客副本从 1/8 导览和 6 位居民重新开始；立即登录并保存**成功**，进入“雾影庄 · 保存的可能”。因此失败与体验后的副本状态有关，不能简单归因于账号或登录配置。
- **期望**：任何允许用户完成的演示操作都不应让保存失效；保存失败时保留副本和登录态，给出可重试入口及可理解的原因。

### 18. 本地完整启动后，后台周期任务反复失败并最终影响登录（P1，运行稳定性）

- **路径**：按项目 `npm run dev` 正常启动并持续体验约二十分钟。
- **实际表现**：运行输出每 15 秒报告一次后台 tick 失败，原因是“公共演示基线只读，请先进入访客体验副本”；大量重复错误后 API 服务退出。随后“登录并保存”连续显示“请求失败（502）”。我只重新启动网页和 API 服务、停止了异常循环的周期任务，未修改代码或数据；服务恢复后登录变为正常，但问题 17 的保存 500 仍存在。
- **期望**：周期任务忽略只读演示基线，并稳定运行；即便单次任务失败，也不应拖垮登录和保存。

### 19. 保存后的世界地图只占屏幕上半部，下面大片空白（P2，视觉）

- **路径**：全新访客副本 →「登录并保存」成功 → 打开保存的世界。
- **实际表现**：同样的外景地图缩到页面上方约 430 像素高，建筑更难辨认；下方近半屏是没有内容、不能滚动的浅绿色空白。视觉上像布局断裂，明显难看。
- **期望**：地图铺满可用视窗，或把下方区域用于事件、居民和操作面板；保存前后保持一致的主画面比例。

### 20. 世界下拉列表里的两个同名世界无法区分（P2）

- **路径**：保存演示世界后，打开右上角「切换世界」下拉列表。
- **实际表现**：列表中有两个完全相同的“海边小镇”，分别是此前手工和 AI 人物创建时自动出现的无场景世界。仅凭下拉项无法判断哪个对应哪位人物、哪个可进入；选中其中一个仍落到“没有可渲染的场景”。
- **期望**：至少附上人物、创建时间和状态；无场景世界应标明“待创建场景”，并能直达补建流程。

### 21. 未选人物时「开始创造」仍可点击，报错按钮又指向设置（P2）

- **路径**：已保存世界 → 下拉菜单「创建世界」→ 只填写地点描述，不选人物 → 点击「开始创造」。
- **实际表现**：尽管页面写“选择 1–6 位人物”，按钮仍可用；点击后报“请先选择至少一位居民”，旁边还出现与问题无关的「前往设置」。随后选中人物，旧错误仍留在页面。
- **期望**：选中人物前禁用按钮并在人物区说明条件；纠正选择后立即清除错误；人物数量错误不显示设置入口。

### 22. 已保存世界的地图对象无法像访客地图那样点开（P1）

- **路径**：将全新演示副本「登录并保存」→ 进入保存的世界 → 切到「主楼室内」→ 分别在「在场」「观察」模式下点击可见居民和多个室内地点。
- **实际表现**：人物与房间的 3D 模型都可见，但点击后没有居民卡或地点卡，也没有其他反馈；同样的坐标操作在保存前的访客全屏地图能正常打开卡片并推动导览。保存后页面上仍显示“体验指引 1/8：选择正在发生变化的地点”，用户却无法完成这一步。
- **期望**：保存前后地图点击行为一致；若对象不可交互，应通过视觉状态说明原因，而不是保留无法完成的引导。

### 23. 分支创建与切换缺乏可理解的解释（P2）

- **路径**：演示世界或已保存世界 → 点「可能」；在已保存世界中打开「切换时间线」，选择“分支 timeli · 新”。
- **实际表现**：点「可能」后直接显示“如果匿名信更早被发现”及“已创建平行宇宙 timeline-…”，没有让用户输入或选择要改变的条件，也没有明显的比较入口。时间线下拉用截断的 `timeli` 技术名称；切换后显示时间从 12:59 变为 01:34、居民数从 6 变为 1，却没有解释这条分支何时分出、为何人数不同。
- **期望**：创建前展示条件并允许确认或修改；为分支使用可读名称，标明分叉时间和起点，给出醒目的“比较两条时间线”入口。切换时说明时间和居民数量差异的来源。

## 整体体验

人物卡的“确知 / 推断 / 未知”结构是亮点，手工编辑、取消与保存可靠；AI 生成的顾舟人物卡也较完整，现场对话能给出有角色口吻的回复。访客副本隔离和“传闻不自动成为事实”的概念值得保留。

但目前核心闭环没有打通：正常创建世界两种描述均失败；单独创建人物自动产生进不去的世界；体验后的访客副本保存失败；保存成功的地图又无法通过点击继续探索。这些问题比新增内容更应先修。视觉方面，外景黑得难辨认，保存页下半屏空白，第一视角室内像半成品。建议先修复可进入、可保存、可继续玩的链路，再提升场景光照和视觉层次。

## 建议修复顺序

1. **先恢复主流程**：问题 8、6、17、22，以及问题 18 的本地运行稳定性。
2. **再修正世界规则与反馈**：问题 4、3、11、12、21、23；避免耗费调用次数后只收到内部错误。
3. **最后统一导航与视觉**：问题 1、10、16、19、20，以及其余表单与文案细节。
