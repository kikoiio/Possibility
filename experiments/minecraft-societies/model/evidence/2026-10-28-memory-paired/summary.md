# 真实模型配对探测（2026-10-28）

源运行：[40733909302](https://github.com/kikoiio/Wispiva/actions/runs/40733909302)，源提交 `49d39752232eb165481892a2afa67efdea4340fc`，Luanti 5.10.0，模型 `spark-x2.6`。原始日志、报告、哈希清单和 [结构化汇总](results.json) 同目录保存。

三次配对均从同一停服世界的独立副本启动；每组每次 3 人×8 次有效动作；第 2 次反转组顺序。两组都收到当前消息、上次动作结果、局部位置与可行动作，只有历史情节开关不同。共同目标明确要求采集、向邻居报告和建造，因此属于目标驱动探测。

每个有效动作执行前均通过校验；资源动作另以世界写入回读判断成功，不能把所有有效模型动作都算成成功任务。六组均通过资源总量守恒。144 个有效动作共 150 次调用，6 次 invalid_action 触发有界重试，全部用量已计入。另有独立 6 动作烟雾测试（6 调用），其中成功采集 3 次、放置 2 次、采集失败 1 次。

开启记忆合计成功采集 10 次、放置 5 次、消息 14 条、81,401 token；关闭组分别为 8、5、15、61,230。开启组 token 约多 33%，其中也包含重试次数差异，不能当作纯记忆开销。三次重复不足以估计可靠收益，建造次数相同；本轮未证明 FIFO 记忆改善任务结果。

消息中出现报告采集进度、提议建造坐标和响应他人计划；它们是实际模型输出并进入接收者 inbox。这里只证明消息投递和资源修改，没有验证计划履约、共同结构、稳定分工或自发社会涌现。放置计数不是独特方块数：角色可重新采集刚放置的资源。

初轮单次每角色六动作、每组十八动作的比较见 [旧证据](../2026-10-28-memory-initial/results.json)，当时没有消息／放置，且摘要缺陷与即时反馈后来修正。新旧轮之间同时改变提示、信息与格式兼容，不能把行为变化单独归因于某一个改动。

建议下一轮采用延迟回忆与来源判断任务，固定 token 预算和世界种子，再比较 FIFO、事件检索、检索加总结。当前未实现长期语义记忆。

证据保存了源码提交、配置、原始事件和 token 审计；原始模型上下文、provider 文本与世界数据库未归档，无法逐 token 回放。配对同源副本已在执行时做逐文件内容哈希核对，重跑是重复配置的独立实验，模型输出不保证相同。
