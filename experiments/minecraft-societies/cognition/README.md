# 观察、动作与记忆

这些 Lua 5.1 模块已接入 `agent/mod/society/init.lua`，在 GitHub Actions 的 Luanti 5.10.0 中验证。规则模式通过 `society_cognition=true` 开启附加观察与记忆；模型模式自动开启。

## 给 LLM 的信息

每次请求包含自己的 ID、persona 标签、时间、目标、位置、移动目的地、私有库存、上次动作实际结果、当前收到的消息，以及范围内的角色 ID／位置和资源／标记。`action_context.lua` 列出此刻够得到的采集点和持有资源时可放置的空位。`wander`／`approach` 设置目的地，后续 `advance` 才移动；模型返回一个动作，由引擎重新校验并执行。

`observation.lua` 的范围为三维球体，返回 `{pos, radius, agents, nodes}`。只公开邻居 ID、位置、距离；不公开别人的记忆、库存或内部实体。节点名由调用方白名单指定。它不检查视线遮挡，因此 `visible_nodes` 这一历史字段表示范围内节点，不能解释为第一人称视觉。世界是无碰撞路径规划的简化平面；角色使用 `set_pos` 移动，不能据此声称能在普通生存游戏中行走。

## 当前记忆实现

`memory.lua` 为每人独立的 FIFO，集成容量为 32 条。每条记录有 `time`、`text`、`source.kind/id`；输入、输出复制，角色间不共享私有记录。内容包括观察摘要、资源动作结果、发出和收到的消息。记录数有上限，消息字节另有限制。规则策略另有接触集合 `memory.met`，它不等同于情节记忆。

`MODEL_MEMORY=false` 只从模型请求中去掉历史情节；当前消息和上次动作结果仍提供，两组都能接收即时反馈。消息 inbox 最多 8 条，提交请求后清空；处理请求期间新到消息在下次请求提供。历史来源只是“谁报告了什么”，不是对陈述真实性的证明。

当前没有向量检索、长期语义记忆、关系推理、reflection 或持久计划。FIFO 是本轮可检验的基线。后续应分别比较“近期记录／按任务检索／检索与总结”，并测事件回忆、过期信息、来源混淆和 token 成本，不能仅凭人物故事判断记忆质量。

## 持久化与资源

`persistence.lua` 保存实体位置、稳定 body ID、库存、RNG、计数和记忆。恢复前验证完整批次；`--resume` 保留身体与世界，清除记忆、关系和移动目标，并重设 persona 与本轮决策数。body ID 不变，故不是全新人口。停服写入；异常退出后的世界不保证可恢复，快照必须在停服后创建。

`resource_actions.lua` 检查整数目标、1.5 格欧氏距离、已加载节点、库存及实际写入回读。仅操作 `society:resource`，采集增加库存、放置消耗库存；集成停服核对“世界资源＋库存”守恒。`mark` 是独立的调试标记，不消耗资源。模块不提供一般游戏的保护、视线与回调语义。

## 定向验证

在本目录运行 `lua5.1 test.lua`、`test_persistence.lua`、`test_resource_actions.lua` 和 `test_action_context.lua`。这些是轻量模拟引擎测试；实际启动、恢复、资源夹具与模型闭环由独立 Actions 工作流验证，结果见 [执行计划](../PLAN.md)。
